## 발표 대본

### 1. 복지나침반

안녕하세요. 복지나침반의 발표자 송현오입니다. 복지 공고를 찾아도, 내 나이와 가구 상황에 맞는지, 소득은 누구의 소득인지 다시 해석해야 합니다. 저희는 이 탐색과 이해의 부담을 줄이는 개인 복지 비서를 만들고 있습니다.

### 2. 개인비서 사용 흐름

사용자가 지역과 생활 상황을 입력하면 관련 공고와 이유를 확인하고, 상세 내용과 공식 출처를 살펴보는 흐름입니다. 쉬운 화면에서는 입력을 세 단계로 나누고 공고를 하나씩 보여줍니다. 현재 이 화면의 공고와 추천은 합성 예시이며, 실제 공고 연결을 준비하고 있습니다.

### 3. 조건 해석과 원문 근거

핵심은 조건의 적용 대상을 구분하는 것입니다. 예를 들어 부모 소득과 신청자 소득, 계약 보증금과 가구 재산을 같은 값으로 비교하면 안 됩니다. 명확한 조건은 코드로 처리하고, 복합 문장은 AI가 후보를 추출합니다. 원문 근거를 검증한 뒤 초안으로 남기며, 정보가 없으면 추가 확인으로 처리합니다.

### 4. 현재 구현

현재 공고 수집과 조건 추출, 웹 탐색과 쉬운 화면을 구현했습니다. 최근에는 서버 인증과 소득·재산 참고 계산, 동의 후 입력 저장도 추가했습니다. 다만 문자 인증은 개발용이며 실제 공고를 저장하는 DB와 추천 API는 아직 연결 전입니다. 기존 공개 정책 6건 실험에서 조건 후보 60개를 얻었지만, 전체 정확도로 해석하지 않습니다.

### 5. 재현 방법

재현을 위해 입력 계약과 조건 스키마, 테스트용 표본, 실행 명령을 저장소에 정리했습니다. 웹 예시 흐름과 백엔드 검증을 나누어 실행할 수 있습니다. 다음에는 검토한 실제 공고를 저장하고 API로 연결해, 같은 입력에서 결과와 원문 근거까지 확인하는 통합 검증을 하겠습니다.

### 6. 다음 목표와 사업화

최종발표에서는 실제 공고의 입력부터 원문 확인까지 이어지는 시연을 목표로 합니다. 사용자에게 탐색 과제를 주고 완료율과 소요시간을 측정하겠습니다. 사업화는 기관의 상담 보조 도구를 가설로 두고, 수요와 운영 비용을 검증하겠습니다. 감사합니다.

## 질의응답

질문마다 결론 한 문장, 현재 근거, 다음 검증 순서로 15~25초 안에 답한다. 아래는 예상 질문이며 심사위원의 실제 질문이나 개인 성향을 예측한 것이 아니다.

### 1. 복지로나 정부24와 무엇이 다른가요?

“공고 조건의 적용 주체와 원문 근거를 함께 정리하고, 쉬운 화면에서 이해하도록 돕는 흐름에 집중합니다. 이 방향이 기존 서비스보다 유용한지는 아직 비교 검증 전입니다. 같은 탐색 과제의 완료율과 소요시간으로 확인하겠습니다.”

기존 서비스에 맞춤 추천이나 민간정보가 없다고 주장하지 않는다. 차별화는 현재 설계 방향과 앞으로 입증할 효과로 설명한다.

### 2. AI 정확도는 몇 퍼센트인가요?

“현재 전체 정확도 수치는 없습니다. 기존 공개 정책 6건에서 조건 후보 60개를 추출하고, 사전에 정한 8개 구분 항목을 확인한 기록이 있습니다. 별도 정답 표본에서 누락과 주체·단위·예외 오류를 측정하겠습니다.”

8개 일치를 100% 정확도로 표현하지 않는다. 6건과 후속 2건 실험은 겹칠 수 있으므로 8건으로 합산하지 않는다. 이번 준비 과정에서 해당 외부 모델 호출을 재실행한 것은 아니다.

### 3. 실제 AI 추천이 되나요?

“공공 원문에서 조건을 추출하는 AI 파서는 구현과 호출 실증 기록이 있습니다. 웹의 개인별 공고 추천은 현재 합성 예시입니다. 정책 저장소와 추천 API를 연결하는 것이 다음 핵심 작업입니다.”

### 4. 왜 AI를 쓰나요? 코드로 하면 안 되나요?

“현재도 명확한 조건은 코드로 처리합니다. 적용 주체와 예외가 섞인 복합 문장을 AI가 후보로 해석하고, 코드가 자료형과 원문 인용 등을 검증하도록 역할을 나눴습니다. 의미 정확성은 별도 검토합니다.”

### 5. 잘못된 추천으로 신청 기회를 놓치면 어떻게 하나요?

“현재 결과를 수급 자격 확정으로 안내하지 않습니다. 미기재 정보는 제한 없음과 구분하고, 파싱 결과는 검토 전 초안으로 유지합니다. 실제 공개 단계에는 검토 승인과 최신 원문 확인 경로를 연결하겠습니다.”

### 6. 얼마나 구현됐고 가장 큰 남은 과제는 무엇인가요?

“수집·조건 추출, 예시 웹, 인증과 소득·재산 참고 계산은 구현했습니다. 가장 큰 과제는 검토한 정책의 MySQL 저장·조회와 실제 추천 API 연결입니다. 이 연결을 최종 시연의 우선순위로 두고 있습니다.”

### 7. DB와 인증은 완성됐나요?

“인증과 회원 금융 원입력 저장은 코드와 격리 SQLite 검증 이력이 있습니다. 실제 문자 발송은 미연결이고, 정책 DB 저장은 별도 미구현입니다. MySQL 접속 점검을 전체 서비스 완성으로 보지는 않습니다.”

### 8. 개인정보는 어디에 저장하나요?

“추천용 프로필은 기본 메모리에서 사용하고, 선택하면 브라우저에 저장합니다. 금융 원입력은 비회원 계산에서는 저장하지 않고, 로그인한 사용자가 동의하면 계정별로 저장합니다. 저장 입력 삭제 경로는 있으며 보관기간과 계정 탈퇴 정책은 후속 과제입니다.”

전화번호·이름·금융 입력 기능이 있으므로 ‘개인정보를 수집하지 않는다’고 말하지 않는다. 공개 정책 분석 실증과 사용자 개인별 추천 흐름을 구분한다.

### 9. 돈은 어떻게 벌고 운영비는 감당하나요?

“기관 상담용 조회 도구와 운영·연동 서비스를 수익화 가설로 두고 있습니다. 현재 계약이나 매출은 없습니다. 공고당 처리량과 검토 시간을 측정하고, 기관 인터뷰로 유료 도입 의사를 확인하겠습니다.”

### 10. 다른 팀원이 그대로 실행할 수 있나요?

“실행 문서와 예시 설정, 테스트용 표본, API 계약을 저장소에 정리했습니다. 웹 예시 흐름은 재현할 수 있습니다. 과거 실제 AI 실험의 원문·전체 산출물은 Git 제외 폴더에 있어, 그 실험까지 재현하려면 공개 가능한 입력과 설정을 별도로 준비해야 합니다.”

### 11. 쉬운 화면은 실제 시니어가 검증했나요?

“큰 글자와 단계별 입력, 공고 한 개씩 보기를 구현했습니다. 실제 시니어 사용성 평가는 아직 수행 전입니다. 도움 요청 횟수, 완료율과 소요시간을 측정할 계획입니다.”

### 12. 최종발표까지 범위가 너무 넓지 않나요?

“핵심 시연은 검토한 실제 공고를 저장하고 웹에서 조회해 원문을 확인하는 데 집중합니다. 그 연결을 완료한 뒤 추천 이유와 사용자 평가를 검증하겠습니다. 상세 일정과 담당자는 최종발표 일자에 맞춰 확정하겠습니다.”
