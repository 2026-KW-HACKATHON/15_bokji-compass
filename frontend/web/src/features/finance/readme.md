# 소득·재산 계산기

`CalculatorPage({easy,user,profile,session,onSessionChange,onProfileChange,onRecommend})`는 2026년 소득·재산 입력 및 서버 계산 결과를 표시하는 React 컴포넌트입니다. 담당: 프론트엔드. `profile`은 계산·저장·불러오기를 완료한 상위 앱 메모리 값이고 `session`은 작성 중 초안·화면 위치·결과·복구용 가구원/차량 정보를 담는 메모리 값입니다. `onSessionChange(session)`은 입력과 화면이 바뀔 때 호출합니다. 계산 요청 및 저장·불러오기 성공 시 `onProfileChange(raw)`, 입력 변경·삭제 시 `onProfileChange(null)`을 호출해 이전 추천용 원자료를 해제합니다. localStorage·sessionStorage에는 금융정보를 쓰지 않습니다.

기본/쉬운 화면 모두 팝업 없이 시작 → 가구 → 가구원별 소득 → 재산 → 부채 → 차량 → 입력 확인 → 결과로 진행합니다. 가구원 한 명의 나이·공제, 근로소득, 사업소득, 기타소득을 나누고 차량 한 대의 명의·용도, 가액, 제원을 나눕니다. 쉬운 화면 전환은 현재 단계와 입력을 유지합니다. 마지막 입력 확인과 결과에서 전체 수정 화면으로 이동하고, 요약의 수정 버튼은 해당 항목으로 초점을 옮깁니다. 저장 정보는 명시적으로 불러오며 질문을 반복하지 않고 입력 확인 화면을 엽니다.

금액 선택의 ‘없어요’는 0, ‘모르겠어요’는 null이며 ‘있어요’에서 금액을 입력합니다. 빈칸도 null로 전송하며 선택하지 않은 항목을 0으로 만들지 않습니다. 차량 없음/모름이면 상세 질문을 생략하고 전송 목록은 비웁니다. 가구원 수 감소·차량 여부 변경 시 제외한 입력은 앱 메모리에서 복구할 수 있고 API에는 현재 적용되는 목록만 전달합니다. 개별 차량 삭제는 해당 행을 제거합니다.

`App`은 SPA 메뉴 이동 중 초안과 위치를 보관하고, 새로고침·로그아웃·다른 계정 전환 때 초기화합니다. 비회원 초안은 같은 실행 중 로그인하면 이어서 작성할 수 있습니다. 화면의 입력 지우기와 서버 저장정보 삭제는 복구용 메모리도 지웁니다. 페이지 이탈 시 진행 중 API 요청을 취소하고, 취소된 계산으로 돌아오면 재시도할 수 있습니다.

구성 파일:

- `financeFlow.js`: `financeQuestions(draft)` → 질문·필드 목록, `visibleFields(question,draft)` → 조건에 맞는 필드, `validateQuestion(question,draft)` → `{message,field,question}` 또는 null. 단계 이동은 현재 질문만 검사하고 최종 확인·계산은 전체 입력 계약까지 검사합니다.
- `FinanceFields.jsx`: `QuestionFields`는 공통 입력 컨트롤, `FinanceReview`는 입력 요약과 수정 이동을 렌더링합니다.
- `FinanceHelp.jsx`: 가구 범위·기간·소득·부채·차량의 기존 근거 안내를 보관합니다.
- `FinanceResult.jsx`: 기존 서버 결과·추가 확인 사항·공식 출처 UI를 렌더링합니다.

입력 계약은 [FinancialProfile](../../../../../backend/app/contracts/finance.py)입니다. `financeModel.js`는 전송 필드를 제한하고 금액·나이·차량 제원의 안전 정수와 범위를 검증합니다. 전월세 보증금은 소유 주택 가액과 분리하고 가구원별 근로·사업·기타 소득과 정기적으로 받는 사적이전소득을 나누어 전송합니다. 계산식·공제·사업별 기준은 프론트에 복제하지 않습니다.

소득이 양수일 때 `earned_income_basis`(세전/실수령액/모름), `business_income_basis`(필요경비 차감 후/매출/모름)를 묻습니다. 차량은 `ownership`, `registration_use`, `value_basis`, `eco_subsidy`를 실제 사용 목적 `use`와 분리합니다. 기존 저장 정보에 새 필드가 없으면 `unknown`으로 정규화하며 공제 가능 여부를 추측하지 않습니다. 금액·기준을 바꾸면 이전 계산 결과를 지우고 다시 계산하도록 합니다. 공식 정의·기간과 차량 예외의 근거는 [입력 근거 조사](../../../../../backend/docs/finance-input-evidence-2026.md)에 있습니다.

`createFinanceApi({baseUrl,fetchImpl,timeoutMs})`는 15초 제한과 외부 AbortSignal을 지원합니다. 공개 `calculate(profile)`와 `rules()`는 credentials=omit, `getProfile()`, `saveProfile(profile,{consent:true})`, `deleteProfile()`은 credentials=include와 X-Auth-Request 헤더를 사용합니다. demo 공고 설정과 관계없이 실제 서버가 필요하고 실패 시 가짜 계산으로 바꾸지 않습니다.

회원 저장은 별도 동의 체크 후 명시적으로 실행합니다. 기존 계정 정보는 자동으로 불러오지 않으며 ‘저장한 정보 불러오기’를 누를 때만 현재 입력을 바꿉니다. 저장 정보가 없는 null 응답은 현재 입력을 보존하며 안내합니다. 계정이 바뀌거나 페이지가 닫히면 진행 중 응답을 무시하고 요청을 취소합니다. 상위 앱은 계정 ID로 페이지를 다시 만들고 이전 회원의 금융 메모리를 지웁니다. 비회원으로 계산한 메모리는 같은 실행 중 로그인 후 사용자가 저장을 선택할 수 있도록 전달하며 자동 저장하지 않습니다.

계정의 금융정보 삭제는 ‘계정에 저장한 정보 삭제’로 확인 영역을 연 뒤 ‘저장 정보 삭제하기’를 눌러 요청합니다. 취소 버튼은 서버 요청 없이 확인 영역을 닫습니다. 삭제 성공 시 서버 금융정보와 현재 금융 메모리를 비우며 일반 추천 프로필·저장 공고는 건드리지 않습니다. ‘이 화면의 입력 정보 지우기’는 서버 저장 정보 삭제와 다릅니다.

결과는 중위소득 단순 비교, 재산 합계, 서버가 제공한 사업별 추정·추가 확인 사항 및 공식 출처를 표시합니다. 쉬운 화면에서는 사업별 상세와 부가 notes·sources를 담은 ‘계산 기준과 공식 자료 보기’를 접어 둡니다. 지원 자격·수급자·차상위 여부·자동차 특례를 확정하지 않습니다. 출처 링크는 자격증명 없는 HTTPS URL만 허용하며 새 창에 noopener/noreferrer를 적용합니다.

결과의 ‘관련 공고 살펴보기’는 `onRecommend()`로 상위 앱에 명시적 추천 연결을 알립니다. 기본 추천 프로필과 금융정보는 별도이며, 계산·회원 저장만으로 금융정보가 추천에 포함되지 않습니다. 공고 demo는 실제 금융 맞춤 추천을 하지 않고 홈 이동 후 준비 중 안내 토스트를 표시합니다. 실제 추천 API는 아직 미구현이며 [financialProfile 확장](../../../../docs/service-contract.md)은 후속 서버용 제안입니다.

검증 시나리오: `tests/finance.test.js`는 입력·응답 계약, null/0, 안전 정수, 인증 요청 분리, 동의 및 오류·취소를 확인합니다. `tests/e2e/calculator.spec.js`는 게스트 계산, 쉬운 모드, 단계별 검증·키보드 이동, 전체 수정, 메뉴 이동 중 초안 보존, 가구원/차량 복구와 전송 제외, 명시적 저장·불러오기·삭제, 서버 오류 재시도를 다룹니다. 최종 단위 테스트·빌드·포맷 및 수동 브라우저 확인과 CLI E2E 수집 범위는 [쉬운 화면 검증 기록](../../../../docs/senior-mode.md)에 구분해서 남깁니다.
