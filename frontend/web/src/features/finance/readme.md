# 소득·재산 계산기

2026-10-08: 빠른 계산기에서 ‘7명 이상’을 선택하면 추가 선택 없이 실제 가구원 수를 직접 입력합니다. 빈칸을 7명으로 추정하지 않으며, 정수 1~100명 검증과 화면 전환 시 실제 인원 보존을 유지합니다. 상세 계산기의 인원 선택 방식은 유지합니다.

2026-10-08: 사업별 결과의 노란 ‘추가로 확인할 내용’ 상자와 반복 면책 문구를 제거했습니다. 실제 미입력 정보와 계산 미지원 조건은 결과 하단의 ‘계산에 반영하지 못한 정보’에 중복 없이 모아 기본 접힘으로 표시합니다. 미확인 금액과 비교 상태는 그대로 유지합니다. 입력 확인 단계에서 사용자가 선택한 경우에만 미지원 지역과 세후 근로소득을 임시 대체한 근사값을 계산하고, 결과 상단에 가정을 표시합니다. AI·계산 결과의 공통 주의 문구는 일반·쉬운 화면 모두 페이지 맨 아래 `SourceFooter`에서 한 번만 안내합니다.

`#calculator`는 `CalculatorPage({draft,onChange,prefill,hasSavedProfile})`로 가구원 수만 선택하면 2026년 기준 중위소득과 50~200% 기준 금액을 즉시 표시합니다. 가구 전체 월소득은 선택 입력(만원)이며 단순 비율만 비교합니다. `medianIncome.js`의 1~7인 공식 금액과 8인 이상 1명당 959,198원 증가 기준은 2026-10-06 보건복지부 자료를 확인했습니다. 기준 금액과 비율은 화면에서 계산하고 회원의 저장 정보 조회는 아래 공통 불러오기 기능을 사용합니다. 입력은 앱 메모리에 보관하며 메뉴 이동·쉬운 화면 전환 시 유지하고 새로고침·로그아웃 시 지웁니다. 상세 입력 링크는 `#calculator-details`로 연결됩니다.

가구 단계의 지역 선택에 ‘전남광주통합특별시’를 제공합니다. 선택하면 ‘광주광역시’ 또는 ‘그 외 지역’ 권역을 추가로 선택합니다. API의 `region_subdivision` 값은 각각 `gwangju`, `other`이며, 기존 광역시·그 외 지역의 기본재산 공제 기준으로 계산합니다. 권역을 선택하지 않은 기존 입력은 결과를 ‘확인 필요’로 남깁니다. ‘12명 이상’을 선택하면 실제 가구원 수를 입력합니다. 프론트·서버 모두 최대 100명과 해당 인원의 소득 목록을 받으며 13명 이상을 12명으로 축소하지 않습니다. 가구원 범위 확인과 추가 혜택·공제 확인 체크는 ‘(선택)’으로 표시하고 미선택 시에도 다음 단계로 진행합니다. 가구원 범위를 확인하지 않으면 결과의 확인할 항목에 남깁니다.

소득·주택·전월세 보증금·기타 재산·부채·차량 가액은 모두 **만원 단위**로 입력합니다. 예: `500` → 500만 원, `250.5` → 250만 5천 원. 입력 아래에 원 단위 환산 금액도 표시하고 확인 화면·계산 결과는 원 단위 금액을 유지합니다. 소수점 넷째 자리(1원)까지 허용하며 기존 저장액을 반올림하지 않습니다. 나이·인원·차량 제원의 단위는 바뀌지 않습니다.

`moneyInput(text)`는 작성 중 금액을 `{unit:'manwon',value:text}`로 표시해 빈칸·소수점 작성·잘못된 입력도 메뉴 이동 중 보존합니다. `parseMoney(value,label)`는 이 초안만 10,000배 환산하고 기존 숫자/문자열은 원 단위로 해석합니다. `moneyInputValue(value)`는 저장된 원 단위를 정확한 만원 입력값으로 표시합니다. `toFinancialProfile` 결과와 서버 요청·DB 저장 계약은 계속 원 단위 정수이므로 API에서 재검증해도 중복 환산하지 않습니다. 예전 `1,234,567원`은 `123.4567`로 표시되며 재저장해도 값이 유지됩니다.

`App`은 SPA 메뉴 이동 중 초안과 위치를 보관하고, 새로고침·로그아웃·다른 계정 전환 때 초기화합니다. 비회원 초안은 같은 실행 중 로그인하면 이어서 작성할 수 있습니다. 화면의 입력 지우기와 서버 저장정보 삭제는 복구용 메모리도 지웁니다. 페이지 이탈 시 조회·계산 요청을 취소하고, 취소된 계산으로 돌아오면 재시도할 수 있습니다. 저장·삭제는 메뉴 이동 후에도 완료하며 같은 계정의 공통 정보를 갱신합니다. 요청 이후 새로운 입력이 생겼다면 그 입력은 유지하고, 다른 계정으로 바뀌면 이전 요청의 결과를 현재 화면에 반영하지 않습니다.

같은 계정의 저장·삭제 처리 중에는 재진입한 상세 화면에서도 추가 저장·삭제를 잠시 막습니다. 입력·조회·메뉴 이동은 유지합니다. 새 입력이 없는 삭제 완료 시 상세 화면의 로컬 초안도 초기화해 이전 정보가 다시 세션에 올라오지 않게 합니다.

구성 파일:

- `financeFlow.js`: `financeQuestions(draft)` → 질문·필드 목록, `visibleFields(question,draft)` → 조건에 맞는 필드, `validateQuestion(question,draft)` → `{message,field,question}` 또는 null. 다음으로 이동할 때 기본/쉬운 화면 모두 현재 단계의 모든 질문을 검사하며 첫 오류 항목으로 초점을 옮깁니다. 최종 확인·계산은 전체 입력 계약까지 검사합니다.
- `FinanceFields.jsx`: `QuestionFields`는 공통 입력 컨트롤, `FinanceReview`는 입력 요약과 수정 이동을 렌더링합니다.
- `CountField.jsx`와 공통 `countChoices.js`: 묶음 선택·정확한 인원 선택·직접 입력을 제공하며 모름과 0을 구분합니다.
- `financePrefill.js`: 회원의 확정 나이·지역, 빠른 화면의 명시적 가구원 수와 저장 원입력을 기반으로 초안을 만들고 확인된 소득 합계만 빠른 화면으로 전달합니다.
- `useFinancePrefill.js`: 계산기와 내 정보의 계정 조회 상태·원입력 캐시를 공유하며 조회 취소·재시도·저장 갱신·삭제 무효화를 처리합니다.
- `FinanceHelp.jsx`: 가구 범위·기간·소득·부채·차량의 기존 근거 안내를 보관합니다.
- `FinanceResult.jsx`: 기존 서버 결과·추가 확인 사항·공식 출처 UI를 렌더링합니다.

입력 계약은 [FinancialProfile](../../../../../backend/app/contracts/finance.py)입니다. `financeModel.js`는 전송 필드를 제한하고 금액·나이·차량 제원의 안전 정수와 범위를 검증합니다. 전월세 보증금은 소유 주택 가액과 분리하고 가구원별 근로·사업·기타 소득과 정기적으로 받는 사적이전소득을 나누어 전송합니다. 상세 계산의 공제·재산 환산·사업별 기준은 서버에서 계산합니다. 빠른 확인의 공식 기준 중위소득 표와 단순 비율은 `medianIncome.js`에서 처리합니다.

소득이 양수일 때 `earned_income_basis`(세전/실수령액/모름), `business_income_basis`(필요경비 차감 후/매출/모름)를 묻습니다. 차량은 `ownership`, `registration_use`, `value_basis`, `eco_subsidy`를 실제 사용 목적 `use`와 분리합니다. 기존 저장 정보에 새 필드가 없으면 `unknown`으로 정규화하며 공제 가능 여부를 추측하지 않습니다. 금액·기준을 바꾸면 이전 계산 결과를 지우고 다시 계산하도록 합니다. 공식 정의·기간과 차량 예외의 근거는 [입력 근거 조사](../../../../../backend/docs/finance-input-evidence-2026.md)에 있습니다.

소득 단계는 나이·공제 유형과 실제 소득 종류·금액·기준을 질문합니다. 산식에 쓰이지 않는 직업군·은퇴 상태는 질문하지 않습니다. 기존 저장 데이터의 `members[].occupation`은 호환성을 위해 유지하며 생략된 값은 `unknown`으로 읽습니다. 공제 유형의 학생·등록 장애인·직업재활 참여 등은 사업별 공제 확인에 필요한 항목이므로 유지합니다.

`createFinanceApi({baseUrl,fetchImpl,timeoutMs})`는 15초 제한과 외부 AbortSignal을 지원합니다. 공개 `calculate(profile)`와 `rules()`는 credentials=omit, `getProfile()`, `saveProfile(profile,{consent:true})`, `deleteProfile()`은 credentials=include와 X-Auth-Request 헤더를 사용합니다. demo 공고 설정과 관계없이 실제 서버가 필요하고 실패 시 가짜 계산으로 바꾸지 않습니다.

회원으로 빠른 계산기·상세 계산기·내 정보에 들어오면 공통 `GET /v1/finance/profile` 조회를 실행하고 같은 계정의 조회 결과를 메모리에 공유합니다. 저장된 가구원 수와 확인된 월소득은 빠른 화면에 채우고 상세 원입력은 입력 확인 화면에서 확인·수정할 수 있습니다. 저장 정보가 없으면 회원의 확정 만 나이와 구분 가능한 거주 지역을 최초 상세 초안에 채웁니다. 연령대로 정확한 나이를 추정하거나 ‘가족과 살아요’로 인원을 정하지 않으며 다른 가구원의 나이·소득도 비워 둡니다. 경남처럼 계산 지역 구분에 필요한 시 정보가 없는 값은 모름으로 둡니다.

자동 조회보다 직접 수정한 빠른 화면 값과 상세 초안을 우선합니다. 같은 실행 중 비회원으로 작성하다 로그인해도 초안을 이어서 사용하고 자동 조회로 덮어쓰지 않습니다. 조회 중임·저장 정보 없음·조회 실패를 구분하며 실패 시 입력을 유지하고 재시도를 제공합니다. 계정 변경·페이지 이탈·삭제·새 저장 결과 적용 시 이전 요청을 취소하거나 응답 세대를 무효화해 늦은 응답이 현재 값을 되돌리지 않게 합니다. ‘저장한 정보 불러오기’는 사용자가 현재 상세 입력을 저장본으로 교체하려고 직접 선택할 때 유지합니다. 회원 저장은 자동 조회와 별개이며 별도 동의 체크와 저장 버튼으로만 실행합니다. 상세 화면에서 아이디 로그인을 거치면 `#login?return=calculator-details`로 작성하던 화면에 돌아옵니다. 카카오의 기존 회원 콜백은 서버의 홈 이동을 유지합니다.

계정의 금융정보 삭제는 ‘계정에 저장한 정보 삭제’로 확인 영역을 연 뒤 ‘저장 정보 삭제하기’를 눌러 요청합니다. 취소 버튼은 서버 요청 없이 확인 영역을 닫습니다. 삭제 성공 시 서버 금융정보와 현재 금융 메모리를 비우며 일반 추천 프로필·저장 공고는 건드리지 않습니다. ‘이 화면의 입력 정보 지우기’는 서버 저장 정보 삭제와 다릅니다.

결과는 중위소득 단순 비교, 재산 합계, 서버가 제공한 사업별 추정·추가 확인 사항 및 공식 출처를 표시합니다. 결과 수치 앞에 ‘월 소득 합계·기준 중위소득·비율·소득인정액·계산값과 기준·확인 필요’를 설명하는 안내를 항상 펼쳐 표시합니다. ‘50%는 기준 금액의 절반’ 예시를 포함하고, 재산 합계 설명도 해당 금액 목록 앞에 배치합니다. 쉬운 화면에서는 사업별 상세와 부가 notes·sources를 담은 ‘계산 기준과 공식 자료 보기’를 접어 둡니다. 지원 자격·수급자·차상위 여부·자동차 특례를 확정하지 않습니다. 출처 링크는 자격증명 없는 HTTPS URL만 허용하며 새 창에 noopener/noreferrer를 적용합니다.

결과의 ‘관련 공고 살펴보기’는 `onRecommend()`로 상위 앱에 명시적 추천 연결을 알립니다. 기본 추천 프로필과 금융정보는 별도이며, 계산·회원 저장만으로 금융정보가 추천에 포함되지 않습니다. 공고 demo는 실제 금융 맞춤 추천을 하지 않고 홈 이동 후 준비 중 안내 토스트를 표시합니다. 실제 추천 API는 아직 미구현이며 [financialProfile 확장](../../../../docs/service-contract.md)은 후속 서버용 제안입니다.

## 다국어 화면

`useFinanceI18n()`은 공통 `useI18n()`과 함께 `formatMoney`, `formatNumber`, `translateTitle`, `translateError`를 제공합니다. 한국어·영어·중국어 간체·베트남어·일본어로 입력 항목·단계·도움말·검증 오류·저장 동의를 표시하며 원화 통화와 숫자는 선택 언어의 `Intl` 형식을 사용합니다. 한국어의 기존 원 단위 표시를 유지하고, 만원 입력값과 계산·저장 API의 원화 수치·enum·null/0 구분은 바꾸지 않습니다. 가구원·차량 번호가 포함된 제목과 오류만 구조적으로 번역합니다. 서버가 반환한 사업별 설명과 공식 자료 원문은 그대로 표시합니다. 사전은 공통 i18n 모듈에 있으며 번역용 외부 호출은 없습니다. 웹 단위·빌드 및 다국어 E2E에서 단계 입력, 금액 보존과 원래 API 값 전달을 검증합니다.
