# 공고 캘린더

2026-10-08 남은 기간 문구: 날짜별 공고 행은 선택한 접수 회차의 날짜를 기준으로 ‘신청일까지 N일 남음’과 ‘마감일까지 N일 남음’을 구분합니다. 계산 기준일은 선택일이 아닌 한국 시간의 오늘입니다. 시작 당일은 ‘오늘 신청 시작’, 마감 당일은 ‘오늘 신청 마감’이며 시작일이 지난 뒤에는 시작 배지를 숨깁니다. 날짜가 없거나 잘못된 시작일에는 카운트를 만들지 않습니다. 지난 마감일은 경과 일수 없이 공통 배지에 ‘접수 마감’을 한 번 표시합니다. 일반·쉬운 화면의 문구는 동일합니다.

2026-10-08 쉬운 화면: 작은 7열 격자 대신 레이블이 있는 날짜 입력, 이전·다음 날짜
이동, 접힌 `이달 날짜 모두 보기`를 제공합니다. 전체 날짜 목록은 화면 폭에 맞춰 열을
바꾸며 날짜·요일·시작/마감 건수를 함께 표시합니다. 선택일과 오늘은 접근성 상태와
테두리/밑줄로 구분합니다. 일반 화면의 월간 격자와 검색 조건·월·선택일 상태는 공유합니다.
쉬운 화면의 저장 버튼은 아이콘과 `저장/저장됨` 문구를 함께 표시합니다.
`shiftCalendarDay(day, amount) -> YYYY-MM-DD|null`은 UTC 날짜 연산으로 윤년·월/연도
이동을 처리하고 2000~2099년 밖의 날짜와 잘못된 입력을 거부합니다.

`#calendar`에서 공개 공고의 월별 신청 시작·마감 일정을 조회합니다. `CalendarPage`는
기존 공고 repository, 상세 보기, 브라우저 저장 기능을 함께 사용합니다.

- 한국 시간의 오늘을 기준으로 처음 표시하며 이전 달·다음 달·오늘 이동을 지원합니다.
- 검색어, 검색 범위, 분야, 지역, 대상은 서버 필터입니다. 검색 범위는 `all`(자동으로 찾기),
  `organization`(게시기관), `content`(공고 내용)이며 기본 전체를 제외하고 `search_scope`로
  전달합니다. 기본은 문장 의도를 서버에서 해석하고, 직접 고른 게시기관은 기관 이름,
  공고 내용은 제목과 본문에서 찾습니다. 검색 해석·수정안·범위별 개수를 표시하며 날짜별
  공고에도 검증된 이유와 원문 근거를 표시합니다.
  해석 아래 관계 선택은 `search_relation=publisher|related`로 자동 해석을 유지하며,
  학교 이름이 없는 출처 문맥의 관련 지원도 보존합니다. 같은 선택은 해제합니다.
  시작만/마감만은 조회된 월의 표시 필터입니다.
- 날짜를 선택하면 해당 일의 시작·마감 공고와 명확한 접수 기간에 포함되는 공고를 표시합니다.
- 접수 마감일이 지났다는 이유로 공고를 숨기지 않습니다. 과거 달·날짜를 선택하면 당시
  공고를 확인할 수 있고 날짜별 목록의 마감된 공고에는 `접수 마감`을 표시합니다.
- `3~4월`처럼 월만 확인되는 공고는 서버가 첫 월 1일부터 마지막 월의 실제 말일까지
  접수 기간으로 제공합니다. 3월 1일 `신청 시작`, 4월 30일 `신청 마감`으로 표시하며
  기간 내 날짜를 선택해도 공고를 확인할 수 있습니다. 연도가 명시되면 해당 연도가 우선이고
  연도 미기재는 조회 연도에 맞춥니다. 윤년 2월은 29일, 그 외는 28일로 처리합니다.
- `매년 4월 말까지`·`매월 말일까지` 등 마감만 확인되는 반복 일정은 마감 표식만 표시합니다.
  연도 없는 일정의 상세를 다시 조회해도 같은 개정·기간이면 선택한 달력의 날짜를 유지합니다.
- `매년 1월 ~ 재원소진 시까지(수시)`는 연도별 시작일이 있는 상시 접수 일정입니다.
  시작일 표식은 해당 월에만 표시하고 날짜별 공고는 시작일부터 포함하며 시작 전에는 제외합니다.
  종료일이 없으므로 마감 배지는 기존 `상시 접수`를 유지합니다.
- 복수 회차의 `applicationWindows`는 각 기간의 시작·마감 표식을 모두 표시합니다.
  회차 사이의 빈 기간에는 공고를 표시하지 않으며 날짜별 행·남은 기간·상세는 선택한 회차의
  시작·마감일을 사용합니다. 중복된 같은 날짜·종류의 표식은 한 번만 표시합니다.
- 시작·마감일이 없는 상시 접수·날짜 확인 필요 공고는 별도 목록입니다. 없는 날짜를 추정하거나 예시 공고로 채우지 않습니다.
- 필터와 선택 날짜는 일반/쉬운 화면 전환 시 유지됩니다. 좁은 화면에서는 날짜별 목록을 달력 아래에 배치합니다.
- 월·조건 변경이나 공개 공고 갱신 때 마지막 성공 결과를 유지합니다. 요청 상태는
  `role=status`, 일정 영역은 `aria-busy`로 알리고 다음 응답이 성공하면 월·조건·결과·선택일을
  함께 바꿉니다. 이전 월 표시 중 날짜 선택은 `aria-disabled`로 제한하고 월 이동은 이어갈
  수 있습니다. 실패해도 기존 결과를 보존하며 재시도 버튼을 제공합니다.
- `검색 범위 직접 선택`은 접힌 선택 영역입니다. 선택은 필수가 아니며 범위 변경은 적용된
  검색어와 선택한 월·날짜를 유지합니다. 조건 지우기는 자동 범위로 돌리고, 오타 수정의
  원래 검색어 선택은 `search_mode=literal`로 같은 원문을 검색합니다.

`calendarModel.js`는 날짜 계산·월 격자·이벤트·접수 기간 판정을 담당합니다.
`reconcileCalendarResult(previous, next)`는 다음 응답 메타데이터를 사용하면서 변경 없는
공고 객체만 재사용해 재조회 시 같은 공고의 번역이 초기화되지 않도록 합니다.
`createPolicyRepository().calendar(month, filters, {signal})`은 기존 `policiesPath` 뒤에
`/calendar`를 붙여 조회합니다. 응답과 날짜를 검증하며 요청 취소·늦은 응답 격리를 지원합니다.
서버 계약은 [API 관리대장](../../../../../api-management.md)의 공고 캘린더 항목을 따릅니다.

단위 검증: `tests/calendar.test.js`. PC/모바일 브라우저 검증:
`tests/e2e/calendar.spec.js`, `tests/e2e/calendar-search.spec.js`. 검색 범위 검증은 요청 전달,
기본 범위 생략, 게시기관·내용별 결과, 쉬운 화면 유지와 초기화를 확인합니다.
테스트 공고는 해당 테스트 안에서만 사용합니다.
추가 회귀는 느린 조회·실패·재시도 중 달력/날짜별 행/상시 목록의 DOM과 높이 유지,
취소한 월의 늦은 응답 격리, 지난 마감 공고 표시, 연도 없는 월 범위의 다음 해 시작·마감
표식과 접수 기간 내 일별 공고, 윤년 날짜 검증, 복수 회차 표식·기간 사이 공백과 선택한
회차의 상세 갱신 후 날짜 보존을 확인합니다.

## 다국어 화면

5개 언어의 버튼·검색 조건·빈 결과·접근성 안내는 `useI18n().t()`와 공통 기능 사전을 사용합니다. 월·요일·선택일은 선택 언어의 `Intl.DateTimeFormat`으로 표시하되 시간대는 `Asia/Seoul`을 유지합니다. API의 `YYYY-MM`, 날짜, 한국어 필터값은 그대로 전달합니다. 날짜 격자의 공고 제목과 날짜별/미확인 일정 행의 공고 내용은 `useVisibleTranslatedPolicy`로 화면 근처에서 번역하며 상세 열기/저장은 원본 공고를 전달합니다. 번역 대기/실패 시 한국어 원문을 표시하고 행에는 재시도를 제공합니다. 검증은 캘린더 단위 테스트·운영 빌드와 다국어 E2E의 언어별 월/요일·필터 요청 확인을 사용합니다.
