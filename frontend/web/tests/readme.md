## 브라우저 시나리오

`npm run test:e2e`는 Microsoft Edge/Chromium desktop/mobile 프로젝트에 다음 파일을 적용합니다.

- `e2e/app.spec.js`: 검색/태그/상세/저장, 쉬운 화면 프로필 한 폼·공고 3개 목록·설정 유지, 320px, 공고 API 실패/재시도. 모드 전환 시 작성 중 기본 프로필·저장 선택·검색 draft/적용 조건/태그/정렬 유지. 저장 목록 두 번째 페이지에서 4개→3개로 줄어도 남은 공고 모두에 접근할 수 있는 경계 시나리오 포함.
  두 번째 공고 페이지에서 검색어·지역·대상을 적용하면 cursor가 초기화되고,
  결과 건수가 갱신되며 조건 지우기로 전체 목록이 복원되는 흐름을 확인합니다.
  일반/쉬운 화면의 요약·신청 기간·지급 시기를 서로 다른 항목으로 표시하는 흐름도 검증합니다.
- `e2e/recommendations.spec.js`: 정상 빈 목록과 오류/재시도의 구분, 무정보 방문자의 일반 공고·하단 정보 부족 설명·내 정보 연결, 일부 저장 정보의 인기 공고와 공식 지표, 안전 후보 없음 안내, 실제 개인화 완료 응답의 배너/쉬운 화면 제목. 320px 두 모드의 레이아웃과 선택 지표의 누락/출처 링크도 확인합니다. 2026-10-07 실행 범위는 [정보 부족 추천 개선](../../docs/recommendation-fallback.md).
- `e2e/auth.spec.js`: 전화번호 인증·가입·로그인·세션 복원·로그아웃, 모드 전환 시 가입 입력 보존, 진행 중 인증의 모드 전환, 단계별 오류·초점·비밀번호 보기.
- `e2e/calculator.spec.js`: 비회원의 실제 API 호출 경로와 null/0 전송, 쉬운 화면 그룹 입력·그룹 후반부 오류 초점·모드 전환 시 금액 보존·320px, 서버 실패 시 가짜 결과 없음과 재시도, 저장 동의·명시적 회원 불러오기·없는 프로필의 입력 보존·삭제. 이 파일의 HTTP 응답 대역은 화면·전송 검증용이며 실제 서버 산식·DB 저장 통과를 의미하지 않음.

시나리오 추가나 `--list` 수집만으로 E2E 통과를 기록하지 않습니다. 2026-10-01 쉬운 화면 재설계에서는 CLI E2E를 실행하지 않았으며 위 경계 시나리오도 실행 통과 기록이 아닙니다. 단위 테스트와 직접 브라우저 확인의 현재 범위·과거 결과는 [쉬운 화면 검증 기록](../../docs/senior-mode.md)에 구분합니다.

백엔드 setup.ps1/setup.sh로 `.venv`를 먼저 준비해야 합니다. Playwright 설정이 기본 포트 8001의 FastAPI와 5173의 Vite를 시작하고 종료합니다. `E2E_API_PORT`와 `E2E_WEB_PORT`로 실행 중인 시연 서버와 다른 테스트 포트를 지정할 수 있습니다. 인증은 별도 `.cache/auth-e2e-*.sqlite3`를 사용하여 실제 HTTP/DB 흐름을 검증합니다. 기존 개발 서버를 재사용하지 않으므로 설정한 포트가 비어 있어야 합니다. 일부 실패·번호 변경·계산기 화면 시나리오는 HTTP 응답 대역을 사용합니다. 실제 문자 발송·MySQL·LLM·모바일 OS 검증은 아닙니다.
