# 모바일 회원가입과 카카오 로그인

2026-10-08 · 앱 0.3.0. `AccountAccess`에서 아이디 로그인, 이메일 회원가입, 카카오 가입/로그인을 선택합니다. 큰 글자·명확한 선택 표시를 쉬운 화면에도 적용합니다.

## 일반 가입

개인정보 안내·필수 동의 → 아이디 중복 확인·비밀번호 확인 → 이메일 인증 → 가입 확인 순서입니다. 인증번호 요청·확인은 `/v1/mobile/auth/email/request`, `/email/verify`, 가입은 `/signup`입니다. 서버가 발급한 이메일 인증 증명을 JSON으로 전달하며 웹 쿠키를 사용하지 않습니다. 회원가입이 완료되면 기존 모바일 로그인으로 이어집니다. 비밀번호·이메일·인증번호·일반 가입 초안은 기기에 영구 저장하지 않습니다.

가입 방법·입력 단계가 바뀌면 `useScreenStep`으로 화면 맨 위를 표시합니다. 폼을 다시 생성하지 않으므로 이전 단계 이동 시 입력값은 유지됩니다.

## 카카오

`kakao.js`는 주입한 HTTP·보안 저장소·브라우저·난수 생성기를 이용합니다. `expo-web-browser.openAuthSessionAsync`로 공식 카카오 인증 화면을 열며, 카카오톡 Android SDK의 설치 앱 자동 로그인은 사용하지 않습니다. 기존 웹 계정과 동일한 카카오 앱 ID/사용자 ID를 식별자로 사용합니다.

1. 앱에서 32바이트 난수 기반 PKCE verifier와 S256 challenge 생성.
2. `/v1/mobile/auth/kakao/start`에 challenge 전송 후, 같은 운영 API 출처의 `/authorize`만 열기.
3. 서버가 브라우저 결합 쿠키와 `mobile.` 네임스페이스의 state를 생성하고 기존 등록된 웹 카카오 Redirect URI 사용.
4. 서버 콜백이 공급자 인증을 확인하고 고정 `bokji-compass://auth/callback`으로 일회용 code·flow만 전달. 공급자/회원 액세스 토큰은 URL에 넣지 않음.
5. 앱에서 flow·주소를 검사하고 code+verifier를 `/exchange`에 전송. 기존 회원은 모바일 Bearer 로그인, 신규 회원은 이메일·가입 동의 후 `/complete`로 가입.

인증 시작/가입 대기는 10분, 복귀 코드 교환은 2분 유효합니다. PKCE 증명과 가입 대기 토큰은 SecureStore에 잠시 보관하여 앱 종료 후 복귀를 처리하고 성공·취소·만료 때 지웁니다. `+native-intent.tsx`는 복귀 주소를 계정 화면으로 연결합니다. 외부 링크의 토큰을 그대로 로그인에 사용하지 않습니다. 실제 세션 저장 실패 시 발급받은 세션을 폐기합니다.

`api.js`는 인증 응답 검증·입력 오류 안내, `signupModel.js`는 입력과 동의 검증, `SignupConsent`는 현재 서버 안내문 표시를 담당합니다. 선택 프로필·AI 동의는 기본 꺼짐이며 금융 저장 동의와 별개입니다.

## 검증

`tests/auth-signup.test.mjs`는 신규/기존 카카오 회원, 취소·공급자 실패, 다른 주소/state·중복 파라미터 거부, 앱 재시작, 코드 중복 처리, 보안 저장 실패, 일반 가입 입력·동의를 검사합니다. 서버의 `tests/test_mobile_signup.py`는 실제 임시 DB와 공급자/메일 대역을 사용합니다. 대역 검증은 실제 카카오 계정 인증 성공을 의미하지 않습니다. 실제 로그인 입력과 공급자 동의는 사용자가 진행해야 합니다.

0.3.0 릴리스 APK를 Pixel 2 에뮬레이터에 기존 서명으로 업데이트 설치하고, 실제 운영 HTTPS 연결에서 계정 화면의 카카오 버튼·일반 가입 안내·쉬운 화면 표시를 확인했습니다. 카카오 버튼으로 시스템 Chrome 인증 창이 열리지만 해당 에뮬레이터의 Chrome 첫 실행 설정이 표시되어, 실제 계정 인증은 사용자 진행을 요청했습니다. 화면 증거는 추적 제외된 `tmp/mobile-auth-qa/`에 있습니다.
