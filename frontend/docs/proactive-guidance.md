# 지속 복지 안내의 프런트엔드 연결

회원 계정에 저장한 생활정보를 바탕으로 지원 분야와 지원 후보를 추적하는 ‘AI 복지비서’ 독립 페이지(`#assistant`)를 제공합니다. AI 복지비서와 내 정보는 같은 `/v1/monitoring` 저장소를 조회합니다. 홈에는 페이지 진입 버튼을 배치합니다. 추천용 브라우저 저장과 계정의 지속 안내 저장은 별도이며, 기존 회원 주소·프로필·금융 계산 흐름을 그대로 사용합니다.

1. 회원이 주거 소유 형태·주택 종류·준공연도·수리 필요 여부, 실제 구직 여부, 직접 확인한 재난 종류·피해 여부·발생일을 선택적으로 입력합니다. 미확인 값은 비워 두며 지역 재난만으로 개인의 피해를 확정하지 않습니다.
2. 생활정보 저장·안내 활용 동의를 체크하고 지속 안내 켜기를 선택해 계정에 저장합니다. 서버는 저장된 생활정보와 회원 거주 지역으로 지원 탐색을 수행합니다.
3. AI 복지비서에서 내 상황 요약·새 안내·추가 확인 정보·신청 진행 상태를 먼저 확인하고, 관련 공고·살펴보는 이유·확인할 조건·신청 기간과 공식 링크를 봅니다. 신청 자격을 확정하지 않습니다.
4. 살펴보는 중·신청 준비 중·신청 완료·내게 해당 없음·지원 확인 완료의 상태를 직접 관리합니다. 표시된 새 안내의 읽음 상태와 최근 공고 확인 시각을 확인합니다.
5. 지속 안내를 중지하거나 저장한 생활정보·지원 후보 상태·새 안내를 삭제할 수 있습니다. 삭제 전에는 실제 삭제 범위를 표시합니다.

웹의 활성 화면은 저장된 새 안내를 주기적으로 조회합니다. 브라우저를 닫은 동안의 공고 비교는 서버의 monitoring 작업이 수행하므로 운영 환경에서 작업 실행과 상태 점검이 필요합니다. 수동 공고 다시 확인은 실제 서버 API를 호출합니다. 공고 저장소 장애는 생활정보 저장 성공과 구분해 표시하며 기존 안내를 유지합니다.

회원 거주 지역이 확인되면, 직접 피해를 입력하기 전에도 원문에 재난 지원 근거가 있는 등록 공고를 자동 탐색합니다. 서버의 `disaster_watch` 분야와 후보는 같은 UI에 동적으로 표시하며 실제 피해 여부·발생일 확인 질문을 함께 제공합니다. 모든 재난 지원 후보는 추가 확인이 필요한 안내이며, 지역에 재난이 실제로 발생했거나 회원이 피해를 입었다고 확정하지 않습니다. 회원이 피해 없음을 저장하면 이 탐색을 중지합니다. 피해 있음으로 저장하면 발생일을 모르더라도 피해 복구 분야를 이어서 안내하고 발생일을 추가 확인합니다. 같은 공고의 지원 진행 상태는 분야가 바뀌어도 이어지며, 현재 후보로 표시된 공고는 이전 기록에 중복 표시하지 않습니다.

이번 연결은 회원의 거주 지역·저장한 생활 상황과 현재 등록된 공고를 대상으로 합니다. 관공서의 실시간 재난 발생 공공 데이터 수집·실제 피해 확인, 상세 행정구역과 재난 영역의 매칭, 외부 푸시·메일 전송은 별도 후속 기능입니다. 합성 공고는 실제 UI/API에 넣지 않으며, 테스트 fixtures만 브라우저 검증에 사용합니다.
