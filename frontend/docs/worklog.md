# 프론트엔드 작업 기록

## 2026-09-22 — 개인비서 중심 화면·쉬운 화면·서버 호출자

요청에 따라 개인비서 추천 중심으로 홈을 변경하고, 로그인/가입은 입력폼까지만 구현했습니다. 기존 녹색 계열·데스크톱 사이드바·모바일 하단 탐색을 유지했습니다.

### 변경

- 내 정보 입력 → 공고 추천 및 추천 이유 → 상세/저장. API 모드는 서버 설명을 표시하고 demo는 명시된 결정적 UI 예시로 구분.
- 로그인/가입 이메일·비밀번호·비밀번호 확인 입력폼. 제출 비활성, 인증/계정 저장/요청 없음.
- 쉬운 화면의 큰 글자·큰 컨트롤·모션 제거, 3단계 정보 입력, 공고 한 개씩 보기, 복잡한 조건/상세 접기. [참고와 기준](senior-mode.md).
- 모든 공고 카드와 상세 태그 → URL tag 필터. 직접 검색·분야·지역·대상·정렬과 cursor 페이지.
- GET /v1/policies, POST /v1/recommendations의 제안 계약 호출자. 취소/시간 초과/스키마 검증/빈 결과/실패/재시도. 오류 시 예시 fallback 없음.
- 개발 기본 demo, 운영 기본 api, 배포 시 app-config.js로 공개 주소 변경. [배포 절차](deployment.md)와 Nginx 예시. 실제 배포 수행 없음.
- 프로필은 기본 메모리, 선택 동의 후 localStorage. 전송 필드 whitelist. 예시/API 저장 스냅샷 분리. Android/iOS 공개 HTTP 경계 유지.
- 루트 API 관리대장·README 트리·프론트 관련 README/구조/연동/모바일/협업 문서 갱신. 서버의 실제 구현 경로와 제안 경로를 구분.

### 검증

- Node 단위 테스트 12개 통과: 검색/태그/cursor, 응답 검증, 추천 payload, API 오류 시 fallback 없음, 운영 설정, 저장 실패, HTTP 취소/시간 초과.
- 최종 npm run format:check 및 npm run build 통과.
- Codex 브라우저 도구로 1440px 데스크톱, 390px 모바일, 320px 좁은 화면 확인. 쉬운 화면 20px 기준·한 개 공고, 3단계 입력, 기억하기 후 새로고침, 추천 이유, 태그/뒤로가기, 검색 결과 없음, 상세 저장/유지, Escape·초점 복귀, 로그인/가입 제출 비활성 확인. 320px 본문/상세 가로 넘침 없음.
- 운영 번들을 4173 preview에서 열어 API 연결 실패·재시도·예시 카드 0개를 확인. 실제 API 성공/LLM 응답은 미검증(서버 미구현). 검증용 preview 프로세스 종료.
- 기존 CLI E2E 시나리오는 새 흐름에 맞춰 갱신. 이번에는 CLI 실행 대신 Codex 브라우저 도구로 직접 검증했으므로 E2E suite 통과로 표시하지 않음.
- 문서 73개에서 상대 파일 링크 290개 검사, 깨진 링크 없음(작업 기록 갱신 직전 기준).

### 후속

서버의 공고 조회·LLM 추천 API와 최종 OpenAPI·인증/인가·개인정보 보관/비용 정책 확정, 실제 운영 배포. 실제 시니어 참여 검증, 브라우저 200% 확대, iOS Safari/Android 및 보조기기 검증은 별도 필요. 이번 작업에서 백엔드 구현을 수정하거나 웹을 외부 공개하지 않았습니다.

## 2026-09-22 — 웹 시작점과 모바일 확장 경계

요청: 프로젝트 문서를 기준으로 비어 있던 프론트를 구현하고, 향후 Android/iOS 앱 개발을 고려.

읽은 기준: 루트 README, 백엔드 현재 상태·데이터 계약·구현 계획·공개 API, 프론트 API 연동 현황. 기존 프론트 문서는 API 연동 현황을 제외하면 빈 파일이었으며 실행 소스/패키지는 없었음.

### 구현

- React/JavaScript + Vite, 고정 dependency lock, 개발/배포/테스트/포맷 명령과 공개 환경변수 예시.
- 세이지·그린 계열의 반응형 홈, 직접 작성한 SVG 나침반 일러스트, 데스크톱 사이드바와 모바일 하단 네 메뉴.
- 합성 예시 6개의 키워드 검색·분야/지역/대상 필터·정렬·상세 모달·관심 혜택 저장.
- 관심 지역/분야 설정과 localStorage 저장. 스키마 검증, 손상/권한 오류 처리, 서버 전송 없음.
- 빈/로딩/오류 화면, 모달 키보드 초점·Escape, hash 뒤로 가기, 모바일 safe-area와 320px 폭 대응.
- HTTP 연결 확인은 문서화된 GET /health만 사용. 업무 API를 가정하거나 DB/원문에 직접 연결하지 않음.
- 검색·프로필 검증은 순수 JS, 화면·HTTP 환경·브라우저 저장소는 별도 파일로 분리. Android Java 계획 유지, iOS 계획 문서 추가.
- 역할·호출 입력/반환·오류·실행/검증·배포 proxy·플랫폼 경계를 README와 architecture/api-integration에 기록.

### 검증

- `npm.cmd test`: 4개 통과. 검색 조합·전국 포함·정렬 비변경·손상 프로필·저장 오류.
- `npm.cmd run build`: 배포 번들 생성 성공.
- `npm.cmd run test:e2e`: Microsoft Edge/Chromium의 데스크톱·모바일 총 8개 시나리오 통과. 필터·빈 결과·상세·저장 유지·프로필 유지·뒤로가기·포커스·320px 가로 넘침·health 성공/실패 대역 검증.
- 데스크톱/모바일 스크린샷을 확인하고 작은 설명 글씨의 크기와 대비를 보완.
- 최종 검증 중 외부 폰트 로딩 대기로 모바일 테스트가 지연되는 현상을 확인하여 폰트를 Fontsource 패키지로 자체 제공하도록 변경하고 재검증.
- npm 설치 감사: 발견된 취약점 0개. 환경의 Windows 샌드박스 쓰기 제한으로 npm 설치·포맷·빌드·브라우저 실행에는 승인된 도구 권한을 사용.

### 남은 작업

실제 정책 API 계약 및 어댑터, 페이지네이션, 공식 원문 연결, 인증/기기 동기화, 사용자 자격 판정, 운영 배포, Android/iOS 네이티브 구현·기기 검증. 지금의 예시는 실제 신청 가능한 정책이 아니며 E2E의 API 대역 성공은 실제 서버 연동 검증과 구분함. 모바일 화면 검증은 iOS Safari/네이티브 검증을 대신하지 않음.
