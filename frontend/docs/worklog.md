## 2026-10-06 — 해커톤 Android 독립 APK 준비

- 사용자 배포 대상은 Android이며 첫 출시용 새 배포 키 생성을 선택했다.
- `release:android`에 설정·타입·린트·회귀·Prebuild·Gradle release·zipalign·서명·APK 검사 연결.
  JS를 포함하고 ARM/x86_64를 지원하며 Metro 없이 실행하는 APK를 생성한다.
- `release:key`는 기존 키를 덮어쓰지 않고 새 RSA 배포 키와 Windows DPAPI로 보호한
  로컬 비밀번호를 생성한다. keystore/자격 증명은 Git 제외를 확인했다.
- 릴리스 검사에서 실제 Expo 설정과 HTTPS 주소, 설치된 공유 계산 core의 최신 여부를 검사.
  EAS preview APK/production AAB와 빌드 후 설정 검증 훅을 추가했다.
- SDK의 알림·FCM 필수 권한과 SEND 권한으로 보호한 FCM 수신기를 검사기가 정상 허용하도록
  수정했다. 실제 합쳐진 Manifest에서 사용하지 않는 배지·설치 유입 권한 17개를 발견해 제거했다.
- ESLint 캐시 파일 쓰기 권한 오류가 배포 검증을 막지 않도록 `npm run lint`는 전체 무캐시 검사.
- 실제 native release에서 Ninja의 260자 파일 경로 제한 오류를 재현했다. Windows에서는
  짧은 `tmp/cxx` staging 경로와 CMake 객체 경로 해싱을 적용하도록 config plugin을 수정했다.
  기존 생성 프로젝트도 `--clean` 없이 최신 plugin 블록으로 갱신한다.
- PowerShell 7에서 Windows PowerShell을 호출할 때 잘못된 보안 모듈이 로드되지 않도록
  해당 셸의 내장 모듈을 명시적으로 사용한다. 생성된 자격 증명은 데스크톱 계정에 맞게
  DPAPI 재보호했고 비밀번호를 출력하지 않았으며 임시 암호화 전달 파일은 제거했다.
- 모바일 80개와 타입·린트, APK 권한/수신기 검사 4개 통과. 변경 전 서버 회귀는
  631 passed/21 skipped이며 MySQL 선택 검사는 실행하지 않았다.
- 실제 공개 HTTPS API의 health/ready/공고 조회 200 확인. ready의 database는 reachable.
- npm audit는 high 19개로 node-forge(기존 로컬 패치)와 braces(공식 수정 없음)의 전파 결과.
  [배포 명령·서명 보관·남은 의존성 제한](android-release.md).
- 실제 3개 ABI native release Gradle 빌드 성공. APK 리소스 최적화가 XML 파일명을 줄이는
  동작도 재현해 검사기가 리소스 테이블에서 실제 파일명을 읽도록 수정했다.
  XML 누락·추가 변형 파일의 검사 우회는 계속 차단하며 APK 검사 회귀 6개를 통과했다.
- 새 배포 키로 서명한 APK의 21개 정적 검사 모두 PASS. 디버그/개발 컴포넌트 없음,
  JS 번들 포함, 정확한 서명 지문, HTTPS/백업 정책과 알림 권한 확인.
  실제 휴대폰 설치·화면 동작·원격 푸시는 이번 검증에 포함하지 않았다.
- 공유 파일은 `output/android-release/bokji-compass.apk` (약 83.1 MB),
  SHA-256 `afee39881bc00e2fbe63fe9a5b4d7d290a934088c1f66dc54b1c72295d041aa5`.
  `release:android -- -SignOnly`의 실제 서명·검사·파일 복사 경로도 성공했다.

- 선택 및 오류 테두리를 덮던 쉬운 화면 전용 입력 테두리와 금융 입력·안내 색상도 제거했습니다.
- 검증: 운영 빌드 통과. 실제 8080 화면에서 모드를 전환해 본문·배경·주 버튼·선택 메뉴·입력·데모 배너·제목의 계산된 색상이 동일함을 확인했습니다. CSS 변경으로 기능 테스트는 추가하지 않았습니다. 아래 초기 개편의 청록 팔레트 대비 수치는 변경 전 기록입니다.

## 2026-10-01 — 쉬운 화면의 정보 구조와 조작 흐름 개편

- KRDS 디자인 원칙·버튼·입력폼·디스클로저와 NIA·W3C의 접근성 자료를 확인했습니다. 나이로 이용 능력을 단정하지 않고, 중요한 정보와 기능을 유지하면서 반복 행동을 줄이는 방향으로 개편했습니다. 출처와 프로젝트의 설계 선택은 [쉬운 화면 설계](senior-mode.md)에 구분해 기록했습니다.
- 홈은 주 행동 하나와 안내를 구분하고, 따뜻한 중립 배경·짙은 청록색·18px 본문·절제된 제목 위계를 적용했습니다. 공고는 세 개씩 비교하는 목록으로 바꾸고 카드별 버튼을 ‘자세히 보기’ 하나로 줄였습니다. 지원 내용·대상·신청 기간은 목록에서 표시하며 저장과 태그 탐색은 상세에 유지합니다.
- 추천 정보는 논리적 구역으로 나눈 한 폼에서 제출합니다. 쉬운 계산기는 가구·가구원별 소득·재산·부채·차량으로 묶어 1인·차량 없음 기준 입력 화면을 10개에서 5개로 줄였습니다. 금액 상태는 선택상자로 구분하고, 만원 입력·0/null·원 단위 API 계약을 유지했습니다. 이동 버튼을 고정 해제하여 입력을 가리지 않도록 했습니다.
- 저장 공고가 4개에서 3개로 줄 때 마지막 페이지에 남아 앞의 공고에 접근할 수 없던 경계 문제도 페이지 시작 위치 기준으로 보정했습니다.
- 검증: Node 단위 테스트 26개와 Vite 운영 빌드 통과. 인앱 브라우저에서 추천 정보의 모드 전환·한 폼 제출·추천 3개, 공고 3개 페이지 이동·필터 보존·상세 저장·Escape 초점 복귀, 계산기 후반 항목 오류 초점·0/미확인 구분·500 입력의 5,000,000원 확인·실제 로컬 API 결과까지 확인했습니다. 320px 홈·목록·추천 폼·계산기와 768/1440px 목록에서 가로 넘침이 없음을 확인했습니다.
- 주요 색 조합의 계산 대비는 주 버튼 7.81:1, 본문 10.90:1, 흰 배경의 보조 글자 6.31:1, 입력 테두리 4.05:1입니다. 320px 추천 폼의 선택상자 50px, 계산기 이동 버튼 약54px과 static 배치를 확인했습니다. 전체 접근성 인증을 의미하지 않습니다.
- E2E 시나리오는 새 목록·그룹 입력·저장 페이지 경계에 맞춰 갱신했으며 이번에는 CLI E2E를 실행하지 않았습니다. 실제 고령 사용자 평가·보조기기·200% 확대·실기기 검증은 남아 있습니다. 인증 기능·서버 산식은 변경하지 않았습니다.
- 빌드 결과를 기존 시연 웹 서버에 반영하고 확인했습니다. 내부 점검 스크린샷은 로컬 `tmp/senior-redesign/`에 있습니다.

## 2026-10-01 — 금액 입력을 만원 단위로 변경

- 소득·주택·전월세 보증금·기타 재산·부채·차량 가액을 만원 단위로 입력하도록 변경했습니다. 보증금 500만 원은 `500`으로 입력하며, 입력칸 옆 단위와 원 단위 환산 안내를 표시합니다.
- API 요청·DB 저장·계산 결과는 기존 원 단위 정수를 유지합니다. 기존 저장액을 불러올 때 만원으로 표시하고, 소수점 넷째 자리(1원)까지 보존하여 재저장 때 금액이 달라지지 않게 했습니다. 없음(0)·모름(null), 소수 입력 중 상태, 화면 이동·수정 흐름을 유지합니다.
- 검증: 프론트 단위 테스트 26개, 계산기 E2E 10개 시나리오 × 데스크톱/모바일 = 20개 통과(최초 16개와 안내문 선택자 수정 후 재실행 4개), Vite 운영 빌드 통과. E2E는 응답 대역으로 화면과 원 단위 요청 본문을 검사하며, 실제 DB·계산 서버 연동 검증과 구분합니다.
- 실행 중인 공개 시연 서버와 충돌하지 않도록 E2E API 포트도 `E2E_API_PORT`로 지정할 수 있게 했습니다. 검증에는 웹 5182·API 8013을 사용했습니다.

- 기존 서버 API·입력 계약·산식은 유지했습니다. 질문 정의/검증, 입력/요약, 도움말, 결과 컴포넌트를 분리했습니다. 단계 이동은 해당 질문만, 최종 확인·계산은 전체 계약을 검증합니다.
- 검증: 기존 프론트 단위 테스트 22개 통과, 계산기 E2E 9개 시나리오 × 데스크톱/모바일 = 18개 통과(기본 16개와 추가 계정 경계 2개로 나누어 실행), Vite 운영 빌드 통과. 320px 쉬운 화면 스크린샷을 시각 확인하고 가로 넘침·키보드 Enter·오류 초점·0/null·차량 상세·서버 오류 재시도·회원 동의/저장/불러오기/삭제·초안 복구·로그인/로그아웃을 검증했습니다.

- 변경 파일의 포맷은 정리했습니다. 전체 `format:check`에는 이번에 변경하지 않은 기존 파일들의 포맷 경고가 남아 있어 전체 통과로 기록하지 않습니다.

## 2026-09-25 — 반응형·쉬운 화면 개선과 소득·재산 계산기

### 화면과 문구

- 원격 Git의 기존 로그인·회원가입·전화번호 인증 구현을 기준으로 UI를 개선했습니다. 가입의 단계별 오류 안내·비밀번호 표시·초점 이동과 기본/쉬운 모드 간 입력 보존을 반영했습니다.
- 기본 프로필·검색 조건이 화면 모드 전환 때문에 초기화되지 않도록 조정했습니다. 검색 페이지 크기가 바뀌면 첫 페이지로 돌아갑니다.
- 기본 탐색을 1024px 이하 하단 메뉴로 전환하고, 공고 카드는 가용 폭에 따라 1~3열로 배치합니다. 홈·로고·상단 계정 메뉴·가입 폼·페이지 이동의 줄바꿈과 좁은 화면 배치를 보완했습니다.
- 홈의 중복 입력 버튼을 줄이고 쉬운 화면에서는 반복 보조 제목을 덜어냈습니다. 정보 입력을 마친 쉬운 홈은 추천에 바로 집중하도록 짧게 표시합니다. 추천 이전/다음 이동 시 새 카드 제목으로 초점을 옮깁니다.
- 홈·프로필·공고·가입의 과장된 표현과 모호한 행동 문구를 실제 기능·다음 행동 중심으로 고쳤습니다. 데모 공고의 제목은 유지하고 설명에 예시임을 분명히 했습니다.

### 계산기와 데이터 경계

- `#calculator`에 가구·소득 → 재산·부채 → 결과 흐름을 추가했습니다. 기본 화면은 섹션 전체, 쉬운 화면은 세 단계로 표시하며 회원가입 없이 실제 서버 계산을 요청할 수 있습니다.
- 가구원별 근로·사업·기타소득·사적이전소득·공제 유형, 소유 주택·전월세 보증금·일반·금융 재산, 부채 유형, 차량별 금액·종류·용도·제원을 구분합니다. 없는 항목의 0과 모르는 항목의 null을 다르게 전송합니다.
- 계산식은 프론트에 복제하지 않고 서버의 2026년 규칙·공식 출처를 사용합니다. 중위소득 단순 비율, 생계급여 기본 산식, 차상위 확인사업 기본 산식, 국민임대 일반 소득·자산 비교를 구분하여 표시합니다. 사업별 한도의 반올림·가구원 수 확장도 서버 책임입니다.
- `estimated`/`needs_review`, 개별 비교의 `within`/`over`/`unknown`, 미입력·추가 검토 사항과 공식 근거를 표시합니다. 수급자·차상위·자동차 특례나 최종 신청 자격을 확정하지 않습니다.
- 비회원 금융정보는 실행 중 메모리만 사용하고 브라우저 저장소에 기록하지 않습니다. 회원은 별도 체크 동의 후 서버에 저장하고 명시적으로 불러오거나 삭제합니다. 저장된 정보가 없는 응답은 작성 중 입력을 유지합니다. 계정 전환·로그아웃은 이전 회원의 금융 메모리와 진행 중 응답을 버립니다.
- 일반 추천 프로필의 브라우저 저장, 저장 공고, 회원 금융정보 저장을 분리했습니다. 계산·회원 저장 실패 시 예시 결과로 대체하지 않습니다.
- 사용자가 ‘관련 공고 살펴보기’를 선택한 뒤에만 후속 추천 요청의 `financialProfile` 확장을 활성화합니다. 금융정보 갱신·계정 전환은 선택을 해제합니다. 공고·LLM 추천 서버는 여전히 미구현이며 demo는 금융조건으로 자격을 판단하지 않습니다.

### 검증 기록의 범위

- 프로필·검색·가입의 모드 전환 회귀 시나리오, 금융 원자료·요청·응답 계약 단위 테스트, 게스트 계산·명시적 회원 저장·빈 프로필·실패 처리 브라우저 시나리오를 추가했습니다.

- 최종 Node 단위 테스트 22개, Prettier 전체 검사, 운영 빌드 통과. Playwright 시나리오 32개 수집 확인(`--list`); 이번에는 CLI E2E 전체를 실행하지 않았으며 아래 실제 브라우저 점검과 구분합니다.
- 소득의 세전·경비 기준과 차량 명의·등록용도·공적가액·보조금 항목 추가. 양수 소득에만 기준 질문을 표시하며 차량 상세는 쉬운 화면에서 접습니다. 이전 입력에 새 기준이 없으면 unknown으로 읽고 임의 분류하지 않습니다.
