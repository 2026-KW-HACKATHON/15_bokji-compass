# 웹·앱 쉬운 화면 접근성 개편

2026-10-08 · 대상은 사용자가 켠 쉬운 화면입니다. 기존 서비스 색상과 서버 계약을 유지하고 정보 위계·명료한 조작·작은 화면 가독성을 개선했습니다.

## 참고 기준과 구현

[Apple Human Interface Guidelines: Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)를 확인했습니다. 동적으로 표시되는 본문은 Apple의 [문서 데이터](https://developer.apple.com/tutorials/data/design/human-interface-guidelines/accessibility.json)에서도 확인했습니다. 충분한 대비, 글자 확대에 대응하는 배치, 색 이외 상태 표현, 조작 영역/간격, 키보드 조작, 간단한 동작과 모션 감소를 참고했습니다. 이 문서는 전체 접근성 인증이나 모든 보조기술 검증을 의미하지 않습니다.

- 웹: 기본 브라우저 글자 크기를 따르는 112.5% 루트, 주요 제어 56px 이상, 설명 0.94~1rem, 명시적 테두리와 초점 표시. 큰 제목만 키우지 않고 레이블·도움말·일정·출처도 읽을 수 있게 조정했습니다.
- 앱: 공통 텍스트의 쉬운 화면 최소 20sp와 1.5배 줄 간격, 시스템 글자 확대 허용, 주요 버튼 최소 60dp, 충분한 입력/선택 영역과 명시적인 선택 표시. 하단 탭은 두 줄을 허용하고 시스템 글자 크기에 따라 높이가 늘어납니다.
- 위 수치는 제품 설계 선택입니다. Apple 플랫폼의 pt, 웹 CSS px, React Native 논리 단위를 동일한 규격으로 취급하지 않습니다.

## 사용자 흐름

웹 헤더는 현재 위치와 직접 여닫는 전체 메뉴를 제공합니다. hover나 가로 스와이프가 없어도 모든 경로에 접근할 수 있습니다. 큰 헤더가 본문을 가리지 않도록 쉬운 화면에서 고정 헤더를 해제했습니다. Escape는 메뉴를 닫고 열기 버튼으로 초점을 돌려줍니다. 이동 시 메뉴가 접히고 본문으로 초점이 이동합니다.

홈 검색은 지역·검색어 레이블을 항상 표시하고 돋보기 옆에 ‘검색’을 표시합니다. 분야 버튼은 여유 있는 간격으로 배치합니다. 모드 전환 시 입력한 값은 유지합니다. 이모지 언어 표시는 동일한 선형 아이콘으로 교체했고 아이콘 단독으로 동작을 설명하지 않습니다. 모달 닫기와 배너 이동도 글자 레이블을 제공합니다. 쉬운 화면에서는 배너가 자동으로 넘어가지 않습니다.

공고 카드·조건·검색 필터·프로필·계산기는 읽기 순서에 따라 배치하고 좁은 화면에서 한 열로 바뀝니다. 달력은 날짜 입력·하루 이동을 기본으로 제공하며 월간 날짜 목록은 직접 펼칩니다. 날짜 선택은 입력 초점을 유지하고 결과 제목만 조용히 알립니다. 선택과 저장은 테두리/체크/텍스트도 함께 표시합니다.

웹 챗봇은 쉬운 화면에서 본문을 덮는 아바타 대신 문서 아래의 도움말 바로 진입합니다. 개인정보·신청 자격 관련 안내와 공식 출처는 유지합니다. 앱에서는 복잡한 그래픽과 작은 아이콘 버튼을 줄이고, 의미가 있는 선형 아이콘과 텍스트를 함께 표시합니다.

## 검증

- 웹 단위 테스트 154개와 운영 빌드 통과. 최종 빌드는 Vite 임시 설정 파일의 Windows 접근 오류를 피해 `npm run build -- --configLoader runner --outDir ../../tmp/easy-web-dist`로 확인했습니다. 달력 날짜 이동 회귀는 윤년·월말·연말·허용 날짜 경계·잘못된 입력을 검사합니다.
- 앱 타입 검사·린트·단위 테스트 133개, Android/iOS Hermes export 통과. 설치용 APK/IPA를 만들거나 실제 기기에 설치한 검증은 아닙니다.
- Codex in-app browser에서 웹/앱 미리보기를 320px에서 확인했습니다. 웹에서 전체 메뉴 열기/이동/Escape 초점 복원, 일반↔쉬운 전환 검색어 유지, 날짜 이동과 초점 보존, 가로 넘침을 점검했습니다.
- 웹 1280px 및 320px 베트남어 줄바꿈, 로그인·계산기 화면을 추가 확인했습니다. 메뉴·캘린더·챗봇·일정 레이블의 E2E 시나리오는 현재 UI에 맞춰 갱신했으며, 이번 검증은 in-app browser 상호작용으로 수행했습니다. Playwright 전체 E2E suite는 실행하지 않았습니다.
- 앱 미리보기에서 발견한 헤더 브랜드 압축과 switch의 접근성 상태 불일치는 수정 후 재확인했습니다. 개발용 API가 연결되지 않은 앱 화면에서는 서버 연결 안내를 확인했으며 실제 계정·공고 데이터 처리는 이번 시각 검증의 범위가 아닙니다.
- VoiceOver/TalkBack, 실제 기기 시스템 글자 200% 이상, 앱 스토어 접근성 표시는 별도의 기기 검증이 필요합니다. 웹의 작은 폭 검증을 실제 기기/보조기술 검증으로 간주하지 않습니다.

## 파일 경계

- `web/src/app/EasyNavigation.jsx`: 쉬운 메뉴의 상태와 초점.
- `web/src/app/easy-shell.css`: 포털 이후 적용하는 쉬운 화면 공통/홈 스타일.
- `web/src/app/easy-features.css`: 검색·공고·캘린더·폼·비서별 스타일.
- `mobile/src/components/`, `mobile/src/i18n/LocalizedText.tsx`: 앱 공통 크기/간격/아이콘/레이블.
- `mobile/src/features/`: 각 화면의 쉬운 배치와 상태 표현.
- `packages/core/src/i18n/navigationMessages.js`: 새 날짜 조작과 짧은 동작 레이블의 5개 언어 사전.

같은 작업 폴더에서 수행된 별도 병합 후 `policyModel.js`에 남아 있던 충돌 마커는 두 import를 모두 보존한 채 제거했습니다. 서버 보안과 달력 날짜 검증을 함께 유지합니다.

## 배포 화면의 홈 아이콘 보완

사용자가 배포 주소에서 홈의 작은 아이콘과 연한 분야명을 지적해 해당 행을 추가 개선했습니다. 일반 화면 분야명은 14px와 `#465e73`로 높였고, 쉬운 화면은 18px 분야명·32px 아이콘·2.2 선 두께·명확한 카드 테두리·56px 이상의 행동 표시를 사용합니다. 의미를 나타내는 가방·집·지갑 도형과 글자 레이블을 함께 유지합니다. 앱의 대응 아이콘은 60dp 타일 안에 34dp 도형과 2.25 선 두께로 표시합니다.

웹 단위 테스트 154개와 운영 빌드를 다시 통과했습니다. 검증한 새 정적 자산을 기존 `frontend/web/dist/assets`에 먼저 추가하고 진입 HTML을 마지막에 갱신했습니다. 기존 자산과 런타임 설정·APK 파일은 유지했습니다. 공개 주소 `https://bokji.commitnaru.com`에서 새 CSS `index-BugSxB3c.css`, 분야명 18px, 아이콘 32px/2.2를 확인했으며 1280px·320px에서 가로 넘침이 없었습니다. 일반 화면에서도 14px/진한 분야명을 확인했습니다. 쉬운 화면 설정은 브라우저 출처별로 저장되므로 로컬 미리보기에서 켠 설정이 배포 주소로 자동 전달되지는 않습니다. 이번 보완에서 앱은 타입 검사와 린트를 통과했으며 설치된 APK를 업데이트한 것은 아닙니다.
