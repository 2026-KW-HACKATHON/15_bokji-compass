# 웹 구조와 Android/iOS 확장

담당: 프론트엔드. 웹 설명 기준은 2026-09-25이며, 2026-10-01 모바일 첫 이식을 [이식 기록](mobile-migration.md)에 추가했습니다.

## 서비스 흐름

목표 흐름은 서버가 공고를 수집·검토해 공개 목록을 공급하고, 입력된 사용자 정보를 바탕으로 서버의 개인비서 LLM이 관련 공고와 설명을 추천하는 것입니다. 웹은 결과를 표시하며 LLM/DB/원천 수집 API에 직접 접근하지 않습니다. 추천은 지원 자격 확정과 다릅니다.

현재 서버에는 health/readiness, 회원가입·로그인·전화번호 인증·세션 조회·로그아웃, 소득·재산 계산과 회원별 금융정보 저장 API가 있습니다. 공고 목록과 추천 API는 미구현이며 [해당 HTTP 계약은 제안](service-contract.md)입니다. 웹은 개발 기본 demo, 운영 기본 api 모드를 사용합니다. 공고·추천의 demo 모드에서도 인증과 계산기는 실제 서버를 호출합니다. 구현 현황과 정확한 요청·응답은 [루트 API 관리대장](../../api-management.md)을 기준으로 합니다.

웹 화면: 내 비서 → 내 정보 → 추천 이유·공고 상세. 전체 공고·저장한 공고·소득·재산 계산기도 별도 제공합니다.
경로는 #home, #explore, #calculator, #calculator-details, #saved, #profile, #login, #signup. 태그는 #explore?tag=...에 보관하며 브라우저 뒤로 가기로 복원됩니다. 계산기는 비회원도 사용하며 회원 저장은 선택입니다.

## 책임

- app/App.jsx: 라우팅·모드·기본 프로필·추천 상태·로컬 저장·로그인 상태 조립. 금융 프로필은 계정 소유자를 구분한 메모리에만 유지. 프로필 변경 시 이전 요청 취소 및 오래된 응답 무시. 앱 시작 시 세션 조회, 로그인 성공 시 사용자 표시, 로그아웃 시 세션 종료 처리.
- app/services.js: 공개 설정으로 API/demo repository 생성.
- features/assistant: 입력된 정보로 추천 요청, 서버 설명 표시. demo는 명시된 정렬 예시.
- features/policies: 페이지/필터 요청, 응답 모델 검증, 화면. 모든 카드/상세 태그가 검색으로 연결.
- features/profile: 선택값 검증·전송 필드 whitelist. DOM 없는 모델과 웹 폼 분리.
- features/finance: 가구·소득·재산·부채·차량 입력, 서버 계산 응답 검증·표시, 명시적 회원 저장·불러오기·삭제. 금액의 빈칸과 0을 구분하고 산식은 서버에만 둠. [모듈 경계](../web/src/features/finance/readme.md).
- shared/api: 공고·추천 요청의 HTTP 상태·JSON·네트워크·시간 초과·취소 처리. 이 클라이언트는 credentials=omit을 사용하며 인증 요청은 별도 어댑터가 담당.
- shared/config: 런타임 공개 설정과 빌드 설정 해석.
- shared/storage: 브라우저 저장 실패·손상 격리.
- features/auth: 아이디 로그인, 이름·계정 정보·전화번호 인증을 포함한 회원가입. authApi.js는 credentials=include와 X-Auth-Request 헤더로 실제 인증 API 호출. 쉬운 화면의 가입 폼은 계정 만들기 → 기본 정보 → 전화번호 인증 3단계.

## 계정 인증

| Method | 서버 경로 | 웹 역할 |
|---|---|---|
| POST | /v1/auth/phone/request | 인증번호 요청·재전송 대기 표시 |
| POST | /v1/auth/phone/verify | 번호 확인 후 가입용 인증 증명 보관 |
| POST | /v1/auth/signup | 계정 정보와 인증 증명으로 가입 |
| POST | /v1/auth/login | 로그인 성공 시 사용자 표시, 서버가 HttpOnly 세션 쿠키 설정 |
| GET | /v1/auth/me | 앱 시작 시 현재 로그인 상태 복원 |
| POST | /v1/auth/logout | 서버 세션·쿠키 폐기 |

웹 기본 API 주소는 /api이므로 개발 프록시를 거쳐 위 경로로 전달합니다. 인증 요청 제한은 15초이며 공고·추천의 demo/API 모드와 독립적입니다. 실제 SMS 공급자는 미연결 상태입니다. 서버가 development_code를 반환할 때만 시험용 번호와 실제 문자가 발송되지 않았다는 안내를 표시합니다. 운영에서 개발용 번호를 사용하는 대체 로그인은 제공하지 않습니다. [서버 인증 계약](../../backend/app/modules/auth/readme.md).

## 저장과 개인정보

| 키 | 내용 |
|---|---|
| bokji.easy.v1 | 쉬운 화면 boolean |
| bokji.profile.v2 | 선택해서 기억한 프로필만. 기본은 메모리 |
| bokji.saved.v2.demo / bokji.saved.v2.api | 모드별 공고 스냅샷 배열, 최대 500 |

예전 v1 예시 ID/관심 설정은 신규 개인정보 선택 동의와 분리해 자동 이관하지 않습니다. 기존 키는 사용하지 않습니다.
API 모드에서 추천받기를 누르거나 저장된 프로필로 앱을 다시 열면 서버 추천을 요청합니다. 브라우저에 저장된 정보는 평문 사이트 저장소이며 비밀/인증 보관소가 아닙니다. 선택 해제 후 추천받기를 누르거나 내 정보 지우기로 제거합니다. 저장/삭제 실패는 화면에서 알립니다.

가입 정보는 인증 API를 통해 서버에 전송·저장합니다. 비밀번호와 가입용 인증 증명은 브라우저 localStorage에 저장하지 않으며, 웹 앱은 HttpOnly 세션 쿠키를 직접 읽지 않습니다. 가입 입력값과 인증 진행 상태는 같은 화면에서 쉬운 모드를 바꾸거나 단계 간 이동할 때 유지하지만 새로고침을 넘겨 저장하지 않습니다.

지역·연령대·관심 분야로 구성된 기본 추천 프로필과 저장한 공고는 계정 정보에 연동하지 않습니다. 로그인해도 가입 정보로 기본 추천 프로필을 자동 채우거나 다른 기기에 동기화하지 않으며, 로그아웃해도 해당 브라우저의 기본 추천 프로필·저장 공고를 자동 삭제하지 않습니다. 기본 추천 프로필은 별도 입력·브라우저 저장 선택·삭제가 필요하고, 저장 공고는 브라우저와 데이터 모드별로 관리됩니다.

금융 프로필은 위 기본 프로필과 별개입니다. 비회원은 계산기에 입력한 원자료를 브라우저의 실행 중 메모리에만 보관하며 localStorage/sessionStorage에 기록하지 않습니다. 같은 실행 중 계산한 정보는 로그인 후 저장을 선택할 수 있지만 로그인만으로 서버에 저장하지 않습니다. 회원은 ‘이 정보를 내 계정에 저장’에 동의하고 저장 버튼을 눌러야 서버에 저장합니다. 불러오기도 버튼을 누를 때만 실행하며, 저장된 정보가 없으면 현재 입력을 유지합니다. 로그아웃·계정 전환 시 이전 회원의 금융 메모리와 진행 중 응답을 버립니다. 새로고침한 회원도 서버에서 명시적으로 다시 불러와야 합니다.

회원 금융정보 삭제는 ‘계정에 저장한 정보 삭제’로 확인 영역을 연 뒤 ‘저장 정보 삭제하기’를 눌러야 요청합니다. 취소할 수 있으며, 삭제 성공 시 서버의 금융 프로필과 현재 금융 메모리만 제거합니다. ‘이 화면의 입력 정보 지우기’는 현재 금융 메모리만 비우므로 서버에 저장한 정보 삭제와 다릅니다. 기본 추천 프로필과 저장 공고의 삭제 동작도 별개입니다.

## 금융 계산과 추천의 경계

계산기는 `/v1/finance/calculate`에 원자료를 보내며 서버의 2026년 규칙과 공식 출처를 사용합니다. 기준 중위소득에 대한 월 소득의 단순 비율, 생계급여·차상위 확인사업의 기본 산식, 국민임대 일반 소득·자산 항목 비교를 구분합니다. 미입력·특례·가구 범위 등 불확실한 사항은 `unknown`/`needs_review`로 표시하며 최종 신청 자격으로 바꾸지 않습니다. 계산 API와 회원 저장은 실제 구현되어 있지만 실제 공고별 조건 추출·추천 서비스는 미구현입니다.

계산만 하거나 계정에 저장하는 동작은 금융정보를 추천 요청에 자동으로 포함하지 않습니다. 사용자가 계산 결과에서 ‘관련 공고 살펴보기’를 누른 뒤에만 후속 추천 요청의 선택 필드 `financialProfile`을 활성화합니다. 계산·회원 저장·불러오기로 상위 금융 메모리를 갱신하거나 삭제할 때, 로그인/로그아웃할 때 이 사용 상태를 해제합니다. 공고 demo에서는 금융정보를 전송하거나 금융 자격으로 예시 공고를 선별하지 않습니다. 계산기에서 홈으로 이동한 뒤에도 실제 금융 맞춤 추천은 준비 중이라는 토스트를 표시하도록 경로 전환 안내를 전달합니다. [추천 확장 계약](service-contract.md)은 서버 구현 전 제안이며 실제 금융 맞춤 추천이 제공된다고 표시하지 않습니다.

## 모바일 앱 경계

| 항목 | Android/iOS |
|---|---|
| UI/탐색 | 같은 정보 구조, 네이티브 탭·상세 스택 및 플랫폼 접근성 |
| API | 동일한 필터·cursor·추천 프로필·금융 원자료·오류 계약. 계산과 추천의 구현 상태 구분 |
| 순수 JS 모델 | 금융 모델·질문 정의는 `frontend/packages/core`에서 웹·앱 공유. 공고/프로필은 후속 |
| 환경 | 앱별 공개 HTTPS API 주소. localhost는 기기 자체임 |
| 저장 | 기본 프로필의 플랫폼 저장과 금융 프로필의 명시적 계정 저장 분리. 모바일의 메모리·보안 저장 방식은 별도 설계 |
| 쉬운 화면 | Dynamic Type/글꼴 배율·모션 감소·큰 터치 영역 반영 |
| 로그인/푸시 | 모바일 Bearer 세션·SecureStore 구현. 푸시는 권한·동의·토큰 계약 확정 후 구현 |

2026-10-01 사용자 요청으로 Android Java 별도 개발 계획을 React Native + Expo 공통 앱으로 변경했습니다. `frontend/mobile`에 로그인·계산·저장/조회/삭제를 구현하고 금융 순수 모델을 `frontend/packages/core`로 공유합니다. 모바일 Bearer 인증·SecureStore는 [앱 실행 안내](../mobile/readme.md)를 따릅니다. 위 표의 공고/추천·기본 프로필/공고 저장·푸시는 후속 목표입니다. 모바일 웹 검증은 실제 Safari·TalkBack·VoiceOver 테스트를 대신하지 않습니다. [쉬운 화면 기준](senior-mode.md).
