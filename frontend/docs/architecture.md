# 웹 구조와 Android/iOS 확장
기준: 2026-09-22. 담당: 프론트엔드. 네이티브 앱은 계획 단계입니다.

## 서비스 흐름
서버가 공고를 수집·검토해 공개 목록을 공급하고, 입력된 사용자 정보를 바탕으로 서버의 개인비서 LLM이 관련 공고와 설명을 추천합니다. 웹은 결과를 표시하며 LLM/DB/원천 수집 API에 직접 접근하지 않습니다. 추천은 지원 자격 확정과 다릅니다. 현재 서버에는 health만 있고 [업무 HTTP 계약은 제안](service-contract.md)입니다.

웹 화면: 내 비서 → 내 정보 → 추천 이유·공고 상세. 전체 공고·저장한 공고도 별도 제공합니다.
경로는 #home, #explore, #saved, #profile, #login, #signup. 태그는 #explore?tag=...에 보관하며 브라우저 뒤로 가기로 복원됩니다.

## 책임
- app/App.jsx: 라우팅·모드·프로필·추천 상태·로컬 저장 조립. 프로필 변경 시 이전 요청 취소 및 오래된 응답 무시.
- app/services.js: 공개 설정으로 API/demo repository 생성.
- features/assistant: 입력된 정보로 추천 요청, 서버 설명 표시. demo는 명시된 정렬 예시.
- features/policies: 페이지/필터 요청, 응답 모델 검증, 화면. 모든 카드/상세 태그가 검색으로 연결.
- features/profile: 선택값 검증·전송 필드 whitelist. DOM 없는 모델과 웹 폼 분리.
- shared/api: HTTP 상태·JSON·네트워크·시간 초과·취소 처리. 쿠키/토큰 아직 사용하지 않음.
- shared/config: 런타임 공개 설정과 빌드 설정 해석.
- shared/storage: 브라우저 저장 실패·손상 격리.
- auth: 입력폼만, 인증 상태/외부 호출 없음.

## 저장과 개인정보
| 키 | 내용 |
|---|---|
| bokji.easy.v1 | 쉬운 화면 boolean |
| bokji.profile.v2 | 선택해서 기억한 프로필만. 기본은 메모리 |
| bokji.saved.v2.demo / bokji.saved.v2.api | 모드별 공고 스냅샷 배열, 최대 500 |

예전 v1 예시 ID/관심 설정은 신규 개인정보 선택 동의와 분리해 자동 이관하지 않습니다. 기존 키는 사용하지 않습니다.
API 모드에서 추천받기를 누르거나 기억된 프로필로 앱을 다시 열면 서버 추천을 요청합니다. 브라우저에 기억된 정보는 평문 사이트 저장소이며 비밀/인증 보관소가 아닙니다. 선택 해제 후 저장 또는 내 정보 지우기로 제거합니다. 저장/삭제 실패는 화면에서 알립니다. 인증 폼 데이터는 앱이 보관하거나 전송하지 않습니다.

## 모바일 앱 경계
| 항목 | Android/iOS |
|---|---|
| UI/탐색 | 같은 정보 구조, 네이티브 탭·상세 스택 및 플랫폼 접근성 |
| API | 동일한 필터·cursor·추천 프로필·오류 계약 |
| 순수 JS 모델 | Java/Swift이면 동일 규칙 재구현. JS 런타임 선택 시 추후 공유 패키지 |
| 환경 | 앱별 공개 HTTPS API 주소. localhost는 기기 자체임 |
| 저장 | 플랫폼 저장 어댑터, 동의·삭제. 인증은 별도 보안 저장 설계 |
| 쉬운 화면 | Dynamic Type/글꼴 배율·모션 감소·큰 터치 영역 반영 |
| 로그인/푸시 | 서버 인증·권한·동의·토큰 계약 확정 후 구현 |

Android Java 계획을 유지하고 iOS 프레임워크나 React Native를 미리 강제하지 않습니다. 모바일 웹 검증은 실제 Safari·TalkBack·VoiceOver 테스트를 대신하지 않습니다. [쉬운 화면 기준](senior-mode.md).
