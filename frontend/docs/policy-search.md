# 공고 자동 검색

담당: 프론트엔드. 기준: 2026-10-07. 웹 전체 공고·캘린더와 모바일의 자연어 검색 UI,
공개 검색 메타데이터, 응답 검증을 관리합니다. 해석·후보 조회·순위는 서버 책임입니다.

## 사용자 동작

필요한 지원을 평소 말투로 입력하고 검색 버튼이나 Enter를 누릅니다. 기본은 자동으로 찾기이며
검색 범위를 먼저 고를 필요가 없습니다. 서버는 입력한 문장만 로컬에서 해석합니다.
브라우저·앱은 계정 주소, 저장된 금융 정보, 비공개 공고를 검색 요청에 추가하지 않습니다.

| 입력 예 | 화면에 표시하는 의미 |
| --- | --- |
| 광운대에서 올린 장학 공고 찾아줘 | 게시 기관과 장학 목적을 해석한 결과 |
| 광운대 재학생인데 등록금 도와주는거 | 대학생 대상 지원을 포함한 결과와 실제 원문 근거 |
| 광운대 | 결과를 먼저 표시하고 게시 기관·내용별 개수로 선택해서 좁히기 |
| 광운데 재학생인데 알바 말고 등록금 도와주는거 | 수정안과 제외 의도를 설명하고 원래 표현 검색을 선택할 수 있음 |

검색 해석과 수정안은 결과 위에 표시하고 원래 입력은 그대로 유지합니다. 기관명이 모호할 때의
범위별 개수는 겹칠 수 있습니다. 결과 카드의 `찾은 이유`와 `근거 보기`는 서버가 원문에서
확인한 문구입니다. 대학생 지원으로 함께 찾은 공고와 특정 학교 대상 공고의 이유를 구분하며,
검색 결과를 신청 자격 확정으로 표시하지 않습니다.

해석 아래의 기관·관련 지원 버튼은 자동 해석을 유지하며 관계별 결과를 좁힙니다. `우리대학`처럼
학교 이름이 본문에 직접 없지만 출처와 원문으로 확인한 결과도 관련 지원에 남습니다. 같은 버튼을
다시 누르거나 함께 찾은 공고를 누르면 해제합니다. 선택한 버튼은 눌린 상태로 표시합니다.

`검색 범위 직접 선택`은 접힌 선택 영역입니다. `자동으로 찾기`는 자연어 검색,
`게시 기관`과 `공고 내용`은 기존 문구 검색의 직접 지정입니다. 범위 변경은 이미 적용한
검색어를 사용하고 입력 중인 초안은 그대로 둡니다. 목록은 첫 페이지로 돌아가며 캘린더는
선택한 월·날짜를 유지합니다. 쉬운 화면 전환은 검색 조건을 보존하고 페이지 크기만 초기화합니다.
조건 지우기는 빈 검색어·자동 범위·자동 정렬을 복원합니다.

자동 정렬은 검색어가 없으면 출처 조회수 인기순, 자연어 검색이면 서버 관련도순입니다.
사용자가 선택한 관련도·인기·최근·이름순은 다음 검색에서도 유지합니다. 오타 수정안의
`원래 검색어로 찾기`는 같은 원문을 문구 검색하며 다음 검색 버튼은 자동 해석으로 돌아갑니다.

## 요청과 응답 계약

- 웹 `repository.list(filters,{cursor?,limit?,signal?})`와 모바일 `policyPath(filters)`는
  원래 검색 문장을 `q`로 전달합니다. 기본 `searchScope='all'`과 `searchMode='smart'`는
  생략하고, 직접 지정 범위는 `search_scope`, 원문 검색은 `search_mode=literal`로 전달합니다.
- 해석의 관계 버튼은 `searchRelation='publisher'|'related'`를 `search_relation`으로 전달하며
  기본 자동 범위·해석을 유지합니다. 새 검색·직접 범위 선택·원문 검색은 관계 선택을 해제합니다.
  쉬운 화면 전환과 페이지 이동은 관계를 보존합니다.
- 정렬이 `auto`일 때 검색어가 있으면 `sort`를 생략해 서버 기본을 따르고, 없으면
  `sort=popular`를 보냅니다. 명시한 `relevance|popular|recent|name`은 그대로 전달합니다.
- `repository.calendar(month,filters,{signal?})`는 같은 검색 계약을 월별 조회에 사용합니다.
- 선택 `search`는 `mode,summary,originalQuery,interpretedQuery,corrections,alternatives,warnings?`입니다.
  수정안은 `{from,to}`, 범위별 개수는 `{scope,label,count}`입니다.
- 선택 `policy.searchMatch`는 `{relations,reason,evidence}`입니다. 관계는
  `publisher|target|contextual|student_general|mention|benefit|literal`, 근거는 `{field,quote}`입니다.

`parseSearchMetadata`와 `parseSearchMatch`는 허용된 관계·범위·문자열 길이·개수를 검증하고
알 수 없는 내부 필드를 버립니다. 근거는 최대 3개·인용 250자입니다. 잘못된 선택 메타데이터는
숨기고 올바른 공고 목록은 계속 표시합니다. 모든 설명·인용은 React/RN 텍스트이며 HTML을 실행하지
않습니다. 근거 필드는 제목·게시 기관·본문·사업 목적·지원 대상·선정 기준·지원 내용과
공개 편집 요약·조건만 허용하며, 연락처 같은 다른 필드의 메타데이터는 숨깁니다.

기존 `filterPolicies`/`matchesPolicySearch`는 문구 검색 테스트 대역용입니다. 자연어 의도를
클라이언트에서 다시 해석하거나 현재 페이지를 재필터링하지 않습니다. 스마트 브라우저 테스트는
명시된 서버 응답 계약 대역을 사용하고 실제 해석 품질은 백엔드의 후보·순위 검증에서 확인합니다.

## 검증

웹 단위 테스트는 응답 메타데이터 보존·잘못된 선택 항목 숨김·근거 필수·정렬 기본·원문 검색
전송을 확인합니다. 모바일도 같은 계약 테스트와 타입·린트를 실행합니다.
`tests/e2e/smart-search.spec.js`는 평소 말투·오타·부정 요청 응답, 기관 선택 없이 검색,
전국 대학생 지원 이유, 근거 펼치기, 원문 검색 되돌림, 선택 범위·쉬운 화면·캘린더·320px 폭과
HTML 문자열을 실행하지 않는 것을 검증합니다. 기존 검색·자동 갱신·캘린더 회귀도 함께 확인합니다.

실행: 웹 `npm.cmd test`, `npm.cmd run build`, 모바일 `npm.cmd test`,
`npm.cmd run typecheck`, `npm.cmd run lint`. 브라우저는
`npm.cmd run test:e2e -- tests/e2e/smart-search.spec.js tests/e2e/policy-search.spec.js tests/e2e/policy-refresh.spec.js tests/e2e/calendar-search.spec.js tests/e2e/calendar.spec.js`.
테스트 산출물은 독립 tmp 경로·SQLite와 별도 localhost 포트에 저장합니다. 네이티브 기기나
VoiceOver/TalkBack 확인, APK 재빌드·배포는 이 소스 변경 검증에 포함하지 않습니다.

2026-10-07 최종 소스 검증: 웹 단위 89/89, 모바일 단위 91/91, 웹 production build,
모바일 typecheck·lint와 변경 파일 Prettier 검증을 통과했습니다. 목록·자동 갱신·캘린더·검색의
브라우저 시나리오 32개 중 첫 묶음 실행은 31개 통과·기존 모바일 캘린더 1개가 로딩 시간 초과였고,
