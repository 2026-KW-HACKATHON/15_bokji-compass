# 쉬운 화면 설계

설계 갱신: 2026-10-01. 아래에서 이번 개편의 구현·검증 범위와 과거 검증 결과를 구분합니다.

쉬운 화면은 읽기와 조작에 여유가 필요한 사용자가 직접 선택하는 화면입니다. 나이를 기준으로 자동 적용하지 않으며, 사용자를 낮춰 보는 표현이나 기능 제한을 전제로 하지 않습니다. 글자를 일괄 확대하는 대신 정보의 순서, 선택해야 할 횟수, 누르는 영역과 탐색 방식을 함께 개선합니다.

## 이번 화면의 설계 선택

다음 수치는 공식 자료의 일률적인 의무 수치가 아니라, 서비스의 정보량과 화면 구성을 고려한 프로젝트 선택입니다.

- 기본 화면의 루트 글자 크기는 16px, 쉬운 화면은 18px을 사용합니다. 기존 쉬운 화면의 20px 루트 크기를 조정하고, 제목·본문·보조 설명에 역할별 크기·두께·간격을 적용합니다. 본문 줄 간격은 1.5 이상으로 둡니다.
- 주요 입력·버튼은 최소 48px, 일부 입력은 최소 52px의 조작 영역을 확보하고 보조 컨트롤도 44px 이상의 접근 영역을 목표로 합니다. 줄 간격·내용·여백에 따라 실제 높이는 더 커질 수 있습니다. 화면에 보이는 버튼 수를 줄이는 것과 터치 영역 축소를 혼동하지 않습니다.
- 기본 화면과 쉬운 화면은 파랑 `#0068b7`, 본문색 `#17324d`, 배경색 `#f8fafc`를 포함한 공통 색상 토큰을 사용합니다. 쉬운 화면은 별도 팔레트를 정의하지 않고 기본 화면의 토큰과 상태 색상을 상속합니다. 모드 간 차이는 정보 배치, 글자 위계, 여백과 조작 흐름으로 표현합니다. 선택·오류·초점은 색상만으로 구분하지 않습니다.
- 과한 장식, 반복 제목, 여러 개의 채운 버튼을 줄입니다. 링크와 버튼의 구분, 현재 메뉴, 선택 상태는 분명하게 유지합니다.
- 쉬운 화면의 전환 애니메이션과 부드러운 스크롤은 사용하지 않습니다. 기본 화면의 `prefers-reduced-motion` 지원도 유지합니다.
- 이번 개편은 쉬운 화면에 집중합니다. 기본 화면의 기존 흐름과 인증 기능은 변경 대상이 아닙니다.

## 화면별 적용

### 홈과 공고 목록

- 중복되는 소개·안내를 하나의 짧은 설명으로 합치고 추천을 위한 주 행동 하나를 강조합니다.
- 쉬운 화면의 추천·검색·저장 목록은 한 열에 공고 세 개를 표시합니다. 한 공고씩 넘기던 방식은 폐지하여 불필요한 반복 조작을 줄입니다. 필요한 목록 페이지 이동은 유지하고 검색 결과가 한 페이지뿐이면 이전·다음 버튼을 표시하지 않습니다.
- 공고 하나의 주요 동작은 ‘자세히 보기’ 하나로 정리하고 저장 기능과 부가 태그는 상세 정보에서 제공합니다.
- 지원 대상, 지원 내용, 신청기한 등 판단에 필요한 핵심 정보는 목록에서도 읽을 수 있게 유지합니다. 미확인 정보는 확인된 사실처럼 표현하지 않습니다.
- 상세 정보의 중요 안내와 출처는 접근할 수 있게 유지하고, 장문 부가 설명만 의미 있는 제목 아래 묶습니다.

### 검색과 추천용 정보 입력

- 검색 조건은 익숙한 기본 선택 상자를 사용하며 추가 조건은 한 영역에 모아 접을 수 있게 합니다. 검색어와 현재 적용 조건은 파악할 수 있어야 합니다.
- 추천용 정보 입력은 거주 지역과 선택 정보를 하나의 폼 안에서 논리적으로 구분합니다. 항목마다 ‘다음’을 누르던 절차를 없애고, 선택 정보의 의미와 선택 여부는 명확하게 안내합니다.
- 모드 전환과 화면 이동 때문에 작성 중인 값이 사라지지 않도록 합니다. 정보 수집 목적·개인정보 관련 안내는 화면 정리를 이유로 제거하지 않습니다.

### 소득·재산 계산기

- 쉬운 화면에서는 가구 정보 한 화면, 가구원별 소득 각 한 화면, 재산 한 화면, 부채 한 화면으로 관련 질문을 묶습니다.
- 차량 보유 여부를 선택한 뒤 차량이 있으면 차량별 상세 정보를 한 화면씩 입력합니다. 필요한 조건별 질문과 입력 확인·수정 과정은 유지합니다.
- 금액의 상태는 ‘금액 입력·없음·모름’을 선택 상자로 구분합니다. 없음은 0, 모름은 미확인 값이며 서로 바꾸어 처리하지 않습니다.
- 금액은 만원 단위로 입력합니다. 예를 들어 보증금 500만 원은 `500`을 입력하고, 서버에는 기존과 같이 `5,000,000`원으로 전달합니다. 기존 저장값과 API의 원 단위 계약은 유지합니다.
- 결과의 주요 요약, 미확인 사항, 사업별 추가 확인 상태를 바로 표시합니다. 중위소득의 단순 비율과 사업별 소득인정액·최종 자격이 다르다는 안내를 유지합니다.
- 계산 근거와 공식 자료 등 부가 설명은 접을 수 있게 하되, 검증되지 않은 자격을 확정적으로 표현하지 않습니다. 실제 금융 맞춤 추천이 준비 중인 데모에서는 관련 안내를 유지합니다.
- 계정의 금융정보 저장·불러오기·삭제는 사용자 의사를 확인할 수 있는 기존 동작을 유지합니다. 삭제 확인과 개인정보 안내는 버튼 수를 줄이기 위해 생략하지 않습니다.

## 공통 동작과 화면 크기 대응

- 쉬운 화면 선택 수단과 현재 상태를 표시하고 선택은 브라우저에 저장합니다. 선택을 나이에 연결하지 않습니다.
- 같은 페이지에서 모드를 바꿔도 추천용 정보, 가입 정보, 금융 정보, 검색어와 검색 조건을 보존합니다. 이는 새로고침 후 모든 입력을 복원하는 기능이나 개인정보 자동 저장 동의를 의미하지 않습니다.
- 목록 크기가 달라지는 모드 전환에서는 첫 페이지로 이동하되 검색 조건을 유지합니다.
- 읽기 순서와 DOM 순서를 일치시키고, 키보드 초점·현재 위치·이전 화면 복귀를 명확하게 제공합니다. 상세창을 닫으면 적절한 원래 위치로 초점을 돌려줍니다.
- 1024px 이하에서는 기존 하단 탐색 메뉴를 사용하고, 본문이 메뉴에 가려지지 않도록 여백과 기기 안전 영역을 반영합니다.
- 쉬운 화면 목록은 한 열로 유지하고, 좁은 화면에서는 입력·단위·금액·출처 링크의 줄바꿈을 허용합니다. 큰 글자나 긴 문구 때문에 화면 가로 넘침이 생기지 않도록 확인합니다.
- 회원가입·로그인 기능과 기존 인증 상태를 보존합니다. 이번 작업은 인증 절차나 서버 보안 정책을 변경하지 않습니다.

## 이번 개편의 검증 상태

2026-10-01 현재 확인한 범위입니다. 앱 내 브라우저 직접 확인과 자동 테스트 실행을 구분하며, 전체 접근성 검증을 완료했다는 의미는 아닙니다.

- Node 단위 테스트 26개와 Vite 운영 빌드 통과. 이번 재설계에서 Playwright CLI E2E는 실행하지 않았으며 변경한 시나리오는 실행 통과 기록이 아닙니다.
- 앱 내 브라우저에서 추천용 정보를 한 폼으로 제출한 뒤 추천 공고 3개 표시 확인. 기본↔쉬운 화면 전환 시 서울·은퇴 후·건강·돌봄 관심 분야 체크박스 값 보존 확인. 기억하기 동의와 새로고침 후 정보 보존은 이번 직접 검증에 포함하지 않았습니다.
- 공고 목록 3개에서 다음 목록의 `4–6 / 6개`로 이동 확인. 건강·돌봄 필터 결과 1개와 모드 양방향 전환 시 조건 보존, 한 페이지 결과의 이전·다음 버튼 생략 확인. 상세의 대상·신청 기간, 저장 동작, Escape로 닫은 후 원래 버튼의 초점 복귀 확인.
- 계산기의 가구 정보 그룹 후반부 오류로 초점 이동, 0과 미확인 값 구분, `500` 입력의 모드 양방향 전환 보존 확인. 비회원 테스트 입력의 보증금 500만 원·근로소득 0·나머지 모름이 입력 확인 화면에서 5,000,000원·0·확인 필요로 구분된 뒤 실제 로컬 금융 API의 2026년 계산 결과를 수신했습니다. 모든 사업이 추가 확인 필요 상태로 표시됨을 확인했으며 산식 정확성의 새 평가나 회원 저장 DB 검증을 뜻하지 않습니다.
- 공고 목록은 320·768·1440px, 홈·추천용 정보 폼·계산기 그룹 입력은 320px에서 문서 가로 넘침 없음 확인. 320px에서 추천용 정보 선택 상자 높이 50px, 계산기 이동 버튼 높이 약 53.7px와 일반 문서 흐름 배치 확인. 이 결과를 모든 화면·입력 상태의 반응형 검증으로 확대 해석하지 않습니다.
- 실제 시연 서버의 8080 포트에서 새 홈 제목·18px 루트 크기와 주 행동 버튼 높이 약 53.7px 확인.
