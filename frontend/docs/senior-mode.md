# 쉬운 화면 설계

기준: 2026-09-25. 시니어 사용자를 포함해 큰 글씨와 단순한 안내가 필요한 사용자가 직접 선택하는 모드입니다. 나이로 자동 적용하지 않습니다.

참고:

- [W3C WAI: Older Users and Web Accessibility](https://www.w3.org/WAI/older-users/developing/): 글자 확대, 대비, 읽기 쉬운 간격, 명확한 탐색/폼, 움직임 제어.
- [Apple Assistive Access](https://support.apple.com/guide/assistive-access-iphone/welcome/ios): 핵심 기능 중심의 단순한 화면과 큰 컨트롤. 시니어 전용이라는 의미는 아님.
- [Nielsen Norman Group: Usability for Senior Citizens](https://www.nngroup.com/articles/usability-for-senior-citizens/): 고령 사용자 연구에서 발견된 가독성·조작·오류 대응의 어려움 참고.

## 적용

- 항상 보이는 쉬운 화면 스위치와 상태, 브라우저에 선택 저장.
- 기본 글자 20px, 주요 입력·버튼 56px 이상, 충분한 줄 간격, 고대비 초점 표시.
- 전환·애니메이션·부드러운 스크롤 없음. 일반 화면도 prefers-reduced-motion 존중.
- 추천용 정보 입력은 지역/연령 → 일·가구 → 관심 분야의 3단계. 선택사항은 건너뛸 수 있고 이전 단계로 복귀 가능.
- 회원가입은 계정 만들기 → 기본 정보 → 전화번호 인증의 3단계. 단계별 필수값을 확인하고 잘못된 항목을 안내. 비밀번호 보기/숨기기, 인증번호 입력으로 초점 이동, 인증 후 가입 버튼으로 초점 이동 제공.
- 소득·재산 계산기는 가구와 소득 → 재산과 부채 → 계산 결과의 3단계. 비회원도 계산 가능하며 회원가입을 선행 단계로 요구하지 않음. 가구원·차량별 입력을 구분하고 부가 소득·차량 제원·공제 도움말을 접어서 표시.
- 계산 결과의 요약과 사업별 추가 확인 상태를 먼저 표시하고, 쉬운 화면에서는 사업별 비교·계산 내역과 ‘계산 기준과 공식 자료 보기’의 부가 안내·출처를 접어서 표시. 중위소득 단순 비율이 사업별 소득인정액·최종 자격과 다르다는 안내는 요약 바로 아래에 표시.
- 금액은 원 단위로 안내하고 빈칸과 0을 다르게 처리. 모르는 항목을 자동으로 0으로 채우지 않으며 미확인 사항은 별도 확인 대상으로 표시. 계정 저장·불러오기·삭제는 각각 명시적인 버튼 제공. 회원 정보 삭제는 확인 영역에서 취소하거나 최종 삭제 버튼을 누르는 두 단계.
- 같은 페이지에서 쉬운 화면을 켜거나 꺼도 작성 중인 기본 추천 정보·가입 정보·금융 정보·검색어·검색 조건 유지. 단계 간 이동도 입력을 보존. 이 동작은 새로고침 후 입력을 복원하는 기능이나 자동 저장 동의가 아님.
- 추천/검색/저장 목록은 한 개씩. 선택지가 많은 검색 조건과 공고 세부정보는 접어서 표시.
- 화면 모드를 바꿔 검색 페이지 크기가 달라지면 목록의 첫 페이지부터 표시하되 검색 조건은 유지.
- 아이콘 단독 탐색 대신 텍스트 병기, 명확한 이전/다음·재시도·빈 상태.
- 읽기 순서와 실제 DOM 순서 일치, 단계 이동 시 제목 초점, 추천 이전/다음 이동 시 새 공고 제목 초점, dialog 초점 복귀.
- 불필요한 장식/과정 띠·반복 제목을 줄이고 큰 버튼으로 다음 행동 제시. 정보 미입력 홈은 입력 버튼 하나, 입력 완료한 쉬운 홈은 짧은 안내 다음에 추천 표시. 공고 제목·추천 이유·중요 안내는 생략하지 않음.
- 공고 demo에서 계산기 결과의 ‘관련 공고 살펴보기’를 누르면 홈 이동 후에도 실제 금융 맞춤 추천은 준비 중이라는 안내 토스트 표시. 화면 이동으로 이 안내가 사라지지 않도록 처리.

## 화면 크기 대응

- 가로 1024px 이하에서는 왼쪽 메뉴 대신 하단 탐색 메뉴를 사용하며, 본문이 하단 메뉴에 가려지지 않도록 여백과 기기 안전 영역을 반영.
- 기본 공고 목록은 카드 최소 폭 19rem을 기준으로 가용 폭에 맞춰 1~3열로 조절. 좁은 화면에서는 카드 폭이 화면을 넘지 않으며 쉬운 화면은 한 열·한 공고 표시.
- 홈의 문구·로고, 상단 계정 메뉴, 폼, 검색 조건, 페이지 이동 버튼은 화면 폭에 맞춰 재배치. 긴 문구와 큰 글씨를 위한 줄바꿈 허용.
- 가입 단계의 입력값과 검색 조건은 화면 폭·모드 변경 때문에 초기화하지 않음. 작은 화면에서도 로그인·회원가입과 쉬운 화면 전환에 접근 가능.
- 계산기의 숫자 입력, 단위, 결과 금액, 출처 링크는 좁은 화면에서 줄바꿈·한 열 배치를 사용. 작은 화면의 결과 금액·설명에 맞춰 고정 폭 표 대신 항목별 목록 사용.

## 검증 범위와 남은 검증

이번 변경의 확인 대상은 Chromium의 320px·모바일·태블릿·데스크톱 배치, 쉬운 화면, 키보드·dialog·단계 입력·한 개씩 표시입니다. 자동 회귀 시나리오는 [공고·프로필 E2E](../web/tests/e2e/app.spec.js)의 모드 전환 입력·검색 조건 보존, [인증 E2E](../web/tests/e2e/auth.spec.js)의 가입·로그인, [계산기 E2E](../web/tests/e2e/calculator.spec.js)의 비회원 계산·회원 저장·서버 실패 처리를 포함합니다. 시나리오 추가 자체는 실행 통과를 의미하지 않으며 실제 실행 결과는 작업 기록에 별도로 남깁니다.

2026-09-25 계산기 추가 전 기본 UI의 로컬 브라우저 확인:

- 기본/쉬운 공고 목록: 320·390·768·1024·1280·1920px에서 문서 가로 넘침 없음. 기본 1~3열, 쉬운 화면 1열 확인.
- 가입 폼: 320·390·768·1024·1440px에서 가로 넘침 없음. 기본 입력 16px·48px 이상, 쉬운 화면의 단계별 입력과 비밀번호 표시 전환 확인.
- 검색어와 추천 프로필의 모드 전환 보존, 공고 페이지 초기화, 추천 이동 시 제목 초점, 상세창 Escape 닫기 확인.
- 격리된 테스트 DB와 개발용 SMS로 회원가입·오인증·정상 인증·로그인 오류·로그인·새로고침 세션 유지·로그아웃 확인. 실제 문자 발송 테스트는 아님.
- 단위 테스트 12개 및 배포 빌드 통과. Playwright E2E 실행기는 이번 작업에서 실행하지 않았으며 위 흐름은 앱 내 브라우저에서 직접 확인.

계산기를 포함한 최종 통합 확인:

- Node 단위 테스트 22개, 운영 빌드, 포맷 검사 통과.
- 앱 내 브라우저 도구로 320·390·768·1440px 계산기 화면과 쉬운 모드 배치를 직접 확인. 실제 로컬 서버의 회원 금융정보 저장 후 재조회 성공을 확인.
- 소득 양수일 때만 세전·경비 기준 질문을 표시. 차량의 명의·등록 용도·실제 사용 목적을 분리하고 제원·보조금은 쉬운 화면에서 접음. 320px 차량 영역 시각 확인 및 390·768·1440px 넘침 검사, 모드 전환 시 새 입력값 유지 확인.
- Playwright CLI E2E 32개는 `--list`로 수집만 확인했으며 실행 통과가 아님. 위 화면·저장 확인은 앱 내 브라우저에서 직접 수행한 검증이며 전체 E2E 실행 결과와 구분.

실제 시니어 참여 사용성 검증, 200% 브라우저 확대, VoiceOver/TalkBack 및 실제 iOS/Android는 별도 검증이 필요합니다. WCAG 적합성 인증을 받은 상태로 표현하지 않습니다.
