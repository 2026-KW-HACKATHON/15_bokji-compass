# 공고 상세·캘린더 보완 (2026-10-08)

첨부 사례의 `3~4월` 신청 기간, 명확한 장애인 사업주 대상, 영문 원천 항목명과
캘린더 자동 갱신의 깜빡임을 수정한 작업 기록입니다.

- 캘린더 갱신 중 마지막 성공 화면을 유지하고 새 응답 완료 시 바꿉니다.
  월·필터 이동의 취소/늦은 응답 격리를 유지합니다.
- 마감된 날짜 공고는 원래 연도·월에서 조회할 수 있습니다. 사용자 정정에 따라
  `3~4월`은 3월 1일 접수 시작·4월 30일 접수 마감으로 변환합니다. 다른 월 범위도
  시작 월 1일·마지막 월의 마지막 날을 사용하며, 2월은 윤년을 반영합니다.
  연도가 없으면 캘린더 조회 연도를 사용하고 별도 참고 목록 없이 날짜 격자와 일별 목록에
  표시합니다. 명시된 연도는 그대로 사용합니다.
- 지원 대상 표시는 원문의 `eligibility`를 읽으며, 저장된 연령 이외 조건도 보완합니다.
  근거가 명확한 장애인기업·사업주 지원은 사업·창업 분야로 분류합니다.
- 원문 링크는 저장된 주소와 공급자 목록 주소를 우선 사용합니다. 없는 정부24·복지로
  주소는 공식 서비스 ID로 연결하고, 상세 상단에서 바로 열 수 있습니다.
- `laws`와 `support_type`을 각각 `근거 법령`, `지원 형태`로 표시합니다.
  나머지 표준 원천 필드 항목명과 새 UI 문구도 번역 사전에 추가합니다.

관련 구현: `frontend/web/src/features/calendar/`, `frontend/web/src/features/policies/`,
`backend/app/modules/storage/`, `backend/app/modules/normalization/source_urls.py`.
원문/DB를 수정하지 않고 공개 조회에서 기존 데이터를 보완합니다.

검증은 백엔드 날짜·분류·URL·공개 조회 회귀 테스트, 웹 단위 테스트 및 빌드,
데스크톱/모바일 캘린더·검색·원문 상세 E2E로 진행합니다. 운영 서버 반영이나
실제 공급자 전체 링크의 유효성 검증은 로컬 수정·합성 회귀 검증과 구분합니다.

검증 결과: 백엔드 공고 관련 회귀 252개 통과·실DB 검증 1개 생략,
추가 URL/처리 버전 관련 검증 22개 통과, 웹 단위 114개 통과,
PC·모바일 E2E 20개 통과, 최종 Vite 빌드 및 변경 Python Ruff 검사 통과.
E2E는 전용 로컬 포트 5198/8026에서 실행했습니다.

월 범위의 월초·월말 처리로 정정한 후 날짜·공개 조회·저장 투영 관련 백엔드 73개,
웹 전체 단위 테스트 115개, PC·모바일 E2E 20개가 통과했습니다.
최종 빌드, 변경 날짜 코드와 테스트의 Ruff 검사 및 diff 검사도 통과했습니다.
