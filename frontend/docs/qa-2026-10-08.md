# 2026-10-08 프로젝트 QA

상태: QA 완료. 발견한 UI 오류 3건과 모바일 설치 환경 문제를 수정했으며, 최초 브라우저 실패 21건·백엔드 실패 1건의 재검증이 모두 통과했다.

## 점검 범위

웹 데스크톱·모바일 브라우저, 일반·쉬운 화면, 다섯 언어, 회원가입·로그인·탈퇴, 추천·AI 상담·알림, 공고 검색·저장·상세·신청 안내·캘린더, 금융 계산, 관리자 권한, 운영 CSP를 점검했다. 백엔드 전체 pytest·Ruff·의존성 검사와 모바일 단위·타입·린트 검사도 실행했다.

## 확인한 문제와 수정

- P2: 쉬운 화면에서 일반 화면으로 전환할 때 새 메뉴가 정지한 포인터 아래에 나타나 자동으로 열리고 프로필 탭을 가렸다. `PortalNavigation`은 실제 pointermove에만 호버를 열고, 이미 클릭한 그룹의 열림 방식은 유지한다. 프로필 초안 유지 검사와 새 전환·버튼 닫기 회귀로 확인했다.
- P2: 320px 쉬운 화면에서 베트남어 전체 메뉴 버튼이 두 줄로 바뀌면 헤더와 메뉴 높이가 20px 늘었다. 360px 이하 버튼에 76px 최소 높이를 확보했다. 다섯 언어의 geometry 회귀로 확인한다.
- P3: 쉬운 고급검색 summary가 기존 list-item 규칙을 상속해 제목과 조건 문구 사이 gap이 적용되지 않았다. 최종 쉬운 스타일에서 flex를 명시하고 681px·320px의 실제 문구 간격을 검증했다.
- 모바일 설치 환경: `install-links=true`로 복사한 `@bokji/core`가 최신 소스와 달라 금융 이력 함수 3개의 타입 검사가 실패했다. 잠금 파일 기준 `npm ci`로 갱신하고 공유 core 일치 여부·단위·타입·린트를 재검증했다.
- 모바일 린트 범위: 생성된 네이티브 export 번들이 있는 `.cache/`와 Expo 생성 파일 `.expo/`를 제외했다. 소스·스크립트·검사 파일은 유지한다.
- QA 설정: CRLF 파일을 LF 기본값으로 검사해 245개 포맷 경고가 발생했다. `endOfLine: auto`로 저장소의 Windows/macOS 줄바꿈을 존중하고, 남은 실제 README 포맷 오류 세 개를 정리했다.
- 백엔드 검사 목록: liveness/readiness의 정확한 OpenAPI 경로 집합에 최근 `/v1/monitoring/candidates/feedback`·`/v1/monitoring/candidates/preparation`이 누락돼 있었다. 두 경로를 추가했고 집합의 정확한 일치 검사는 유지했다.
- 오래된 검사 절차: 다국어 AI 소개가 첫 번째 메뉴 그룹에 있다고 가정한 선택자를 AI 비서 그룹으로 수정했다. 공고 번역의 합성 원문에 현재 API 계약인 `applicationGuide`를 추가하고 신청 안내를 펼친 뒤 원래 신청 URL을 확인한다. 확인되지 않은 옛 `applicationUrl`을 실제 신청 주소로 승격하는 동작은 추가하지 않았다. 인증 검사는 요청을 시작하기 전에 응답 대기를 등록하고 API 성공/거절을 확인한 후 화면 상태를 검증한다. 탈퇴 검사는 실제 문서 재로딩 완료를 기다리며, 여러 화면 폭·계정·언어를 반복하는 헤더 검사는 충분한 전체 실행 시간을 할당한다.

## 증거와 한계

실패 context/trace 및 수정 회귀 JSON은 `tmp/qa-2026-10-08/`에 보관한다. `baseline-last-run.json`, `baseline-failures.json`, `final-regression-results.json`, `auth-translation-results.json`, `failure-resolution-summary.json`으로 최초 실패와 최종 통과를 대조할 수 있다. 백엔드는 `backend-baseline-summary.json`·`backend-recheck-summary.json`, 모바일은 `mobile-sequential.log`에 결과를 남겼다. 합성 공고·테스트 계정·격리 SQLite와 API 대역을 사용했다. 71개 조건부 제외에는 명시적 MySQL 실행 조건과 운영체제·도구 요구 조건이 포함된다. 실제 MySQL 운영 데이터, 외부 SMTP·카카오 인증·LLM 응답, iOS/Android 실기기의 동작은 이번 자동 검증으로 확정하지 않는다. 커밋·푸시와 별도 배포 명령은 실행하지 않았다. 초기 기본 빌드는 `frontend/web/dist`를 생성했다. 이 경로는 기존 Caddy 설정의 공개 경로이므로 배포 영향이 없다고 단정할 수 없다. 최종 수정 빌드는 QA 전용 경로에만 생성했다. 기존 500kB 번들 크기 권고는 성능 후속 항목으로 남긴다.
