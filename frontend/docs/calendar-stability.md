# 캘린더 조회 안정성과 월 단위 접수 기간

2026-10-08 사용자 제보에 따른 웹 캘린더 수정 기록입니다.

## 조회 중 화면 유지

`CalendarPage`는 조회 시작 시 마지막 성공 응답을 비우지 않습니다. 결과에 대응하는 월,
선택 날짜, 검색 해석과 날짜별/상시 목록을 유지하고 `role=status`와 `aria-busy`로 새
조회 진행을 알립니다. 성공 시 결과와 적용 조건, 선택 날짜를 함께 바꿉니다. 월 변경
대기 중에는 이전 월의 날짜 버튼에 `aria-disabled`를 제공하며 다음/이전 월 이동을
이어갈 수 있습니다. 실패해도 마지막 성공 결과와 행을 보존하고 재시도 안내를 표시합니다.
첫 조회가 실패하면 날짜 격자는 남아 있고 결과 패널은 오류를 안내합니다.

요청별 `AbortController`와 응답 처리의 취소 확인으로 늦은 월/조건 응답을 격리합니다.
`reconcileCalendarResult(previous, next)`는 모든 공고 데이터가 동일한 경우 객체를
재사용하므로 기존 번역 행이 새 한국어 원문과 번역 대기 상태로 돌아가지 않습니다.
수정된 내용·개정·검색 근거와 새 응답 메타데이터는 그대로 반영합니다.

## 지난 공고와 월 단위 일정

프론트엔드 일정 모델에는 오늘 이후로 제한하는 필터가 없습니다. 과거 월/날짜의
마감된 공고도 확인할 수 있고 날짜별 목록은 마감일이 지난 공고에 `접수 마감`을 표시합니다.

서버가 `scheduleStatus=dated`, `applicationPrecision=month`,
`applicationMonths=[3,4]`, `applicationYear=2026|null`로 제공하는 월 단위 일정은
첫 월 1일부터 마지막 월의 실제 말일까지 접수 기간으로 표시합니다. `3~4월`은
3월 1일 시작, 4월 30일 마감으로 달력에 표시하며 해당 기간 내 날짜별 목록에도
포함합니다. 연도가 명시된 공고는 그 연도가 우선이고 연도 미기재는 조회 연도로
날짜를 계산합니다. 월말은 실제 달력을 따르므로 윤년 2월은 29일로 처리합니다.
연말을 넘는 `11~2월`은 11·12월 조회 시 그해 11월부터 다음 해 2월,
1·2월 조회 시 지난해 11월부터 그해 2월로 이어집니다. 원문 신청기간도 유지합니다.

`createPolicyRepository().calendar()`는 월 단위 일정의 월 배열·연도·정밀도와 날짜가
모두 있는지 검증합니다. 올바르지 않은 응답을 정상 일정으로 표시하지 않습니다.
