# Android·iOS 앱 이식 기록

기준: 2026-10-01. 담당: 프론트엔드/모바일·인증 백엔드. 사용자 요청에 따라 기존 Android Java 계획을 Android·iOS 공통 React Native + Expo 개발로 변경했습니다.

## 이번 구현 범위

- `frontend/mobile`에 Expo SDK 57·React Native 0.86·TypeScript·Expo Router 프로젝트 생성.
- 홈·내 계정·단계별 소득/재산 계산·쉬운 화면, 명시적인 금융 저장/조회/삭제.
- 기기 SecureStore 세션 보관·앱 시작 시 조회·만료 처리·로그아웃 재시도.
- 웹과 앱이 같은 금융 입력 검증·질문 정의를 사용하도록 `frontend/packages/core` 분리. 기존 웹 import 경로 유지.
- `/v1/mobile/auth/login`, `/me`, `/logout` 추가. 기존 금융 API는 모바일 Bearer와 기존 웹 쿠키를 지원하고, 잘못된 Authorization이 있으면 쿠키로 우회하지 않음.
- 서명·클라우드 계정 없이 로컬에서 확인 가능한 빌드/테스트와 EAS 프로필 준비.

## 단계별 상태

| 단계 | 상태 | 완료/후속 기준 |
|---|---|---|
| 폴더·앱 골격 | 구현 | Expo 설정과 3개 탭, 실행 안내 |
| 인증·금융 API | 구현 | 서버 테스트·세션 상태 테스트·실제 API 브라우저 연결 검사 |
| 공통 금융 로직 | 구현 | 기존 웹 테스트·빌드 회귀 확인 |
| Android/iOS 실행 | 번들 검증, 기기 검증 대기 | 개발 빌드 설치 후 SecureStore·재시작·키보드·뒤로 가기·접근성 |
| 공고·추천·저장 공고·프로필·가입 | 후속 | 공개 서버 API 상태와 계약 확인 후 순차 이식 |
| 푸시·딥 링크·스토어 배포 | 후속 | 서버 토큰 계약·기기 권한·서명·소유 앱 식별자 확정 |

모바일 번들 생성은 APK/IPA 설치나 스토어 심사를 의미하지 않습니다. 브라우저 미리보기에서 토큰은 메모리에만 두므로 네이티브 보안 저장의 재실행 검증을 대신하지 않습니다. 현재 금융 초안은 로그인 상태 전환 시 모두 초기화됩니다. 비회원 초안을 로그인 후 유지하는 흐름은 후속 UX 작업입니다.

## 검증 기록

- 인증·금융 백엔드 회귀: 47개 통과. 격리 SQLite 사용, 기존 의존성 deprecation 경고 2건.
- 모바일 HTTP·세션·금융 입력 테스트: 14개 통과.
- 기존 웹 테스트: 26개 통과, Vite 운영 빌드 성공.
- 모바일 TypeScript·ESLint 통과. Expo Doctor 21/21 통과.
- Android·iOS Hermes 번들 생성 성공. 네이티브 OS에서 설치/실행은 아직 미검증.
- 격리 SQLite 실제 API + Edge 390px 미리보기에서 로그인→계산→동의 저장→화면 초기화→불러오기→삭제 취소/확정→로그아웃→금융 메모리 제거를 확인. 페이지 JavaScript 오류와 가로 넘침 없음. [작업 기록](worklog.md).
- npm audit moderate 13건 확인. Expo/Router의 전이 의존성 경고이며 SDK 강제 다운그레이드 없이 유지. 출시 전 수정 버전 점검 필요.
