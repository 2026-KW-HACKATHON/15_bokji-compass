# 로그인·회원가입 화면 개선

## 2026-10-08 개인정보 동의 팝업

- 가입 첫 화면의 긴 개인정보 전문을 없애고 필수 가입 동의, 선택 맞춤 안내, 설정된 경우 선택 외부 AI 동의를 짧은 행으로 표시합니다. 체크박스와 항목명/내용 보기 버튼을 분리해 읽기와 동의 선택을 구분합니다.
- 항목명이나 내용 보기를 누르면 `PrivacyNoticeDialog`에 전문 전체를 표시하며 선택한 항목부터 읽을 수 있습니다. 수집 항목·목적·보유기간·거부 영향·운영자·문의·AI 처리 정보·관련 법령의 기존 내용은 그대로 유지합니다.
- 팝업은 화면 높이 안에 맞추고 본문만 스크롤합니다. 제목·닫기·확인 버튼은 고정합니다. 키보드 초점은 native dialog 안에 머물고 닫기/Escape/바깥 클릭 후 열었던 버튼으로 돌아갑니다. 확인 버튼은 팝업만 닫으며 동의를 선택하지 않습니다.
- 로그인·가입 하단의 개인정보 재열람도 팝업으로 통일했습니다. 동의 단계의 제목·행·하단 링크 간격도 좁혔습니다. API, 안내 버전, 필수/선택 구분, 초기 미동의와 제출 계약은 변경하지 않았습니다.
- 신규 UI 문구는 기존 번역 사전에 영어·중국어·베트남어·일본어를 함께 추가했습니다. 전문의 서버 제공 운영 정보는 기존대로 표시합니다.
- 검증: 데스크톱·모바일의 개인정보/가입 브라우저 검사 20개와 번역 사전 검사 4개 통과. 필수 미동의 차단, 선택 거부 가입, 외부 AI 동의 버전, 일반·카카오 가입, 전문 재열람·스크롤·초점 복귀를 확인했습니다. 프로덕션 빌드 통과(기존 번들 크기 경고 유지).
- 1440px·390px·320px 및 모바일 영어 화면을 캡처했습니다. 세 동의 항목을 모두 표시해도 본문 전문은 숨겨져 있으며 팝업은 뷰포트 안에서 스크롤합니다. 페이지/팝업의 가로 넘침과 JavaScript 오류는 없었습니다. 캡처는 `output/design-review-2026-10-08/*-signup-compact.png`, `*-privacy-popup.png`에 저장했습니다.

## 이전 화면 개선 기록

2026-10-06. 첨부 화면과 [리디 로그인](https://ridibooks.com/account/login), [노벨피아 로그인](https://novelpia.com/home), [CSS 인증 화면 모음](https://inpa.tistory.com/entry/CSS-%F0%9F%92%8D-%EB%A1%9C%EA%B7%B8%EC%9D%B8-%ED%9A%8C%EC%9B%90%EA%B0%80%EC%9E%85-%ED%8E%98%EC%9D%B4%EC%A7%80-%EC%8A%A4%ED%83%80%EC%9D%BC-%F0%9F%96%8C%EF%B8%8F-%EB%AA%A8%EC%9D%8C)을 참고했습니다. 리디·노벨피아는 실제 브라우저 화면을 확인했습니다. 제공된 Figma 커뮤니티 목록은 웹 조회가 차단되어 개별 템플릿을 확인하지 못했습니다.

## 화면과 동작

- 일반 화면: 은은한 브랜드 색과 기존 나침반 로고, 입력 카드, 로그인/회원가입 메뉴. 작은 화면에서는 장식 영역을 생략합니다.
- 아이디로 로그인: 실제 펼침 버튼으로 변경했습니다. 클릭·Enter로 입력 폼을 열고 아이디에 초점을 옮깁니다. 접었다 펼쳐도 입력값을 유지합니다. 카카오 사용 불가 시 자동으로 펼칩니다.
- 쉬운 화면: 장식과 계정 메뉴·펼침 조작을 제거하고 아이디·비밀번호를 바로 보여줍니다. 큰 글씨·명시적 라벨·56px 입력칸/주요 버튼을 사용합니다. 카카오는 아래의 대안으로 표시합니다.
- 회원가입: 같은 레이아웃을 적용하고 기존 한 항목씩 입력·중복 확인·이전/다음·진행률·오류 초점 이동을 유지합니다. 카카오 가입 완료에도 적용합니다.
- 쉬운 가입 방법 선택은 아이디 가입을 먼저 표시하며 실제 DOM·키보드 탐색 순서도 일치합니다. 카카오 요청 중 화면 모드를 바꾸면 진행 요청을 취소하고 처리 중 상태를 해제해 아이디 입력을 계속할 수 있습니다.
- 로그인 오류를 입력칸과 연결하고 비밀번호 보기 버튼과 입력값 보존을 유지합니다. 준비 중인 카카오는 안내와 회색 비활성 버튼으로 구분합니다.
- 서버 API와 비밀번호·쿠키 저장 방식을 변경하지 않습니다. 지원하지 않는 로그인 제공자와 계정 찾기 기능은 추가하지 않았습니다.

## 검증

`npm run build`, 변경한 파일의 Prettier 검사, `tests/e2e/auth.spec.js`와 `tests/e2e/auth-design.spec.js`를 데스크톱·모바일로 실행합니다. 새 테스트는 펼침·키보드 선택·초점 이동·입력 보존·쉬운 화면 즉시 입력·입력 오류 연결·가입 단계 보존·320px 가로 넘침을 확인하며 화면 캡처를 저장합니다. 기존 테스트는 격리 SQLite 인증 API와 카카오 응답 대역을 사용합니다. 실제 카카오 인증 제공자는 호출하지 않습니다.

실행 결과: 최초 인증 테스트 40개 중 39개 통과. 모바일 전체 가입·로그인 테스트 1개는 30초 실행 제한을 초과했으며, 동시 실행 수를 줄이고 90초 제한으로 재실행한 관련 8개는 모두 통과했습니다(해당 모바일 테스트 13초). 카카오 요청 취소 검증을 추가한 최종 UI·카카오 관련 16개가 모두 통과했습니다. 최종 빌드·변경 파일 포맷·diff 공백 검사도 통과했습니다. 화면 캡처는 `tmp/auth-ui/`에 보관했습니다.
