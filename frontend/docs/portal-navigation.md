# 계층형 상단 메뉴

## 2026-10-08 모바일 햄버거 메뉴

1000px 이하에서는 일반·쉬운 화면 모두 모바일 전용 세로 메뉴를 사용합니다. 로그인·쉬운 화면을 같은 행에 두고 기존 가로 스크롤 탭은 숨깁니다. 이 변경은 아래 과거 기록의 모바일 가로 스크롤/열 배치 설명을 대체합니다. [현재 동작·검증 범위](mobile-header.md).

## 2026-10-08 세로 목록과 토스 참고 애니메이션

토스 공식 사이트의 서비스/비즈니스 메뉴 전환을 브라우저에서 확인했습니다. 하위 메뉴는 선택한 탭 아래에 왼쪽 정렬한 **세로 한 열**로 표시하며 마지막 탭은 오른쪽 경계 안으로 보정합니다. 모바일도 한 열을 유지합니다. 이 배치는 아래의 가로 카드·모바일 두 열 설명을 대체합니다.

패널은 CSS grid의 `0fr → 1fr` 전환으로 420ms 동안 펼치고 360ms 동안 접습니다. 제목 다음 링크가 65ms 간격으로 위에서 아래 순서로 나타나며 작은 이동·불투명도·흐림 해제를 결합했습니다. 다른 탭으로 옮기면 새 목록의 등장 효과를 다시 실행합니다. 기본 목록 최소 높이를 공유해 항목 수가 다른 탭 사이의 높이 변화를 줄였습니다. 펼침용 잘림 영역과 제한 높이 스크롤 영역을 분리해 애니메이션 도중 스크롤바가 잠깐 나타나지 않도록 했습니다.

닫는 순간 `inert`와 `aria-hidden`으로 링크 조작을 해제하고, 마지막 목록은 접힘 전환이 끝날 때까지 렌더링합니다. 키보드 초점이 있는 행은 즉시 선명하게 표시합니다. `prefers-reduced-motion: reduce`에서는 펼침·접힘·행 등장·화살표 전환을 모두 생략합니다. 기존 페이지 경로·터치·Escape·포커스 복귀 동작은 유지합니다.

검증: 메뉴 E2E 9개 통과·모바일 호버 1개 제외. 모션을 켠 PC 호버 전환과 동작 줄이기 상태의 키보드/터치·세로 행 정렬·320px/5개 언어/쉬운 화면을 확인했습니다. 스크롤 영역 보완 후 해당 PC/모바일 시나리오 5개도 재통과했습니다. 웹 단위 163개, 운영 빌드 및 변경 파일 포맷/공백 검사 통과. 실제 로컬 브라우저에서 펼침 중 행의 흐림 해제와 완성된 세로 배치를 확인했고, 캡처는 `tmp/navigation-vertical-final.png`에 보관했습니다.

## 2026-10-08 탭별 하위 메뉴와 안내 페이지 분리

- AI 비서 → **지속 복지 안내** (`#assistant-monitoring`): 생활정보·지속 안내 설정·지원 분야·후보 관리.
- 내 정보 → **신규공고 확인하기** (`#new-notices`): 새 안내·안 읽은 개수·개별/표시된 안내 읽음.
- 회원 정보(`#profile`) 본문에서는 두 영역을 제거했습니다. 페이지 간 이동과 새로고침에도 계정에 저장된 읽음·진행 상태를 다시 조회합니다. 비회원은 로그인 후 해당 페이지로 돌아갑니다.

디자인 참고: [토스](https://toss.im/)의 넓은 여백과 흰색 메뉴 패널, [카카오톡 소개](https://www.kakaocorp.com/page/service/service/KakaoTalk)의 선택 탭에 한정한 하위 메뉴. 실제 페이지를 브라우저에서 확인하고 기존 서비스의 파랑 계열 강조색·헤더 구조에 적용했습니다.

이전 전체 7열 메뉴 대신 호버한 상위 탭의 링크만 표시합니다. 화살표 버튼 클릭·키보드 Enter/Space·아래 방향키도 지원합니다. 링크로 이동하는 동안에는 메뉴를 유지하고 바깥 이동 시 짧은 지연 후 닫습니다. Escape·외부 클릭·포커스 이탈·페이지 이동 시 닫으며 닫기/Escape는 열기 버튼으로 초점을 복원합니다. 모바일 480px 이하는 한 열, 481~1000px은 두 열입니다. 쉬운 화면은 전체 메뉴에서 두 새 페이지를 제공하고 새 메뉴 문구는 5개 언어를 지원합니다.

이하 전체 열 표시와 정렬 설명은 이전 구현 기록입니다.

검증: 웹 단위 162개와 운영 빌드, 메뉴/지속 안내 브라우저 시나리오 29개 및 챗봇 연결 4개 통과. 모바일 호버 1개는 터치 버튼 시나리오로 대신합니다. 320px·쉬운 화면·5개 언어의 가로 넘침을 검사했습니다. 브라우저 데이터는 테스트 전용이며 실제 운영 배포는 포함하지 않습니다.

2026-10-08. 제공된 대학 사이트 사진의 보조 줄·브랜드와 주요 메뉴·전체 폭 하위 메뉴 구조를 복지나침반에 적용했습니다. 브랜드와 파란색 디자인은 기존 서비스를 따릅니다.

| 상위 메뉴 | 하위 메뉴 | 주소 |
| --- | --- | --- |
| AI 비서 | 서비스 소개 | `#assistant-intro` |
| AI 비서 | 내 복지 현황 | `#assistant-overview` |
| 홈 | 서비스 안내 | `#guide` |
| 내 정보 | 회원 정보 | `#profile` |
| 내 정보 | 계산기 | `#calculator` |

홈·전체 공고·공고 캘린더·저장한 공고는 주요 메뉴에서 직접 이동합니다. 기존 `#assistant` 주소는 첫 방문 소개와 이후 현황을 자동 선택하며 기존 공개 링크와 발표 QR의 `#guide` 주소를 유지합니다. 새 AI 서비스 소개의 본문은 기존 개발 중인 `AssistantPage`의 소개 화면을 공유하고, 이미 소개를 본 사용자도 `#assistant-intro`로 다시 열 수 있습니다. `#assistant-overview`는 소개 이력과 무관하게 현황을 엽니다.

`App`은 서비스 소개의 시작 버튼을 `#assistant-overview?setup=1`로 연결합니다. `initialProfileEntry`가 정보 등록 화면을 열며 소개와 현황 사이의 상담 초안은 App의 계정별 메모리로 복원됩니다. 프로필·대화·API 값을 새로 저장하거나 외부로 보내지 않습니다.

PC의 메뉴 링크는 hover·키보드 포커스로 펼칩니다. 화살표 버튼은 터치와 키보드로도 조작할 수 있습니다. Escape·닫기 버튼·외부 클릭·탭 이탈·페이지 이동으로 닫히며 Escape·닫기 후 조작 위치에 포커스를 돌려줍니다. 모바일은 두 열과 내부 스크롤을 사용합니다. 펼친 메뉴를 챗봇 아이콘보다 위에 두어 하단 링크와 닫기 버튼을 가리지 않습니다.

2026-10-08 정렬 개선: 일반 화면의 상위 메뉴와 하위 메뉴에 같은 7열을 적용했습니다. 하위 메뉴는 헤더의 로고 너비·열 간격·좌우 여백을 공유해 로고 오른쪽에서 시작하며, 제목과 링크를 해당 대카테고리의 가운데에 배치합니다. 1000px 이하에서는 글자가 좁은 열에 과도하게 줄바꿈되지 않도록 가로 스크롤 주 메뉴·2열 하위 메뉴로 전환합니다. 빌드를 통과했고, Edge에서 1024·1180·1527·1920px의 상·하위 열 중심 차이가 0px이며 페이지 가로 넘침이 없음을 확인했습니다.

메뉴 E2E는 PC·모바일 8개 시나리오를 확인했습니다. 최초 PC 2개는 첫 화면 로딩의 30초 제한을 초과했고, 60초 제한으로 재실행해 통과했습니다. 테스트 실행은 기존 결과 폴더와 Vite 임시 설정 파일의 접근 오류를 피하려고 별도 결과 폴더와 `--configLoader runner`를 사용했습니다.

구현과 함수 계약: [앱 조립](../web/src/app/readme.md). 검증은 `tests/e2e/portal-navigation.spec.js`의 그룹 연결·계산기 이동·키보드/터치·소개/현황 분리·대화 초안·5개 언어·320px 쉬운 화면을 사용합니다. 기존 안내·번역 메뉴·로그인 및 화면 크기별 회귀도 함께 확인합니다. 실제 운영 사이트 배포와 새 소개 내용의 별도 개발 검증은 해당 작업에서 관리합니다.
