# 정보가 부족할 때 이어가는 생활 상담

## 이번 구현

공통 챗봇의 ‘생활 상황으로 상담하고 싶어요’에서 공고를 고르기 전에도 질문할 수 있다.
선택한 공고의 ‘내 상황을 더해서 확인하기’도 같은 상담 화면으로 이어진다.
초기 질문으로 탐색 분야를 정한 다음 본인·타인·가정 상황을 확인하며, 질문 원문만으로
본인의 주택 소유·실업·재난 피해를 확정하지 않는다.

- 정보 부족 사유와 필요한 항목을 표시하고 ‘정보 추가하기’로 대화 안의 입력 영역에 초점을 옮긴다.
- 선택형 답변, ‘1920년 건축’ 같은 연도 입력, 피해 발생일, 모름/건너뛰기를 지원한다.
- 추가 답변 뒤 공고 조건을 다시 비교하고 후보·미확인 요건·공식 링크를 보여준다.
  건축 연도 한 항목으로 지급 가능성을 확정하지 않는다.
- 누수 질문은 생활 대응을 먼저 보여준 뒤 수리비 지원을 함께 찾을지 묻는다.
  생활 대응만 보고 끝낼 수 있다.
- 해당 대화에서 본인이 명시적으로 확인한 생활정보와 표시값을 따로 보여준다.
  사용자 확인·저장 활용 동의 뒤 서버가 해당 필드만 기존 프로필에 병합한다.
  저장하지 않아도 상담할 수 있고, 기존 지속 안내 켜짐/꺼짐 상태는 유지한다.

## 데이터와 요청 수명

`POST /v1/assistant/dialogue`는 최초 `{question, revision_id?}`, 후속
`{continuation, answer:{slot,value}}`를 받는다. 클라이언트가 회원 사실 객체를 만들어 전송하지 않는다.
서버가 반환한 입력 유형·선택지·질문·미확인 항목을 그대로 표시한다.
`POST /v1/assistant/dialogue/profile`는 `{continuation,consent:true,confirmed:true}`만 전달한다.
응답의 profile_draft 전체를 저장 API로 재전송하지 않으므로 오래된 다른 필드를 덮어쓰지 않는다.

질문·답변 원문은 새 서버 대화 이력이나 브라우저 영구 저장소에 보관하지 않는다.
서버의 구조화된 상담 정보는 최대 30분간 임시 사용한다. 웹 대화 화면은 닫기·계정 변경·
새 상담에서 초기화하며, 진행 요청을 취소하고 늦은 응답을 무시한다.
이 기능에서 외부 AI로 상담 정보를 새로 전송하지 않는다.
기존 공고 AI 질문과 브라우저 메모리 질문 내역의 계약은 유지한다.

## 고려했으나 후속인 내용

이전 질문을 최근 관심 분야로 활용하는 방향은 유효하지만, 질문을 검증된 사실로 승격하면
타인 이야기·가정·부정 표현이 잘못 저장될 수 있다. 계정별 질문 기억·관심 신호 장기 보관과
기기 간 대화 재열람은 별도 목적·보유기간·수정/삭제 화면을 설계할 후속 범위다.
현재 상담에서 직접 확인하고 저장한 생활정보는 이미 구현한 지속 복지 안내로 이어진다.

생활 상담의 초기 지원 분야는 주택 수리·누수·취업·재난이다. 일반 주제는 필요한 분야를
추가로 묻는다. 모든 생활 문제를 자유롭게 해결하는 범용 상담이나 모든 자격 기준의 자동
확정을 구현한 것은 아니다. 소득·세부 지역·예외 조건 등은 공고의 확인사항으로 남을 수 있다.

## 파일과 검증

- `frontend/web/src/features/assistant/GuidedConversation.jsx`: 질문·추가 정보·생활 대응·후보·저장 UI.
- `dialogueApi.js`: 회원 요청, 응답 검증, 동의 없는 저장 차단.
- `dialogueModel.js`: 확인한 정보 표시와 안전한 오류 안내.
- `guided-conversation.css`: 일반/쉬운 화면과 좁은 화면 배치.
- `tests/dialogue.test.js`, `tests/e2e/dialogue.spec.js`: 계약·미확인값·명시 저장·추가답변·누수·취소·만료.

실제 공고 내용을 임의 예시로 채우지 않으며 브라우저 검사의 합성 공고는 테스트 파일에만 둔다.
검증 결과는 프론트엔드 작업 기록에 기록한다.
