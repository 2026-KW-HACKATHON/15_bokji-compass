# 정보가 부족할 때 이어가는 생활 상담

## 설명용 사례를 고정 선택지로 사용한 문제 수정 (2026-10-08)

리모델링·누수·취업·재난은 상황에 맞춰 정보를 확인하고 지원을 안내해야 한다는 요구를
설명한 사례다. 이를 모든 사용자에게 같은 시작 질문과 분야별 카드로 노출한 것은 요구를
좁게 해석한 구현이었다. 고정 예시 질문·분야별 시작 카드·집수리 전용 placeholder를 제거했다.
새 상담은 빈 입력창에서 사용자가 자신의 상황을 직접 입력하는 방식으로 시작한다.
실제로 저장된 상황이나 확인 중인 공고에서 이어지는 상담 문맥은 유지한다.
언어 변경도 사용자가 입력한 원문과 진행 중 상담을 바꾸지 않는다.

## 독립 AI 복지비서 페이지 (2026-10-08)

`#assistant`는 정보를 입력하고 관련 지원·새 안내·추가 확인 사항·신청 진행을 확인하는
독립 페이지다. 상단 메뉴, 홈의 ‘AI 복지비서 열기’, 챗봇 메뉴에서 진입한다. 페이지에서는
저장된 생활정보와 실제 `/v1/monitoring` 응답을 사용한다. 홈에는 전체 관리 화면 대신
진입 버튼을 두고, 내 정보의 생활정보 관리 기능은 유지한다.

처음에는 ‘내 정보부터 간단히 알려주세요’ 카드와 ‘내 정보 입력하기’를 보여준다. 주 행동인
입력 버튼을 회원 나이·지역 요약보다 먼저 배치하며 빈 통계나 여러 관리 메뉴를 나열하지
않는다. 버튼을 누르면 한 페이지에서 기본 생활정보·관심 분야와 필요한 선택 상세 정보를
입력한다. 주거·최근 피해 항목은 펼침으로 제공하고 기존 값이 있으면 열린 상태로 보여준다.
저장 후에는 간결한 정보 요약과 ‘맞춤 지원 / 신청 현황 / 새 안내 / 내 정보’ 네 메뉴를
표시하며 부족한 조건은 별도 확인 버튼으로 이어진다.

입력 폼은 모르는 `null`과 명시적인 부정 `false`를 구분하며 선택한 항목으로 다른 사실을
추론하지 않는다. 전체 교체 저장에서 접힌 항목을 지우지 않도록 기존 snapshot의 모든
값을 보존한다. 저장 동의는 직접 선택하며 ‘새 공고도 계속 알려받기’는 별도 선택이다.
최초 안내는 꺼져 있고 수정할 때 기존 활성 상태를 유지한다. 이는 상담에서 확인한 필드만
부분 병합하는 아래 대화 저장 계약과 구분된다.

헤더의 ‘궁금한 점 물어보기’를 누르거나 챗봇의 ‘AI 복지비서에서 이어보기’로 상담을 넘긴
경우에만 대화 영역을 표시한다. 질문 시작 시 입력칸으로 포커스를 옮긴다. `#assistant`에서는
플로팅 챗봇 진입 아이콘을 숨기고 헤더 질문 버튼을 사용한다. 다른 페이지의 공통 챗봇은
짧은 질문과 공고 상담의 진입점으로 유지한다.

이어보기는 선택 공고·후속 질문·입력 중인 답변·확인한 사실을 유지한다. 같은 질문을 자동으로
재요청하지 않는다. 저장 동의 체크는 이동 후 다시 확인하며 대화 내용이나 continuation을
URL·localStorage·sessionStorage에 기록하지 않는다. 페이지의 상담은 같은 계정으로 사이트
안의 메뉴를 오갈 때 유지한다. 새로고침·로그아웃·계정 변경·새 상담에서 초기화한다.
생활정보 또는 회원 프로필을 수정하거나 생활정보를 삭제하면 이전 조건의 상담도 초기화한다.
상담 안에서 확인 필드를 부분 저장한 경우에는 현재 상담을 유지하며 지원 현황을 다시 읽는다.

기기 간 이어보기와 장기 대화 기억은 후속 범위다. 기존 서버의 30분 상담 만료는 페이지
이동으로 연장되지 않으며, 저장된 생활정보를 기반으로 한 지속 안내와 수명이 다르다.

## 이번 구현

공통 챗봇의 ‘생활 상황으로 상담하고 싶어요’에서 공고를 고르기 전에도 질문할 수 있다.
선택한 공고의 ‘내 상황을 더해서 확인하기’도 같은 상담 화면으로 이어진다.
초기 질문으로 탐색 분야를 정한 다음 본인·타인·가정 상황을 확인하며, 질문 원문만으로
본인의 주택 소유·실업·재난 피해를 확정하지 않는다.

- 정보 부족 사유와 필요한 항목을 표시하고 ‘정보 추가하기’로 대화 안의 입력 영역에 초점을 옮긴다.
- 선택형 답변, ‘1920년 건축’ 같은 연도 입력, 피해 발생일, 모름/건너뛰기를 지원한다.
- 추가 답변 뒤 공고 조건을 다시 비교하고 후보·미확인 요건·공식 링크를 보여준다.
  건축 연도 한 항목으로 지급 가능성을 확정하지 않는다.
- 누수 질문은 생활 대응을 먼저 보여준 뒤 수리비 지원을 함께 찾을지 묻는다.
  생활 대응만 보고 끝낼 수 있다.
- 해당 대화에서 본인이 명시적으로 확인한 생활정보와 표시값을 따로 보여준다.
  사용자 확인·저장 활용 동의 뒤 서버가 해당 필드만 기존 프로필에 병합한다.
  저장하지 않아도 상담할 수 있고, 기존 지속 안내 켜짐/꺼짐 상태는 유지한다.

## 데이터와 요청 수명

`POST /v1/assistant/dialogue`는 최초 `{question, revision_id?}`, 후속
`{continuation, answer:{slot,value}}`를 받는다. 클라이언트가 회원 사실 객체를 만들어 전송하지 않는다.
서버가 반환한 입력 유형·선택지·질문·미확인 항목을 그대로 표시한다.
`POST /v1/assistant/dialogue/profile`는 `{continuation,consent:true,confirmed:true}`만 전달한다.
응답의 profile_draft 전체를 저장 API로 재전송하지 않으므로 오래된 다른 필드를 덮어쓰지 않는다.

질문·답변 원문은 새 서버 대화 이력이나 브라우저 영구 저장소에 보관하지 않는다.
서버의 구조화된 상담 정보는 최대 30분간 임시 사용한다. 챗봇 상담은 이어보기 없이 창을 닫으면
초기화한다. 페이지에 넘긴 상담은 위 수명 규칙을 따른다. 화면을 떠나면 진행 요청을 취소하고
늦은 응답을 무시한다.
이 기능에서 외부 AI로 상담 정보를 새로 전송하지 않는다.
기존 공고 AI 질문과 브라우저 메모리 질문 내역의 계약은 유지한다.

## 고려했으나 후속인 내용

이전 질문을 최근 관심 분야로 활용하는 방향은 유효하지만, 질문을 검증된 사실로 승격하면
타인 이야기·가정·부정 표현이 잘못 저장될 수 있다. 계정별 질문 기억·관심 신호 장기 보관과
기기 간 대화 재열람은 별도 목적·보유기간·수정/삭제 화면을 설계할 후속 범위다.
현재 상담에서 직접 확인하고 저장한 생활정보는 이미 구현한 지속 복지 안내로 이어진다.

주택 수리·누수·취업·재난에는 기존의 구조화된 기본 질문을 사용한다. 그 밖의 질문은
네 분야 중 선택을 강제하지 않고 기존 공개공고 검색으로 관련 지원을 찾는다. 누구의
상황인지 확인한 뒤 알려진 정보로 조건을 비교하며, 결과가 없거나 요청이 불명확하면
핵심 내용을 자유롭게 보충하도록 묻는다. 선택 공고는 분야와 무관하게 비교한다.
검색 의도는 원문 질문 필드를 제외해 기존 임시 대화 수명 안에서 사용한다.

일반 생활 지식에 대한 범용 답변, 모든 공고 조건에 따른 동적 후속 질문 생성, 모든 자격
기준의 자동 확정은 구현 범위가 아니다. 소득·세부 지역·예외 조건 등은 공고의 확인사항으로
남을 수 있다. 일반 검색에서 언급한 내용을 새로운 프로필 사실이나 지속 안내 분야로
자동 저장하지 않는다.

## 2026-10-08 — 경제활동·가구 표현과 판단 기준 보완

경제활동 입력은 `취업·사업 → 임금근로자 / 자영업자 / 프리랜서`, `학생`,
`미취업 → 무직 / 취업 준비 중`, `기타`로 정리했다. 대분류는 입력을 돕는 화면 구성이고,
서버는 직접 선택한 세부 상태를 기존 `occupation` 필드에 저장한다. 대화에서도 항목명을
‘경제활동 상태’로 바꾸고 ‘직장인’ 저장값은 ‘임금근로자’로 표시한다.

‘은퇴 후’는 과거 경력과 현재 경제활동을 구분하지 못하므로 복지 안내에 반드시 필요한
현재 상태로 간주하지 않는다. 새 선택지에서는 제외하고 기존 서버 저장값은 보존한다.
편집 화면은 현재 경제활동 확인을 안내하며 은퇴를 무직으로 자동 변환하지 않는다.
‘1인 가구 / 가족 동거 가구’는 표시 라벨이며 기존 `혼자 살아요 / 가족과 살아요` 저장값은
호환성을 위해 유지한다. 이 선택만으로 공고 심사상의 가구원 수를 확정하지 않는다.

서버 계약에 `무직`, `프리랜서`를 추가했다. 직접 선택한 무직만 미취업 조건 비교에
사용하고 학생·취업 준비·프리랜서·은퇴 정보만으로 미취업이나 사업자 상태를 추정하지
않는다. 경제활동과 구직 여부는 독립 정보다. 취업 준비는 관련 공고를 탐색하는 관심
근거가 될 수 있지만 `job_seeking` 또는 취업 준비 조건의 참/거짓을 자동으로 채우지 않는다.
대화는 구직 여부를 별도로 질문하고 모르는 값은 `null`로 유지한다.

관련 백엔드 테스트 273개와 변경 파일 Ruff 검사를 통과했다. 신규·기존 경제활동값과
가구값 저장/재조회, 명시적 무직 조건 비교, 별도 구직 질문과 기존 은퇴 데이터 보존을
격리된 테스트 데이터로 검증했다. 실제 사용자 데이터 변경이나 운영 배포는 하지 않았다.
