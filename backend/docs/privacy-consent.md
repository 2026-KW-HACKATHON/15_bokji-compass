# 가입 동의와 외부 AI 개인정보 안내

2026-10-07. 회원가입은 서비스의 개인정보 수집·이용 안내 버전과 필수 동의를 확인합니다. 맞춤 회원정보와 외부 AI 질문 이용은 각각 선택 동의입니다. 회원가입이나 로그인만으로 외부 AI 질문에 동의한 것으로 처리하지 않습니다. 서버의 `auth_consents`에는 계정별 안내 버전, 수집·이용/회원정보/AI 선택, AI 안내 지문, 서버 접수 시각을 저장합니다.

## DB와 서버 적용

SQLite는 회원 API 첫 호출에서 새 동의 테이블과 선택 입력 스키마를 준비합니다. MySQL은 연결 가능한 상태에서 `backend` 폴더 기준 다음 명령으로 `auth_consents`와 선택 입력 스키마를 적용하고 서버를 다시 시작합니다. 이 명령은 회원 탈퇴를 실행하지 않으며 기존 계정의 동의를 만들어 내지 않습니다.

```powershell
.\.venv\Scripts\python.exe -m app.modules.auth init
```

2026-10-07 현재 프로젝트 서버의 설정된 MySQL(`127.0.0.1:3307`,
`bokji_compass_dev`)에 적용을 완료했습니다. `auth_consents`의 7개 열과
`auth_accounts`의 선택 입력 열을 확인했으며 기존 회원·세션·관리자 권한·카카오 연결·
금융정보의 내용과 행 수를 적용 전후 대조해 보존을 확인했습니다. 기존 계정의 동의는
추정해 생성하지 않았습니다. 웹을 다시 빌드하고 서버를 재시작한 뒤 공개 서비스의
`/api/health/ready` 정상 응답, 안내 버전 `2026-10-07.2`, 새 웹 빌드 반영을 확인했습니다.
다른 서버나 새 DB에는 위 초기화 절차를 별도로 실행해야 합니다.

별도 운영 서버도 코드·스키마를 함께 배포해야 합니다. 운영자와 문의 이메일은 `PRIVACY_OPERATOR_NAME`, `PRIVACY_CONTACT_EMAIL` 설정으로 관리합니다. 기본 문의 이메일은 `03xodbs@gmail.com`입니다.

## 보유기간과 회원 탈퇴

가입 안내 버전은 `2026-10-07.3`입니다. 선택 맞춤 정보에는 우편번호·기본 주소·상세 주소가 포함되며 회원 주소 입력과 계정 내 주소 관리에 사용합니다. 주소 검색은 사용자가 검색 버튼을 누를 때 카카오 우편번호 서비스를 불러옵니다. 정확한 주소는 AI 문맥에 자동 첨부하지 않고 기존 시·도만 사용합니다. 회원 탈퇴 또는 계정 삭제 요청 처리 시 개인정보를 지체 없이 삭제합니다. 탈퇴 후 6개월 등 별도 보관기간이나 복구용 보관을 두지 않습니다.

`POST /v1/auth/withdraw`는 로그인한 웹 회원만 호출할 수 있습니다. `X-Auth-Request: 1` 헤더와 `{ "confirmation": true, "notice_version": "2026-10-07.3" }`가 필요합니다. 확인 누락·거부·숫자/문자열 확인·지난 안내 버전·다른 계정 ID 등 계약 밖 필드는 422로 거부합니다. 서버가 현재 세션을 삭제 트랜잭션에서 다시 확인하고 자신의 계정 ID만 사용합니다.

회원 계정, 수집·이용 동의 기록, 저장한 금융정보, 알림 설정·모바일 푸시 기기, 관리자 권한, 카카오 연결·관련 가입 대기 닉네임, 웹·모바일·콘솔 전체 세션을 같은 트랜잭션으로 삭제합니다. 브라우저에 남은 가입 인증 증명도 해당 브라우저의 증명 토큰으로 폐기합니다. 삭제 중 실패하면 모두 롤백하며 성공 시 인증 쿠키를 지웁니다. 서버 데이터의 별도 탈퇴 보관본이나 복구용 토큰은 만들지 않습니다. 이미 탈퇴한 계정의 이전 로그인 결과로 새 세션을 발급할 수 없습니다.

운영자가 별도 추출한 DB 백업은 회원 삭제 요청을 반영한 뒤 복원해야 합니다. 기존 SQLite 이관 도구는 존재하지 않는 계정을 새로 가져오는 도구이므로 삭제 전 백업을 검토 없이 이관하면 탈퇴한 계정이 다시 만들어질 수 있습니다. 서비스가 백업 삭제를 자동 처리하거나 외부 AI 제공자에 전달한 질문의 삭제를 보장하지는 않습니다. 외부 제공자의 보유기간과 삭제 절차는 별도 AI 안내 설정·운영 계약에서 확인합니다.

## 현재 AI 데이터 흐름

`POST /v1/assistant/dialogue`의 생활 상황 상담은 외부 AI를 호출하지 않는 별도 경로입니다.
질문은 주제 선택에 사용하고 원문·전체 대화를 DB에 저장하지 않습니다. 본인/타인/가정,
질문 항목과 답으로 확인한 최소 구조화 사실은 계정별 임시 메모리에서만 사용하며 30분 후
만료합니다. 만료 상태는 접근 시 또는 30초 간격 정리에서 제거하며 서버 종료·회원 탈퇴·
지속 안내 정보 삭제 시에도 제거합니다. 화면의 새 상담·닫기와 서버 삭제는 서로 다릅니다.
`/dialogue/profile`에서 표시한 본인의 확인 정보에 별도로 동의해야 계정의 지속 안내
프로필에 저장됩니다. 타인·가정 정보는 저장할 수 없고 지속 안내를 자동으로 켜지 않습니다.
이 동의는 외부 AI 동의나 과거 질문 이력의 장기 저장 동의를 의미하지 않습니다.
[대화·저장 계약](assistant-dialogue.md).

`POST /v1/assistant/questions`는 로그인한 회원의 공고 개정 ID와 질문을 받습니다. 서버가 회원 DB의 지역과 나이를 10년 단위 연령대로 변환한 값을 추가합니다. 질문 내용, 지역, 연령대와 해당 공개 공고 원문을 설정된 Codex 모델에 보내 공고에 관한 설명을 생성합니다. 회원 ID·아이디·이름·이메일·전화번호·성별·저장한 금융 원입력은 모델 문맥에 자동 첨부하지 않습니다. 다만 자유 입력 질문은 그대로 전달되므로 사용자가 질문에 적은 개인정보도 모델 입력에 포함됩니다.

모델은 매 요청마다 새로운 문맥으로 실행되며 웹·셸·MCP 등 도구를 사용할 수 없습니다. 모델 답변의 공고 인용은 원문과 대조합니다. 신청 자격, 수급 여부를 확정하거나 실제 신청을 수행하지 않습니다. 질문 처리용 임시 작업파일은 요청 종료 시 지우고 서비스 DB에 질문·답변을 따로 저장하지 않습니다. 웹 챗봇 내역은 실행 중 메모리에 보관하며 계정 전환 시 초기화합니다. 이 동작과 CLI의 `--ephemeral` 옵션은 외부 제공자의 보관·학습 정책을 보장하지 않습니다.

`GET /v1/assistant/faqs`의 준비된 공고 안내는 외부 모델을 호출하지 않습니다. 맞춤 추천은 서버의 공고 조건 비교 로직을 사용하며 외부 AI 질문과 별개입니다. 금융 계산·저장·추천 사용은 기존 별도 선택으로 처리하고, 금융 원입력을 AI 질문에 자동 전송하지 않습니다.

## 외부 AI 안내 설정

외부 AI 질문은 기본적으로 비활성입니다. 실제 운영계약·제공자 정책을 확인해 아래 항목을 모두 설정해야 안내가 활성화됩니다. 제공자, 국가, 보관기간, 학습 사용 여부에 추정값을 넣지 않습니다.

| 환경설정 | 의미 | 기본값 |
|---|---|---|
| `PRIVACY_AI_ENABLED` | 확인된 외부 AI 서비스를 활성화할지 여부 | `false` |
| `PRIVACY_AI_PROVIDER` | 개인정보를 이전받는 실제 법인의 명칭 | 빈 값 |
| `PRIVACY_AI_CONTACT` | 이전받는 법인의 개인정보 관련 연락처 | 빈 값 |
| `PRIVACY_AI_COUNTRIES` | 실제 이전·처리·보관 국가 목록, JSON 배열 | `[]` |
| `PRIVACY_AI_RETENTION` | 제공자 측 개인정보 보유·이용 기간 | 빈 값 |
| `PRIVACY_AI_TRAINING` | 해당 운영계약과 계정 설정에 따른 학습 사용 여부와 거부 방법 | 빈 값 |

`get_ai_notice(settings)`는 위 내용과 전송 항목, 목적, 시기, 방법을 반환합니다. 전송 항목은 질문 내용·회원 지역·연령대, 목적은 복지 공고에 관한 AI 답변 제공, 시기는 AI 질문 제출 시, 방법은 암호화된 네트워크 통신입니다. 전체 안내 내용을 정렬된 JSON으로 구성한 SHA-256을 `notice_version`으로 반환합니다. 설정값이 바뀌면 기존 AI 동의 지문이 일치하지 않아 새 동의가 필요합니다.

가입에서 AI 선택 동의를 제출하면 `ai_notice_version`이 현재 안내 지문과 같아야 합니다. 외부 AI 질문 API는 회원 인증 후 필수 동의와 AI 선택 동의, AI 안내 지문을 확인합니다. 가입 안내 `.3`에서 추가한 주소는 AI 전송 항목을 바꾸지 않으므로 기존 `.2` 가입 동의도 호환하며 기록을 자동 변경하지 않습니다. 다른 가입 안내 버전이나 변경된 AI 안내 지문은 계속 거부합니다. 안내 준비 전에는 503, 유효한 동의가 없으면 403을 반환하고 추론 요청이나 질문 사용 횟수 제한을 실행하지 않습니다. 선택 동의를 거부한 회원도 외부 AI를 사용하지 않는 준비된 공고 안내를 이용할 수 있습니다. 모델 접근 키 설정만으로 이 개인정보 관문을 건너뛸 수 없습니다.

## 안내 문구와 법적 근거

가입 시 개인정보 처리 목적을 회원 관리와 맞춤 복지 안내로 설명하고, 외부 AI 질문은 별도 선택으로 분명하게 표시합니다. AI 질문 화면에도 다음 범위를 설명해야 합니다.

> AI에 직접 질문하면 작성한 질문, 회원정보의 지역·연령대, 선택한 공고 내용을 외부 AI 서비스에 보내 답변을 만듭니다. 주민등록번호, 연락처, 건강·장애 정보 등 민감한 내용은 질문에 입력하지 마세요. AI 답변은 참고용이며 신청 자격과 접수 여부는 담당 기관에서 확인해야 합니다.

외부 AI 제공자가 서비스의 업무 범위에서만 처리하는 수탁자라면 위탁계약, 위탁업무·수탁자 공개, 관리·감독이 필요합니다. 제공자가 별도 목적에 활용하는 구조는 제3자 제공 해당 여부를 확인해야 합니다. 본 기능의 선택 동의는 실제 위·수탁 계약을 대신하지 않습니다. [개인정보 보호법 제26조](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1020399009)

국외 이전은 제공뿐 아니라 처리위탁·보관도 포함합니다. 법에는 별도 국외이전 동의와 계약 이행에 필요한 처리위탁·보관에 대한 공개·통지 등 복수의 근거가 있으므로 모든 외부 AI 처리를 동일하게 분류하지 않습니다. 이 서비스는 외부 AI 기능에 별도 선택 동의와 안내 지문을 확인하며, 실제 법적 근거와 이전받는 자·국가·항목·시기·방법·목적·기간·거부방법 및 효과를 운영 처리방침에 명시해야 합니다. [제28조의8](https://law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1020398611)

건강·장애 등 민감정보를 의도적으로 수집·처리하려면 일반 개인정보와 구분한 동의 또는 법령상 근거가 필요합니다. 일반 가입 동의나 금융 저장 체크 하나를 민감정보 처리 동의로 확대 해석하지 않습니다. [제23조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1006185763)

개인정보위의 2026년 처리방침 지침은 생성형 AI의 사용 목적, 이용자 입력·결과물의 처리, 학습 활용 여부·거부절차, 민감정보 입력 주의와 신고·이의제기 경로를 알리도록 안내합니다. 처리방침에는 운영 중인 실제 정책만 기재합니다. [개인정보위 2026-04-24 안내](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&nttId=12021)

## 검증

`tests/test_withdrawal.py`는 로그인·명시적 확인·안내 버전 검사, 자신의 데이터만 즉시 삭제하는지, 다른 계정 보존, 모든 세션 폐기, 삭제 실패 시 전체 롤백을 확인합니다. `account_write_transaction`은 SQLite에서는 읽기 전에 쓰기 잠금을 확보하고 MySQL에서는 회원 행을 잠급니다. 금융 저장·알림 저장·기기 등록·세션 발급·회원별 요청 제한은 같은 회원 잠금을 사용하여 탈퇴 완료 후 진행 중이던 요청이 개인정보를 다시 저장하지 못하도록 검사합니다. `tests/test_withdrawal_write_guards.py`가 삭제와 저장의 동시 실행 순서를 검증합니다. 테스트는 격리된 임시 DB를 사용합니다.

`tests/test_ai_privacy.py`는 기본 비활성·안내 항목 누락·모든 주요 설정 변경에 따른 동의 지문 무효화를 검사합니다. `tests/test_policy_api.py`는 실제 격리 회원 DB로 동의 없음·거부·구버전·수탁자 변경·설정 준비 전에는 모델과 질문 사용 횟수 제한이 호출되지 않는지, 준비된 FAQ가 계속 이용 가능한지 확인합니다. 유효 동의가 있는 웹 쿠키·모바일 Bearer 회원의 최소 모델 문맥은 기존 검증을 유지합니다. 테스트의 제공자·국가·보관기간은 명시적인 테스트 값이며 운영 안내로 사용하지 않습니다.
