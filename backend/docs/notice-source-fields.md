# 공고 상세의 원천 JSON 표시 정제 (2026-10-08)

가사·간병 방문 지원사업의 근거 법령·문의처에서 복지로의 `servSeCode`,
`servSeDetailNm`, `servSeDetailLink`가 포함된 JSON 배열이 그대로 보이는 문제를 수정했습니다.
정규화 모듈은 반복 원천 항목을 근거 검증용 JSON 문자열로 보존하지만 공개 표시가
그 문자열을 바로 반환하던 것이 원인입니다.

- `presentation/source_fields.py`에서 원천 문자열의 완전한 JSON 객체·배열을 읽고
  법령명, `기관명: 전화번호`, `신청 단계: 안내`, `파일명: URL`, `링크명: URL`로 표시합니다.
- 복지로 공통 키와 법령/첨부/문의/신청의 별칭, 일반 `label/url` 구조,
  중첩 항목과 문자열 목록을 지원합니다. 이름과 안내가 같으면 한 번만 표시합니다.
  제공 순서와 URL의 쿼리 문자열·전화번호·수치를 유지하며 내부 코드·ID와 빈 항목을 제외합니다.
- `storage.catalog.card`의 상세 `sourceFields` 전체와 원천/개요의 표시 문구에 적용합니다.
  한 공고에만 제목 조건을 넣지 않아 같은 형식의 다른 공고와 향후 수집 자료에도 적용됩니다.
- 공개 API의 문자열 타입과 원천 항목 키는 유지합니다. 기존 웹·모바일 표시와 연동되며
  번역 서버는 정제된 표시 해시를 사용해 이전 원시 JSON의 캐시와 구분합니다.
- 저장된 원문·해시·개요·인용·자격 모델과 관리자 편집 원본은 변경하지 않습니다.
  신청 캘린더와 지급일 계산에는 기존 원천 필드를 사용하며 DB 갱신이나 LLM 호출은 없습니다.
- 일반 문장·대괄호 서식 제목은 그대로 통과합니다. 파싱에 실패한 문자열을 임의 추정하거나
  원문 일부를 삭제하지 않습니다. 첨부 파일과 관련 주소는 문자열로 제공하고 자동 실행하지 않습니다.

검증은 `tests/test_source_field_presentation.py`의 변환·원문 불변성·개요 대체·
번역 해시 검사와 기존 공고 회귀, `frontend/web/tests/e2e/policy-source-fields.spec.js`의
실제 서버 투영을 사용한 PC·모바일 일반/쉬운 상세 흐름으로 진행합니다.
실제 DB 전체 조회·운영 서버 반영 여부는 로컬 코드와 합성 검증 결과에서 구분합니다.

연결된 DB의 최신 공개 공고 562건을 SELECT로 점검한 결과 20건에서 구조화 문자열을
확인했습니다. 법령 20개, 문의처 20개, 신청 방법 20개, 첨부 파일 17개 총 77개 항목입니다.
각 공고를 수정된 `card(full=True)`에 통과시킨 후 JSON 객체·배열이 남은 항목은 0개입니다.
실제 신청 단계 이름 6종을 확인하고 이의 신청까지 한글 단계명으로 매핑했습니다.
이 점검은 저장·공개 상태를 변경하지 않았으며 실행 중인 운영 서버 반영은 포함하지 않습니다.

검증 결과: 백엔드 관련 회귀 331개 통과·3개 생략, 최종 이의 신청 단계 보완 뒤
표시/원문 보존 테스트 55개 재확인 통과. 웹 단위 전체·Vite 빌드·변경 Python Ruff 통과.
PC/모바일 상세 브라우저 6개 통과(각 정제 시나리오는 일반/쉬운 화면을 함께 검사).
최종 캡처에서 법령명·기관/전화번호·신청 단계가 줄별로 표시되고 320px에서 긴 URL이
줄바꿈되는 것을 확인했습니다. 테스트 서버는 전용 로컬 포트 5199/8027을 사용했습니다.
