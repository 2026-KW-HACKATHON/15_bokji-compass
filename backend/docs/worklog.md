# 작업 기록

## 2026-10-08 — 신청 경로와 준비 서류 지원

- 공개 카드·상세·추천·대화 후보에 원문 기반 `applicationGuide`를 추가했다. 실제 신청
  주소·신청/문의 전화·방문 안내와 서류를 제공한다. 유효한 인용도 신청 문맥을 검증하며
  홈페이지·공고·문의 주소, 팩스와 잘못된 번호를 신청 액션에서 제외한다.
- 신청서 양식 없음과 구비서류 없음을 구분하고 조건부·대체 문장을 보존한다. 원문의
  신청방법에 명시한 주소도 지원한다. 외부 조회·LLM 호출 없이 읽기 시 구성한다.
- 현재 추천의 서류 준비 체크를 계정에 저장·해제하는 인증 API를 추가했다. revision과
  요구 서류의 정확한 목록을 검증하고 원문이 바뀌면 과거 체크를 초기화한다. 신청 상태·
  자격·추천 제외 이유를 유지하고 지연 worker를 버전으로 차단한다. 기존 JSON 저장을
  활용해 테이블 변경은 없다. 서류 준비 변경은 실제 신청이나 파일 제출을 뜻하지 않는다.
- 관련 백엔드 테스트 437개, 변경 Python Ruff·diff 검사를 통과했다. 임시 SQLite에서
  소유권·세션·변경 원문·체크 복원·기존 추천과 대화를 검증했다. 운영 DB·외부 기관·
  서비스 프로세스는 변경하지 않았다.

## 2026-10-08 — 추천 제외 이유의 계정별 반영

- 추천받은 공고에 `not_eligible` / `not_interested` 이유를 저장·복원하는 인증 API를
  추가했다. 후보 JSON을 활용해 별도 테이블·운영 DB 변경 없이 계정에 영구 저장한다.
- 해당 공고는 다음 추천에서 제외한다. 관심 없음은 같은 분야·제목 단어 유사도를 이용해
  유사 공고의 순위를 낮추고 기존 관련도 순서를 같은 감점 안에서 유지한다. 홈·AI 대화의
  결과 제한 전에 반영해 다음 공고로 채운다. 자격이나 생활정보를 추정·변경하지 않는다.
- scan·공고 개정·다른 탐색 분야·프로필 수정에도 이유를 보존한다. 지연 worker를 버전으로
  차단하고 기존 신청 기록은 유지한다. 제외 공고의 미확인 알림을 읽음 처리하며 반복 알림을
  억제한다. 명시적 복원·안내 삭제·탈퇴에 맞춰 제외 설정을 해제한다.
- 관련 백엔드 295개 테스트가 통과했고, 실제 대화 검색·인증 API 검증을 포함한 추천 제외
  테스트 7개도 통과했다. 변경 Python의 Ruff 검사와 웹 빌드를 확인했다. 임시 SQLite·
  mock API만 사용했으며 실제 운영 DB나 서비스 프로세스를 변경하지 않았다.

## 2026-10-08 — AI 비서의 신청 확인사항 정제

- `matching.review_questions()`는 공고 원문에 있는 미확인 신청 대상·제외 조건을 안내한다.
  내부 추출 키, 우대·참고사항, 충족한 OR 분기의 다른 조건은 필수 확인으로 표시하지 않는다.
  긴 조건은 예외를 잘라내지 않고 공식 공고 확인으로 연결한다. 접수 예정은 비교에 사용한
  예정일 논리 상태를 전달해 신청 대상의 미확인 조건도 보존한다.
- 지속 안내와 일반 생활 상담이 같은 생성 함수를 사용한다. 생활정보 질문은 탐색 분야에
  유지하고 모든 공고 카드에 반복하지 않는다. 선택 공고의 미확인 내부 항목은 생활정보 입력
  요청으로 추가하지 않으며 원문 비교 근거와 자격 미확인 상태는 보존한다.
- 관련 서버 검사 289개 범위를 검증했다. 마지막 전체 실행은 288개 통과와 질문을 옮긴
  위치를 잘못 선택한 테스트 1개 실패였으며, 해당 테스트와 신규 안내·기존 청년 판단 검사
  14개를 수정 후 재실행해 통과했다. 변경 Python 파일의 Ruff와 차이 검사를 통과했다.
  격리 SQLite·원문 fixture를 사용했으며 실제 DB·AI 호출·운영 배포는 하지 않았다.

## 2026-10-07 — 사용자 상황 기반 지속 복지 안내

- 별도 동의한 생활·주거·구직·피해 정보를 계정에 저장하고 주거 개선·청년 일자리·취업·지역 재난 공고 확인·피해 복구 탐색 분야를 도출. 탐색용 연령·주택 연한을 실제 공고 자격으로 확정하지 않음. 피해 미입력 상태의 지역 재난 공고는 필수 양의 거주지역 조건과 실제 복구·구호 목적이 있을 때만 연결하고 개인 피해를 추정하지 않음.
- 최신 공개 공고 전체를 keyset 페이지로 조회. 불충족 제외, 미확인·접수 예정 유지, 원문 근거와 확인 질문 표시. 참고·우선순위 날짜와 실제 접수 기간을 구분하고 AND/OR 기간 분기를 보존.
- 지원 진행 상태·앱 안 알림 영속화, 의미 변경 fingerprint 중복 방지, 프로필 UUID·최신 회원 사실 비교로 중지/삭제/변경/탈퇴 이후 지연 결과 차단. 같은 공고의 상태를 탐색 분야 전체에서 공유하고 watch→recovery 전환 시 계승. 손상·조회 실패는 이전 성공 결과 보존.
- 웹/모바일 공통 인증의 `/v1/monitoring` API, no-store·POST 요청 가드·안전한 오류 처리 및 탈퇴 삭제 연결. 독립 `--init/--once/--watch` worker는 로그인 세션과 무관하게 전체 활성 계정 순회.
- 로컬 MySQL에 세 선택정보 테이블 초기화. 현재 회원 주소 코드에 필요한 nullable 열도 기존 회원 행을 보존하는 스키마 초기화로 준비. 실제 공개 DB에서 주거·청년 합성 입력의 후보 36건 조회(모두 추가 조건 확인 대상), 익명 요청 401과 API 등록·health 200 확인.
