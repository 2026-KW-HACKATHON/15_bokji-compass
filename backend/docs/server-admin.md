# 백엔드 서버 관리자 화면

2026-10-02 구현. 백엔드 주소의 `/`에서 관리자 로그인 화면을 제공합니다. 기존 최고 관리자
계정으로 로그인하면 서버 준비 상태, 수집 이력, 처리량과 모델·API·DB 설정을 관리합니다.
웹사이트의 일반 회원 화면과 별도로 백엔드가 HTML/CSS/JavaScript를 직접 제공합니다.

## 접속과 최초 계정 준비

일반 서버는 `http://127.0.0.1:8000/`, 기존 공유 서버는 `http://127.0.0.1:8001/`로 접속합니다.
실제 주소는 실행한 서버의 호스트·포트를 따릅니다. 공유 사이트의 공개 `/`는 기존 프론트이며
새 관리 화면은 백엔드 주소로 직접 접속합니다. 이 작업으로 터널·방화벽·바인딩을 변경하지
않습니다. 기존 `/docs`, `/health`, `/health/ready` 경로도 유지합니다.

인증 저장소에 `superadmin` 등급으로 등록된 기존 아이디·비밀번호를 사용합니다. 일반 회원과
`qr_admin`은 서버 설정에 접근할 수 없습니다. 일반 서버 8000과 공유 서버 8001은
서버 설정의 회원 저장소(SQLite 또는 MySQL)를 사용합니다. 기존 공유 SQLite 회원·관리자 권한은
서버 중지 후 [회원 저장 이관](member-privacy.md)에 따라 명시적으로 옮겨야 하며, 계정이
보이지 않는다고 같은 아이디로 새 계정을 만들지 않습니다. 회원 ID와 기존 관리자 등급을 보존합니다.

최고 관리자 계정이 없는 환경에서는 서버 PC에서 다음 명령을 실행합니다. 명령은 저장소 루트
기준이며 기존 계정의 비밀번호·등급을 덮어쓰지 않습니다.

```powershell
.\backend\.venv\Scripts\python.exe backend/scripts/setup-admin.py --username bokji_admin
```

출력된 로컬 설정 URL에서 비밀번호를 직접 입력합니다. 링크는 15분 동안 한 번만 사용할 수
있으며 비밀번호는 영문과 숫자를 포함해 12~128자로 지정합니다. 비밀번호를 명령행·문서에
넣지 않습니다. `--share` 옵션도 같은 서버 설정의 MySQL 저장소를 사용합니다.
초기화·인증 저장소 구분은 [관리자 권한 안내](../app/modules/admin/readme.md)를 참고합니다.
이번 구현에서는 실제 계정 생성·권한 변경을 실행하지 않았습니다.

## 화면에서 할 수 있는 작업

**수집 실행 → AI만 끝까지 분석 → 최초 일괄 분석 시작 · 한도 없음**은 최초 적재에
사용하는 실행 전용 모드입니다. 최대 16건·입력 100,000글자씩 묶고 개별 모델 요청에 최소
900초를 부여합니다. 긴 원문은 묶음을 줄여 처리하며 내용을 자르지 않습니다. 분석 완료
공고는 건너뛰고 대기열이 비면 종료합니다. 모델·추론·공개 설정은 저장된 값을 사용하며
평상시 자동 수집 설정과 `.env`는 변경하지 않습니다. 모든 공고를 단일 요청에 넣는 대신
큰 묶음을 반복해 처리합니다. 처리 속도는 원문 길이·모델 출력·검증 실패에 따라 달라집니다.

**AI 전체 분석 시작 · 기본 모드**는 이미 확보한
원문의 분석 대기열만 처리합니다. 공공 API·상세 수집·외부 검색은 실행하지 않습니다.
저장 설정에 따라 최소 4건씩(큰 원문은 한 건씩) 묶으며 서버의 모델·추론·공개 설정을 사용합니다.
앱의 회차 작업 수·모델 호출·토큰·총 실행시간·일일 모델 호출 한도를 적용하지 않습니다.
실제 사용량은 계속 집계하고 Codex 계정 자체의 제한과 개별 호출 타임아웃은 유지합니다.
**AI 분석 중지**는 현재 모델 요청의 결과를 저장한 뒤 남은 작업을 보류합니다.
연결·로그인·모델 접근 실패 시 전체 반복을 일시 정지하며 원문과 완료된 결과를 보존합니다.

서버 PC에서 `backend/.venv/Scripts/python.exe backend/scripts/analyze-all.py`로 명시적으로
실행할 수도 있습니다. 명령으로 실행한 작업 역시 관리 화면에서 진행 상황 확인·중지가
가능하며 API 서버를 재시작해도 별도 분석 프로세스는 이어집니다. 분석 작업은 MySQL의
수집 잠금을 사용해 다른 회차와 겹치지 않습니다. 미완료 작업은 재실행 시 이어집니다.
최초 일괄 모드는 위 명령에 `--mode bulk`를 추가합니다. 관리자 API는
`{"action":"analyze-all","analysis_mode":"bulk"}`를 받습니다. 생략 시 기본 모드입니다.
Codex 비대화형 실행·JSON 구조 출력은 [공식 OpenAI 문서](https://developers.openai.com/codex/noninteractive/)를
기준으로 유지하며 실제 모델 입력 한도·계정 사용 제한을 무제한으로 바꾸지는 않습니다.

**서버 개요**와 **데이터 수집 → 수집 현황** 상단에서 총 보유 공고, 원문 확보 공고,
분석 저장 공고, 공개 공고 수를 확인합니다. 수집 인덱스와 기존 분석 저장소의 공고 ID를
합쳐 총건수를 계산하며, 같은 공고의 재수집·변경 이력은 중복으로 세지 않습니다.
공개 공고는 실제 공개 목록과 같은 분석 개정 저장소를 기준으로 셉니다. 새로고침하면
DB의 현재 건수를 다시 조회하며, 저장소를 확인할 수 없으면 0 대신 `—`를 표시합니다.

2026-10-06: **수집 실행** 메뉴를 추가했습니다. 명령어를 입력하지 않고 DB 준비 확인,
원문 수집, 소량 AI 분석, 기존 공고 연결, Windows 자동 수집 등록·해제를 실행할 수 있습니다.
수동 작업은 백그라운드에서 처리하며 화면에 실행 상태와 HTTP·모델·토큰 사용량을 표시합니다.
같은 API 프로세스에서는 한 작업씩 실행하고 실제 수집은 기존 MySQL worker 잠금도 사용합니다.

1. **DB 준비 확인**으로 공고 DB와 수집 테이블을 확인합니다. API 키 등록 여부를 보여주지만
   실제 공급자 응답이나 Codex 로그인까지 검증하는 버튼은 아닙니다.
2. **원문 수집**을 선택해 소량 목록부터 확인합니다. 기본 한 번에 5개·수집 반복 1회·120초·데이터 요청 2회이며
   대기 작업·AI·외부 검색을 실행하지 않습니다.
   **한 번에 수집할 공고 수 × 수집 반복 횟수**로 목록 조회량의 상한을 표시합니다. 실제 수집량은
   남은 데이터·중복·요청 한도에 따라 달라집니다. 반복 횟수 0은 목록 수집을 건너뜁니다.
3. **소량 AI 분석**은 기본 2작업·AI 분석 최대 2회로 상세·분석 작업을 처리합니다. 상세 수집과
   AI 분석을 각각 1개 작업으로 세고, AI 사용 횟수는 추가 분석·대체 모델·외부 검색도 포함하므로
   작업 수와 AI 횟수가 분석 완료 공고 수를 의미하지는 않습니다. 외부 검색은 끄고
   완료하지 못한 분석은 다음 회차에서 이어갑니다. **직접 설정**은 저장된 서버 설정에서 시작하며
   검색 여부도 저장된 설정을 따릅니다. 수동 회차는 최대 600초입니다.
4. **자동 수집 등록**은 기존 Windows 작업 스크립트로 10분 간격의 실제 수집을 등록합니다.
   수동 폼의 숫자는 이번 실행만 적용되므로 반복 처리량은 **서버 설정**에서 저장해야 합니다.
   기존 작업을 덮어쓰지 않습니다. 작업이 있으면 해제 후 다시 등록합니다.

**기존 공고 전체 연결**은 작은 100건 단위로 끝까지 자동 반복하며 진행 건수를 표시합니다.
API·모델을 호출하지 않으며 기존 결과를 무조건 채택하지 않습니다. 중단 후 재실행하면 저장된
처리 위치에서 이어갑니다. 연결 후 새 분석이 대기열에 들어갈 수 있습니다.

**자동 수집 프리셋**에서 최초 대량 수집/평상시 지속 수집을 선택하고 **프리셋 적용·저장**을
누릅니다. 최초 모드는 원문·상세 확보 뒤 4건씩 AI 분석하며, 초기 대기 작업 처리 종료 후
평상시 예산으로 전환합니다. 일회 실행 폼에서도 두 모드를 선택할 수 있습니다.
API 일일 한도는 기존 값을 유지합니다. [예산·모델 선택·연구 근거](ingestion-tuning.md).

자동 등록은 기본 `backend/.env`와 동일한 서버 설정일 때만 허용합니다. 별도 `APP_CONFIG_FILE`
또는 편집 항목의 프로세스 환경변수가 있으면 예약 CLI와 API 설정이 달라질 수 있어 등록을
거절합니다. 일일 계정 한도와 실행 사용자의 Codex 로그인은 먼저 확인합니다. 로그인 유지·AC
전원·MySQL 실행이 필요하고 절전·로그아웃 중 지속 실행을 보장하지 않습니다. 자동 수집 해제는
진행 중인 회차를 강제 종료하지 않습니다. **새 공고 수집 회차 허용**을 끄면 이후 회차를 막습니다.

화면의 최근 작업은 현재 API 프로세스에서 버튼으로 실행한 기록입니다. 서버 재시작 뒤의
지속 이력·공고 변경·실패 목록은 **데이터 수집** 메뉴에 저장된 MySQL 기록으로 확인합니다.
정상 서버 종료는 진행 중인 수동 작업을 기다린 뒤 DB 연결을 닫습니다.

| 화면 | 표시·조작 |
| --- | --- |
| 서버 개요 | 가동 시간, 실행 환경·주소, 현재 DB의 연결 확인, 인증 저장소 종류, 여유 RAM·디스크, 수집 상태와 재시작 대기 설정 |
| 서버·프론트 제어 | 백엔드·프론트 개별 또는 전체 종료·재시작, 실행 상태와 재시작 후에도 남는 최근 결과 |
| 수집 실행 | 이번 회차의 처리량·시간·호출 한도, 원문·분석 실행, DB 준비 확인·기존 공고 연결, 자동 수집 등록·해제, 최근 수동 작업 결과 |
| 데이터 수집 | 작업 상태·실패 코드, 저장된 수집 위치, 공고 변경 항목·관측 시각, 외부 검색 후보·유사 제목 후보 |
| 서버 설정 | 회차·하루 호출 한도, 처리량·재시도·자원 하한, 재확인 주기, 외부 검색 도메인·검색어, 모델·추론 수준·timeout, API 키, 자동 공개 방식, DB 연결 설정 |

상태 새로고침은 로컬 자원과 저장된 기록을 읽고 DB에 `SELECT`만 실행합니다. 새 공고 수집,
모델 호출, 검색, 스케줄 등록을 시작하지 않습니다. 외부 후보 조회는 검토용이며 원문 수집
등록·실패 작업 재시도는 [수집 CLI 안내](server-ingestion.md)를 사용합니다.

## 설정 저장과 적용 시점

**서버·프론트 제어** 메뉴에서 백엔드와 프론트를 각각 또는 함께 종료·재시작합니다.
최고 관리자만 실행할 수 있으며 실행 전 영향 안내를 확인합니다. Windows의 프로젝트 실행
BAT로 시작한 서버를 지원합니다. `server.py --reload`나 별도 `uvicorn` 실행은 관리 대상으로
인식하지 못할 수 있으므로 일반 개발 BAT 또는 운영 BAT로 실행하세요.

개발 모드는 이 프로젝트의 `server.py`와 Vite를, 운영 모드는 공유 실행 기록의 백엔드·웹·QR을
제어합니다. MySQL·Cloudflare 터널·자동 수집 예약은 유지합니다. 운영 프론트 재시작은 현재
빌드를 그대로 제공하므로 코드 변경을 반영할 때는 먼저 프론트를 빌드합니다.
콘솔에서 시작한 수집 작업이 진행 중이면 백엔드 종료·재시작을 거절합니다.

백엔드 재시작은 별도 숨김 관리 프로세스가 이어서 처리하며 화면은 연결 복구를 기다립니다.
백엔드 종료 후에는 이 화면으로 다시 켤 수 없습니다. 서버 PC에서
`start-server-dev.bat` 또는 `start-server-prod.bat`로 시작합니다. 작업 결과는
`backend/data/server-control/`에 저장되어 다음 실행에서도 확인할 수 있습니다.
실행 실패 시 같은 폴더의 해당 작업 stdout/stderr 로그와 포트 사용 여부를 확인합니다.

변경한 항목만 저장합니다. API 키·DB 비밀번호는 기존 값을 표시하지 않고 **등록 여부**만
표시합니다. 빈 입력칸은 기존 값을 유지하며 교체할 때만 새 값을 입력합니다. 기존 값을
지우려면 별도의 **저장된 값 삭제**를 선택합니다. API 요청에서 비밀값을 명시적으로 빈 문자열로
보내는 경우는 삭제로 처리합니다. `null`은 허용하지 않습니다.

| 설정 | 적용 시점 |
| --- | --- |
| 수집 허용·처리량·예산·재시도·자원 기준·검색 | 다음 CLI worker 실행부터 `.env`를 새로 읽어 적용 |
| 모델·추론 수준·timeout·최대 입력 글자 수·API 키 | 새 작업부터 적용. 이미 진행 중인 모델·HTTP 요청은 강제 종료하지 않음 |
| `POLICY_AUTO_PUBLISH` | 이후 저장할 공고의 공개 방식. 기존 공고의 공개·비공개 상태를 일괄 변경하지 않음 |
| DB 사용 여부·주소·포트·DB명·사용자·비밀번호·CA 경로 | 파일에 저장하고 **서버 재시작 후 적용**. 현재 API·인증의 DB 연결은 유지 |

`INGESTION_ENABLED=true`가 기본입니다. **새 공고 수집 회차 허용**을 끄면 이후 `tick --live`도
`disabled/collection_disabled`로 종료합니다. 진행 중인 worker는 이번 회차를 계속 처리할 수
있습니다. 이 스위치를 켜는 것만으로 수집·스케줄을 실행하지 않으며 CLI의 `--live`와 별도로
준비한 스케줄이 필요합니다. Windows 작업 등록·해제는 기존
`backend/scripts/ingestion-schedule.ps1`로 수행합니다.

DB 변경 후 서버 개요의 DB 상태는 **현재 실행 중인 연결**에 대한 결과입니다. 저장된 새 주소의
접속 검증 결과로 해석하지 않습니다. DB 설정 저장은 MySQL 시작·스키마 초기화·재시작을
수행하지 않습니다. 스케줄 CLI는 API와 별도 프로세스이므로 DB 설정을 저장하면 다음 worker는
새 값을 읽습니다. DB를 변경할 때는 수집을 먼저 끄고 설정 저장·API 재시작·DB 확인 뒤 다시
켜는 순서로 진행합니다.

모델·추론 설정을 바꾸면 처리 signature도 바뀝니다. 이전 버전으로 대기 중인 추출 작업은
`processing_version_changed`로 분리될 수 있으므로 수집 현황의 실패 코드와
[signature·재개 계약](server-ingestion.md#중복-방지변경중단-복구)을 함께 확인합니다.

환경변수로 이미 지정된 설정은 읽기 전용으로 표시합니다. 프로세스 환경변수가 `.env`보다
우선하므로 해당 값은 서버의 실행 환경에서 수정해야 합니다. 페이지 크기·대기열·호출 한도는
서버 범위와 함께 검증하며 대기열은 한 페이지 이상을 수용해야 합니다. 검색 도메인은 검토한
공식 기관의 정확한 호스트명만 입력합니다. URL·IP·localhost·와일드카드는 거절합니다.

설정 파일은 기본 `backend/.env`입니다. `APP_CONFIG_FILE`을 지정한 서버는 그 파일을 사용하며
상대 경로는 `backend` 기준입니다. 브라우저에서 경로를 지정하거나 변경할 수 없습니다.
로그인 설정·CORS·HTTP 서버 포트·Codex 실행파일·임의 SQL·프로세스 실행은 관리 항목에 포함하지
않습니다. 기존 환경 파일의 다른 항목·주석은 보존합니다.

다른 관리자나 도구가 먼저 파일을 바꾸면 버전 확인에서 409로 거절합니다. **최신 설정 불러오기**
후 변경을 다시 적용합니다. 파일 잠금과 임시 파일의 동기화·원자적 교체로 관리자 간 저장
충돌과 중간 내용 노출을 줄입니다. 노트북 시연에서는 기존처럼 한 API 프로세스로 실행합니다.

## 인증과 HTTP 계약

전용 `bokji_server_admin` 쿠키는 HttpOnly, SameSite=Strict이며 최대 7일 유효합니다.
production 환경에서는 Secure를 사용하므로 HTTPS로 접속해야 합니다. 매 상태·설정 요청에서
현재 세션과 `superadmin` 권한을 다시 조회하므로 권한 회수·만료·로그아웃이 반영됩니다.
일반 웹 세션 쿠키를 보내는 것만으로 콘솔 인증을 대신할 수 없습니다.

POST/PATCH는 JSON, `X-Auth-Request: 1`과 같은 출처 요청을 요구합니다. 브라우저의 다른 출처
요청은 거절하며 일반 본문은 최대 64KB, 공고 편집 PATCH는 1MiB입니다. 화면·API는 no-store, 프레임 삽입 금지와 같은 출처
스크립트·스타일·연결 정책을 적용합니다. 비밀번호·키와 원래 검증 입력값을 오류에 되돌려주지
않습니다. [전체 API 계약](../../api-management.md), [모듈 함수 계약](../app/modules/server_admin/readme.md).

```powershell
.\.venv\Scripts\python.exe -m pytest -p no:cacheprovider tests/test_server_admin.py tests/test_server_settings.py tests/test_ingestion_disabled.py
```

임시 인증 SQLite와 합성 환경 파일로 로그인·등급·권한 회수, 다른 출처 요청, 비밀값 비노출,
입력 검증, DB 설정 적용 대기, 동시 저장 충돌·저장 실패 복구를 확인합니다. 실제 `.env`·계정·
공고 MySQL·공급자 API·모델·Windows 작업 등록은 이 테스트의 실행 대상이 아닙니다.

## 공고 내용 수정

로그인 후 왼쪽 **공고 DB 편집**에서 공고를 검색하고 선택합니다. 기본 정보의 분야 분류,
공개 여부와 요약·지원 내용·대상·신청 안내를 수정할 수 있습니다. **공고 원문 전체**를
펼치면 수집된 모든 항목을, **조건·상태 코드 편집**에서는 조건 JSON과 표준화 결과를 봅니다.
JSON 직접 편집을 선택하면 조건 코드·근거를 검증합니다. 원문 변경으로 기존 근거가 유효하지
않으면 규칙으로 재구성하고 미확정 조건을 보존합니다.

수정 사유를 입력하고 저장합니다. 공개 공고는 새 개정으로 교체되어 프론트의 새 요청에
즉시 반영됩니다. 열린 웹의 목록·캘린더·상세는 복귀/포커스와 활성 상태 30초 간격으로 갱신합니다.
비공개 저장 시 기존 공개 개정도 비공개 처리됩니다. 이전 개정은 이력에 남고 AI 자동 분석이
관리자 수정 내용을 덮어쓰지 않습니다. 최고 관리자 전용이며 QR 계정은 사용할 수 없습니다.
