# 2026-10-06 최신 main 통합·보안 점검

통합 기준은 `origin/main`의 `076a0bf`와 로컬 보안 수정 `3451f4b`다.
node-forge 보완은 먼저 `codex/fix-node-forge-cve-2026-85393` 브랜치에
`fix(security): node-forge CVE-2026-85393 취약점 수정`으로 커밋·푸시했다.
그다음 main의 카카오 간편 가입, 선택 회원정보, 금융 계산 UI, 공고 메타데이터와
기존 로컬 관리자·수집·알림·웹·모바일 기능을 통합했다.

## 최신 별도 브랜치 확인

`origin/bonggyu`의 `16b0337`은 main 이후의 별도 6개 커밋이다. 읽기 전용 코드 검토와
메모리 재현으로 다음 문제·동작을 확인했으므로 이번 main 통합에는 포함하지 않았다.

- SQL의 시각·offset 기반 페이지와 Python의 날짜·ID 재정렬 순서가 달라 같은 날의
  공고를 페이지 크기 1로 조회할 때 같은 ID가 반복되고 다른 공고가 누락된다.
- 부산 지역 검색어 확장이 일반 `강서구` 등을 사용해 서울 강서구 공고도 부산에 포함한다.
- 최신 저장 변경은 과거 개정·조건·공개 감사 이력을 삭제하는 동작도 포함한다.

이 브랜치를 이후 병합할 때는 페이지·지역 회귀를 수정하고 이력 삭제 범위를 검토해야 한다.
009 번호는 해당 브랜치의 `009_raw_documents.sql`과 충돌하지 않도록 이번에 사용하지 않았다.

## 유지된 경계와 남은 제한

최신 main은 회원·금융정보의 애플리케이션 수준 DB 암호화를 제거하고 명시적 초기화에서
이전 암호화 데이터를 평문으로 복원하도록 변경했다. 사용자 요청에 따라 이 저장 정책을
포함한 최신 main을 통합했다. 따라서 DB·백업 접근 시 개인정보를 읽을 수 있는 위험이
남으며, 이전 10월 2일 보고서의 암호화 저장 설명은 현재 동작을 설명하지 않는다.
실제 운영 DB 복원·환경 파일 변경·서비스 재시작은 수행하지 않았다.

`DB_ENABLED=false`이면 환경 종류와 관계없이 설정한 SQLite 회원 저장소를 사용하는 것도
최신 main의 명시적 계약이다. MySQL을 사용하도록 설정한 경우의 연결 실패는 503으로
응답하며 SQLite 계정을 새로 만들지 않는다. 이 경계는 개발·운영 모드 모두 회귀 검사한다.
카카오 가입 취소 API도 OpenAPI 계약 검사에 반영했다.

서비스 배포 전에는 [공고 저장 초기화 절차](../database/readme.md)에 따라 008·010을
명시적으로 적용해야 한다. 기존 004~007만 있는 DB에서 새 저장소를 바로 시작하면 필수
호환 테이블이 없어 실패한다. 이번 적용·검증은 격리된 `bokji_compass_test`에서만 수행했다.

웹·모바일·서버 콘솔 세션 구분, 현재 관리자 권한 재검사, 카카오 상태값과 브라우저 바인딩,
회원 재이관 시 철회 데이터 보존, 민감한 POST 리다이렉트 차단, 수집 URL의 사설망·응답 크기
제한은 유지한다. 카카오 공급자는 합성 응답으로 검증하며 실제 동의 화면 성공을 보장하지 않는다.

모바일의 node-forge는 [프로젝트 보완과 설치·검증 절차](../../frontend/docs/node-forge-security-fix.md)를
따른다. 공식 릴리스 대신 설치 파일의 제한된 검증 로직을 보완했으며, 버전 기반 npm audit에는
경고가 남는다. 별도 `braces@3.0.3` 공지도 남아 있으므로 모든 취약점이 0건이라고 보지 않는다.

검사 원본은 추적 제외된 `tmp/node-forge-security-validation/`,
`tmp/main-integration-validation/`, `tmp/main-integration-076a0bf/`에 보관한다.
