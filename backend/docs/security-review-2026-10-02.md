# 2026-10-02 통합 코드 보안·회귀 점검

후속 상태(2026-10-06): 아래에 남겨 둔 node-forge 문제는 [프로젝트 보완과 회귀 검사](../../frontend/docs/node-forge-security-fix.md)를 추가했다. 본문의 10월 2일 검사 수치는 당시 기록이며 최신 의존성 상태는 후속 문서를 따른다.

대상은 원격 `2c34caa`와 로컬 관리자·수집·공고·웹·모바일 변경을 합친 소스다. 인증, 권한, 개인정보 저장, 외부 전송, 수집 URL, 실행 자원 제한, 의존성, 커밋 대상 비밀값을 검토했다. 실제 서비스 공격이나 운영 데이터 이관은 수행하지 않았다.

## 확인한 문제와 수정

| 영역 | 문제와 영향 | 수정·검증 |
| --- | --- | --- |

## 자동 검사와 비밀값 검토

- `pip-audit` 운영 잠금 파일 25개, 개발 잠금 파일 35개: 알려진 취약점 0건, 조회 생략 0건. 프로젝트 가상환경의 `pip check`도 통과.
- 웹 npm 의존성 검사: 알려진 취약점 0건. 모바일은 아래의 미해결 공급자 공지가 남아 있다.
- Bandit로 Python 파일 125개를 검사했다(high 0, medium 1, low 274). medium XML 경고는 호출 경로를 검토했다. XML 파서는 UTF-8만 받고 `DOCTYPE`/`ENTITY`를 거부하며 해당 회귀 검사를 유지한다. 레거시 `urlopen` 경고는 위 전송 경계로 보완했다. 나머지 테스트 `assert`, 프로토콜 이름·UI 문구, 인자 배열 기반 자식 프로세스 실행을 실제 자격증명·셸 문자열 실행과 구분했다.
- `detect-secrets --no-verify`로 Git 추적 파일과 새 파일 491개를 검사했다. 19개 후보는 합성 테스트 값, 공개 환경변수 이름, 참조 데이터 해시였다. 실제 로컬 환경·MySQL 자격증명의 중복 제거한 비밀값 4개도 원문·URL 인코딩 형태로 커밋 대상과 별도 대조했고 일치가 없었다. 비밀값 자체는 기록하지 않았다.
- 자세한 실행 결과는 아래 최종 검증에 기록한다. 검사 원본은 Git에서 제외한 `tmp/security-review/`에 보관한다.

## 남은 의존성 공지

모바일 Expo CLI의 `node-forge@1.4.0`에 [GHSA-86w9-cpqp-85rv / CVE-2026-85393](https://github.com/advisories/GHSA-86w9-cpqp-85rv)가 남아 있다. 2026-10-02 조회 기준 수정 버전은 없으며, npm audit은 이 한 원인을 상위 패키지와 함께 high 4개로 집계한다. 호환되지 않는 Expo 강제 다운그레이드나 임의 암호화 구현 교체는 적용하지 않았다.

확인한 호출 경로는 Expo 개발 manifest의 인증서·서명 처리다. 앱 소스는 node-forge를 직접 가져오지 않으며 현재 자체 OTA 코드서명 설정도 없다. CLI에는 여전히 취약 코드가 설치되므로 신뢰되지 않은 인증서·개인키를 사용하거나 개발 서버를 공개 운영 서버로 사용하지 않는다. 공식 호환 패치가 나오면 다시 갱신·검사해야 한다. [모바일 의존성 경로·검증 기록](../../frontend/docs/mobile-security-review.md).

## 범위와 실행 전 조건

카카오 공급자 응답은 테스트 대역을 사용했다. 실제 카카오 사용자 동의, 운영 배포, 외부 침투 테스트, 최종 서명 APK/AAB 및 실제 iOS 기기 검증을 완료했다는 뜻은 아니다. 실제 서버의 암호화 키·카카오 설정·회원 DB 초기화/이관은 [회원 저장 문서](member-privacy.md)와 [카카오 설정](kakao-login.md)을 따른다. 이번 검사에서는 기존 서비스 환경 파일·회원 데이터·배포를 변경하지 않았다.

실제 MySQL 검사는 데이터베이스 이름 `bokji_compass_test`와 이 프로젝트의 로컬 데이터 디렉터리를 확인한 별도 테스트 DB만 사용한다. 테스트는 합성 데이터를 생성하고 자신이 만든 ID만 정리한다.

| 검사 | 결과 |

| 웹 `npm test` | **39 passed** |
| 웹 Playwright E2E | **100 passed**, 2.9분 |
| 웹 Vite production build | 통과 |
| 모바일 `npm test` | **32 passed** |
| 모바일 TypeScript·ESLint | 통과 |
| Android·iOS Hermes export | 양 플랫폼 통과 |
| 백엔드 전체 Ruff·Git diff 검사 | 통과 |
| Windows 설정 경합 반복 | 동시 4개 요청 × 100회 모두 저장 1건·충돌 3건. 빈 파일 잠금 강제 경합 30회도 통과 |

백엔드에서 건너뛴 2개는 네이티브 POSIX 실행과 호스트에서 허용하지 않는 합성 심볼릭 링크 검사다. 기존 Starlette/httpx 및 anyio 테스트 도구의 deprecation 경고 2개는 남아 있다. 테스트 대역을 통한 회귀 성공을 실제 카카오 공급자 로그인이나 운영 배포 성공으로 해석하지 않는다.

실제 MySQL 검사에서 드러난 줄바꿈 체크섬 오류와 전체 검사에서 드러난 Windows 설정 저장 경합을 수정한 뒤 전체 백엔드를 다시 실행했다. 최종 원본 로그는 `tmp/security-review/main-final-tests.log`, 프런트엔드 검사 산출물은 `tmp/kakao-merge-validation/`에 보존한다.
