# 봉규 브랜치·공고 요약·seed 확인 (2026-10-06)

로컬 main과 `bonggyu@16b0337`을 비교하고 필요한 광운대 수집·seed만 선택 반영했다.
기존 로컬 변경은 보존했다. 전체 브랜치 병합·운영 DB 변경·seed SQL 실행·서비스 재시작은 하지 않았다.

## 이전 보고서의 의미

- 브랜치 제외: SQL의 시각·offset 페이지와 Python의 날짜·ID 재정렬이 달라 같은 날의
  공고가 중복/누락됐다. 강서구처럼 중복된 구 이름을 시도 검색어로 확장해 지역이 섞였다.
  이전 개정·조건·공개 감사 이력을 삭제하는 공개 처리도 있어 전체 병합하지 않았다.
- 평문 저장: 회원·금융 입력값의 애플리케이션 DB 암호화가 제거됐다는 뜻이다.
  DB·백업 접근자는 해당 필드를 읽을 수 있다. 비밀번호는 별도 scrypt 해시를 유지한다.
- braces: 모바일 도구의 `braces@3.0.3`은 중첩 패턴으로 Node 프로세스를 중단시킬 수 있다.
  [공식 공지](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)에 수정 버전은 없다고 표시돼 있다.
  앱 이용자 입력으로 공격이 성공하는 경로가 확인됐다는 의미는 아니다.
- 008은 공고·조건 호환 테이블, 010은 긴 제목·기관·URL·원문·조건 근거를 위한 컬럼 용량 확장이다.
  코드 복사와 DB 적용은 별도이며 이미 적용됐다면 재실행할 필요가 없다.
  초기화기의 적용 기록·체크섬을 확인한다. 이번에는 운영 DB 적용 여부를 확인하거나 변경하지 않았다.

## 공고체와 지급 시기

화면 표시 함수와 신규 개요 프롬프트에 명사형 공고체를 적용했다.
원문 JSON·기존 개요·인용·자격 조건은 그대로다. `card`는 검증된 개요의 혜택을 우선하여
summary/benefit을 만들고 알려진 서술형 어미를 다듬는다. 더 다양한 기존 표현을 재작성하려면
별도 모델 재처리가 필요하며 이번 작업에서는 실제 LLM을 재호출하지 않았다.

- `장학금은 2026년 12월 초 지급 예정이다.` → `장학금은 2026년 12월 초 지급 예정.`
- `10월 중순 이후 선발완료순으로 후지급한다.` → `10월 중순 이후 선발완료순으로 후지급.`

원문에 명시된 지급 시기 한 건은 선택 `paymentSchedule`로 제공하고 일반/쉬운 화면의
목록·상세에서 신청 기간과 별도의 `지급 시기`로 표시한다. 모호하거나 상충하면 표시하지 않고
없는 연도·일자·지급 확정을 만들지 않는다. 지급 시기는 신청 캘린더 날짜에 사용하지 않는다.
