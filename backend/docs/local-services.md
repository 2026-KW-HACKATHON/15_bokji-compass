# 생활반경 기반 지역 복지

노원구·월계1동을 우선 탐색 지역으로 삼되 데이터와 지역 판정을 전국 공통 구조로 분리합니다.
서비스별 실제 이용 가능 범위(`coverage`)와 확인된 동네 거점(`focusAreas`)을 따로 기록합니다.
구 전체 서비스가 월계1동 주민에게 제공되더라도 근거 없는 월계1동 거점으로 표시하지 않습니다.

## 공개 API

`GET /v1/local-services`는 로그인·DB·외부 API 없이 검증된 카탈로그를 조회합니다.
주소 원문이나 계정 ID를 받거나 저장하지 않습니다. 응답은 `Cache-Control: no-store`입니다.

| 매개변수 | 기본값·허용값 |
| --- | --- |
| `region` | `서울`. 기존 프론트엔드와 동일한 17개 시도 축약명 및 정식명 alias. 빈값/`전국`은 전국 탐색 |
| `district` | `노원구`. 시·군·구 이름 또는 `수원시 영통구` 형태. 빈값은 시도 전체 탐색 |
| `neighborhood` | 빈값. 명시적으로 입력한 동·읍·면 이름 |
| `neighborhood_type` | `unknown`, `administrative`, `legal` |
| `category` | `all`, `transport`, `health`, `care`, `culture` |
| `scope` | `all`, `neighborhood` |

응답은 `{items,total,coverage:{regions:[{region,district,count}],totalServices,totalDistricts},
focus:{region:'서울',district:'노원구',neighborhood:'월계1동'},checkedAt}`입니다.
`items`는 검증된 JSON의 모든 필드를 유지합니다. `coverage`는 검색 결과와 관계없이 전체
카탈로그에 실제로 수집된 영역의 건수이며 전국/시도 범위는 district가 빈 문자열입니다.
`totalDistricts`는 명시한 시군구 수만 셉니다. `checkedAt`은 전체 항목 중 가장 오래된 확인일이며
각 항목 확인일도 별도로 제공합니다. 이는 원문 게시일이나 실시간 운영 보장이 아닙니다.

`scope=all`은 전국·해당 시도·시군구 전역 서비스와 정확한 동네 범위 서비스를 합칩니다.
동네를 입력하지 않은 시군구 전체 탐색에서는 그 시군구의 동네 한정 서비스도 모두 보여주며
각 항목의 `coverage`는 원래 범위를 유지합니다. 상위 시 탐색에는 산하 구의 서비스도 포함됩니다.
`scope=neighborhood`는 해당 이름·유형이 `focusAreas` 또는 동네 한정 `coverage`에 명시된
서비스만 반환합니다. 행정동 월계1동과 법정동 월계동은 변환하지 않습니다. `unknown`은
이름이 정확히 같을 때만 일치하며 숫자 삭제·부분 문자열·주소 지오코딩을 하지 않습니다.
수원시 영통구에는 수원시 전역 서비스가 포함되지만 수원시 팔달구 서비스는 포함되지 않습니다.
세종은 시군구 없는 동·읍·면을 지원합니다. 정확한 동네 거점이 먼저 나오고 제목·ID 순으로
안정 정렬합니다. 데이터가 없는 지역·분야는 빈 배열이며 샘플로 대체하지 않습니다.

입력 오류는 422, 카탈로그 누락·검증 실패는 안전한 503입니다. 내부 파일 경로나 검증 원문은
서버 로그에만 남습니다. 지역 이름은 검색용 문자열이고 공인 행정코드가 아닙니다. 명칭이나
코드 변환이 필요한 향후 확장은 기존 `regions` 모듈의 공식 스냅샷과 행정/법정 체계를
명시적으로 연결해야 하며 지역 코드나 동 간 대응을 생성하면 안 됩니다.

## 저장과 갱신

기존 프론트엔드 정적 배열에서 `backend/reference/local_services/services/*.json`을 읽는
API로 이동합니다. JSON은 직접 검토한 공공 안내의 요약이며 운영 데이터베이스가 아닙니다.
여러 지역/분야 파일을 같은 스키마로 더하면 코드 수정 없이 함께 조회됩니다.

1. 기관 공식 상세 페이지에서 현재 이용 대상·비용·이용방법·범위를 확인합니다.
2. 기존 ID를 유지해 해당 항목을 갱신하거나 명확한 새 ID로 추가합니다. 출처 URL,
   기관명, 확인일, 게시일(없는 경우 null), 짧은 검증 근거를 필수 기록합니다.
3. 행정동/법정동 근거가 없는 동네는 추정하지 않고 더 넓은 확인 범위만 기록합니다.
   `focusAreas`는 원문에서 확인한 거점만 포함하며 `coverage` 안에 있어야 합니다.
4. `python -m app.modules.local_services validate`로 필드·범위·중복·날짜·링크 검증을 실행합니다.
5. 대상·요금·시간이 바뀌었는지 원문을 다시 검토하고 변경 요약을 함께 검토한 후 배포합니다.

원본 HTML/PDF, 수집 로그, 링크 점검 결과가 필요하면 git 제외된 `backend/data/local_services/`에
저장합니다. 원문을 reference 아래에 복제하지 않습니다. 현재 자동 크롤러나 예약 수집은 없고,
검토한 출처 요약을 버전 관리합니다. 스키마 검증은 링크 형식만 검사하며 원문 가용성이나
기관 공식성 자체를 보증하지 않습니다. `sourcePublishedAt`은 게시일이 확인되지 않으면 null로
유지하고 `checkedAt`과 혼동하지 않습니다.

향후 수집기를 추가할 때도 동일 스키마를 staging에서 검증한 후 검토된 항목만 공개해야 합니다.
서비스 중단·기간 종료가 확인되면 공개 목록에서 제거하거나 현행 서비스로 내용을 교체하고,
이전 자료는 Git 이력으로 보존합니다. 과거 공고·검색결과 노출만으로 현재 운영을 확정하지 않습니다.
