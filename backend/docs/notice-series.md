# 같은 사업의 단계별 공고

2026-10-08 구현. 원문 게시글의 중복 수집 방지와 별도로, 사용자 화면에서 같은 사업의
신청·추가 절차·선발 결과를 한 묶음으로 표시한다. 저장된 원문·정책 ID·개정·첨부 파일은
변경하거나 삭제하지 않는다. DB 마이그레이션 없이 최신 공개 원문의 읽기 모델에 적용한다.

## 묶음 기준

`storage/notice_series.py`는 게시 기관, 구별되는 사업명, 명시된 연도·학기/반기/분기/월과
모집 차수를 함께 비교한다. 비슷한 제목만으로 합치지 않는다. 연도·기관이 없거나 기간이
여러 개로 해석되는 제목은 별도로 유지한다. 국가근로장학금과 국가장학금·교비근로장학은
다른 사업이며, 연도·학기·기관·차수가 다르면 다른 묶음이다.

차수가 없는 후속 공지는 같은 사업·기간에 명확한 한 차수만 있을 때 연결할 수 있다.
여러 차수 사이에서 어느 것인지 알 수 없으면 합치지 않는다. 추가 모집은 기존 결과
공지와 별도 회차로 유지한다. 제목에 있는 신규/추가 모집을 단순 선발 결과로 분류하지 않는다.
광운대의 동일 DUID 주소 변형은 하나의 원문으로 취급하고 최신 원문을 표시한다.
검색어·분류·상태를 적용하기 전에 전체 공개 원문으로 관계를 확인한다. 필터에서 결과
공지가 빠졌다고 예전 신청을 다시 진행 중으로 판단하거나, 다른 차수가 안 보인다고
어느 차수의 결과인지 불확실한 공지를 하나의 차수에 연결하지 않는다.

기간 연장·재공고 표기는 같은 모집의 갱신이며 대표는 최신 원문을 사용한다. 알려진
국가 사업의 `[한국장학재단]` 접두어와 `청년창업농장학생/청년창업농장학금`의 명확한
동의 표기를 정규화한다. 외부 재단·지역 이름이나 혜택 구분을 임의로 제거하지 않는다.
지급 1~4차는 모집 차수가 아니므로 같은 학기 지급 안내 묶음으로 처리한다. 이 묶음은
모집 1·2차와 별개이며 신청자를 위한 가구원 동의 공지를 특정 모집 차수에 추정 연결하지 않는다.

광운대 `2026년 2학기 국가근로장학금`의 실제 원문은 다음 단계로 연결된다.

| 게시일 | 원문 역할 | 공식 게시글 DUID |
| --- | --- | --- |
| 2026-05-21 | 최초 학생 신청 | 52562 |
| 2026-08-06 | 신청 완료자의 희망 근로지 선택 | 53017 |
| 2026-08-25 | 장학생 선발 확정 | 53187 |

목록 대표는 신청 원문을 우선하고 같은 단계에서는 최신 원문을 선택한다. 목록 위치는
기존 정렬에서 해당 묶음이 처음 등장하는 위치를 사용한다. 검색 근거는 선택된 대표
원문의 근거만 유지한다. 다른 게시글의 인용을 대표 원문의 근거로 바꾸지 않는다.

## 공개 API와 화면

`policy.noticeStage`는 `application|followup|result`이며 판단 근거가 없으면 생략한다.
모집 마감·종료도 신규 신청이 아닌 `result`로 분류하지만 화면은 ‘모집 종료’, 상태 필터는
`closed`로 구분한다. 선발 완료를 의미한다고 표시하지 않는다.
여러 원문이 연결되면 `policy.noticeGroup`을 추가한다.

```text
{ id, title, latestStage, noticeCount,
  notices:[{id,revisionId,title,stage,publishedDate,sourceUrl}] }
```

`id`는 화면용 묶음 ID이며 원래 정책 ID를 대체하지 않는다. `notices`에는 최신 공개 원문만
넣는다. 비공개 원문·첨부·다른 계정 정보는 포함하지 않는다. 원래 ID로 상세를 열면 해당
게시글의 제목·본문·신청 안내·첨부를 그대로 제공하고 같은 묶음의 공개 원문 링크도 표시한다.

공개 목록과 스마트/문자 그대로 검색은 묶음을 구성한 뒤 전체 건수·페이지를 계산한다.
검색의 관계별 건수도 묶음 단위다. 캘린더는 신청 원문의 날짜를 보존하고 후속 절차/결과
공지를 신규 신청 일정으로 추가하지 않는다. 선발 결과 단계의 묶음은 상태 필터에서
`selected`로 구분한다. 웹 카드는 묶음 제목·최신 단계·접을 수 있는 관련 공고 목록을 표시한다.
후속·결과 단계는 새 신청 버튼을 제공하지 않고 원문 신청 안내와 서류는 읽을 수 있게 한다.
지급 일정은 ‘신청자 추가 절차’ 대신 ‘지급 안내’로 표시한다. 실제 연장 원문의
`가. 신청기한 ... (기간연장)` 및 `신청기간: ~마감일까지` 형식에서도 최신 마감일을
읽는다. 시작일이 없으면 만들어 넣지 않고, 상충하는 신청 기간은 계속 미확정으로 유지한다.

## 신규 추천과 기존 저장 정보

홈 추천·일반 대화 탐색·지속 안내는 전체 공개 원문에서 묶음을 먼저 확인한다. 선발 결과
공지와 신청자만을 위한 후속 절차를 신규 신청 추천에서 제외하고, 같은 회차의 선발 결과가
나왔으면 이전 신청 원문도 새 추천에서 제외한다. 새로운 추가/다른 차수 모집은 독립적으로
비교한다. 자격 비교·계정별 추천 제외를 적용한 뒤 묶음 대표와 결과 개수 한도를 계산한다.

저장된 추천 카드와 관련 알림도 최신 원문을 읽어 재검사한다. 이미 기록된 신청 이력·서류
준비·추천 제외는 지우지 않고 조회 화면에서 현재 추천을 걸러낸다. 같은 묶음의 제외 공고가
다른 게시글로 바뀌어 재등장하지 않도록 계정의 제외 설정을 확인한다. 다른 계정·연도·회차에는
영향을 주지 않는다. 사용자가 직접 여는 원문 상세 조회는 계속 가능하다.

## 운영 반영 확인

2026-10-08 사용자 요청으로 웹 빌드와 백엔드를 운영 반영했다. 기존 정적 파일을 백업하고
새 자산과 진입 HTML을 배치한 뒤 `share.ps1 reload`로 API·QR·Caddy를 갱신했다.
고정 터널과 `https://bokji.commitnaru.com`을 유지했고 DB 초기화·원문 재적재·회원 변경은 없다.

23:44 KST 공개 HTTPS 조회에서 실제 반영 전 185개→176개를 확인했다. 원문 190개 중
22개가 8개 묶음이며 각 원문 상세 22개의 제목·본문·공식 주소·첨부 목록·연결을 검증했다.
국가우수 일시지원의 연장 마감일 `2025-11-18`, 청년창업농의 `2026-07-06`과 실제 모집
1·2차 별도 카드도 확인했다. readiness는 `ready/database reachable`이다.
공개 진입 JS `index-BssX8klv.js`와 관련 정적 파일 5개가 새 빌드와 SHA-256 일치했다.

실제 PC·320px 모바일에서 광운대 176개, 지급 1~4차의 관련 공고 4개, 원래 상세와 공식
