# 생활 상황 상담과 부족한 정보 보완

2026-10-07 구현. 발표용 의사결정·검토 사항은 [복지 개인비서 최종 발표 기록](https://chatgpt.com/space/page_c4b4de06d7008191880f0037d2ae8ebe)에 정리한다. 이 문서는 실행 코드의 계약과 한계를 설명한다.

## 사용 흐름

웹 비서의 `생활 상황으로 상담하기`, 선택한 공고의 `내 상황을 더해서 확인하기`에서 시작한다. `리모델링 지원금을 받을 수 있어?`는 주거 개선 탐색 주제를 선택하며, 문장 자체를 본인 소유·피해 사실로 저장하지 않는다. 본인/다른 사람/가정 상황을 구분한 후, 현재 알고 있는 사실과 아직 모르는 항목을 나누어 한 가지씩 묻는다. `정보 추가하기`는 같은 대화의 입력란으로 이동한다.

`1920년 건축` 같은 답변은 질문 중인 준공 연도에만 반영한다. 미래 연도·범위 밖 연도는 다시 묻고, `모름`·건너뛰기는 미확인 상태로 남긴다. 준공 연도만으로 지원 가능을 확정하지 않는다. 공개 공고의 알려진 조건을 다시 비교하고 남은 조건·접수 기간·원문 확인이 필요함을 표시한다. 선택한 공고가 불일치하면 이유를 보여 주며, 조회 장애와 후보 없음은 서로 다른 상태다.

`집에 누수가 생겼어`에는 점검 요청과 안전한 상황 기록 방법을 먼저 안내한 뒤 수리 지원 탐색 여부를 묻는다. 누수·침수 표현이 섞여도 즉시 대응 안내를 표시한다. 누수 질문을 재난 피해 사실로 자동 변환하지 않는다. 전기설비 주변 물·진행 중인 침수에는 접근을 피하고 안전한 곳으로 이동하도록 안내하며 공식 [국민안전24 침수 행동요령](https://www.safekorea.go.kr/safekorea-kor/acts/nacts/action-guide.do?actsHeaderTitle=%EC%B9%A8%EC%88%98&category=inundation&menuSn=4)을 연결한다.

## HTTP 계약

웹 쿠키 또는 모바일 Bearer 회원 인증과 POST `X-Auth-Request: 1`이 필요하다. 응답은 오류를 포함해 `Cache-Control: no-store`다. 이 경로는 규칙과 기존 공고 비교를 사용하며 외부 AI 호출·동의를 요구하지 않는다. 기존 `/v1/assistant/questions`의 외부 AI 계약은 별개다.

| 경로 | 입력과 동작 |
| --- | --- |
| POST `/v1/assistant/dialogue` | 시작 `{question, revision_id?}` 또는 후속 `{continuation, answer:{slot,value}}`. 두 형태 혼합 금지. 계정당 분당 60회 |
| POST `/v1/assistant/dialogue/profile` | `{continuation, consent:true, confirmed:true}`. 서버가 보유한 본인의 명시적 확인 필드만 저장. 클라이언트 profile/account_id 금지. 계정당 분당 20회 |

대화 응답은 `answer`, `topic`, `eligibility_decided:false`, `follow_up`, `missing_fields`, `continuation`, `profile_draft`, `confirmed_fields`, `can_save_profile`, `candidates`, `candidate_count`, `selected_policy`, `catalog_status`, `practical_steps`, `source_links`, `session_notice`, `answer_accepted`를 포함한다. `answer_accepted:false`는 형식 오류로 같은 질문을 유지한다. `catalog_status`는 `not_requested/ready/unavailable`이다. 후보는 최대 12개와 전체 수를 반환한다.

저장 응답은 기존 지속 안내 snapshot과 `scan_status`다. 확인한 필드만 계정 잠금 아래 병합하여 다른 화면이 바꾼 무관한 필드를 보존한다. 기존 지속 안내 enabled를 유지하며 처음 저장은 꺼짐이다. 켜진 계정은 공고를 재비교하고, 공고 장애 시 저장 성공과 확인 불가를 함께 반환한다. 실패한 DB 저장은 대화의 저장 대상을 소비하지 않으며 성공 후 중복 저장은 409다. 타인·가정·대상 미확인의 정보는 본인 계정에 저장할 수 없다.

## 정보와 동시성

- 서버는 질문·답변 원문이나 전체 이력을 DB에 저장하지 않는다. 주제·답한 항목·확인한 최소 구조화 사실만 계정에 묶인 임시 메모리에 보관한다. 외부 모델로 전송하지 않는다.
- 대화는 시작 시점부터 30분 후 만료하며 연장하지 않는다. 만료 정보는 다음 접근 또는 30초 간격 정리에서 제거한다. 서버 종료, 회원 탈퇴, 지속 안내 정보 삭제도 해당 임시정보를 제거한다. 브라우저에서 새 상담을 시작하거나 창을 닫는 것만으로 서버의 임시정보가 즉시 삭제되는 것은 아니다.
- 예측 불가능한 연결 토큰은 사실 자체를 담지 않는다. 다른 계정의 토큰·만료·서버 재시작은 410이다. 동시 답변은 버전으로 검사하고 오래된 순서의 덮어쓰기를 409로 막는다. 명시적 저장과 답변 갱신도 직렬화한다.
- 소스 조회 중 탈퇴한 계정은 마지막 계정 검사에서 응답·임시정보를 제거한다. 실제 저장은 기존 탈퇴와 같은 계정 잠금을 사용한다. 공개가 철회된 선택 공고를 반환하지 않는다.

## 현재 한계와 다음 범위

현재 주거 수리·누수, 취업, 재난 피해에 대한 기본 질문 묶음이다. 모든 공고의 조건을 동적으로 질문으로 바꾸거나 모든 일상 문제에 상담하는 기능은 아니다. 소득·자산·개별 사업 요건 등 지원하지 않는 조건은 계속 미확인으로 표시한다. 건축 연도는 탐색 정보이며 공고별 연한·건축물 적법성 등의 최종 판정 규칙을 대신하지 않는다.

저장된 값이 틀렸으면 `저장한 생활 정보 수정하기`로 이동해 수정한 뒤 새 상담을 시작한다. 건너뛴 값을 같은 대화에서 되돌려 수정하는 기능과 자유 문장에서 여러 사실을 자동 추출하는 기능은 후속 범위다. 과거 질문의 장기 관심사 메모리도 검토 단계이며 구현하지 않았다.

임시 대화 저장소는 서버 프로세스 단위다. 여러 worker·서버를 사용하는 배포에는 세션 라우팅 또는 만료·계정 삭제를 공유하는 저장소가 필요하다. 현재 브라우저 UI를 구현했고 모바일 네이티브 상담 UI는 후속 범위다. 정기 공고 확인 worker·외부 재난 피드·알림 채널의 운영 범위는 [지속 안내](proactive-guidance.md)를 따른다.

## 검증

`test_assistant_dialogue.py`, `test_assistant_dialogue_api.py`는 부족한 입력·연도 해석·건너뛰기·대상 구분·공개 공고·소스 장애·만료·경쟁 저장·탈퇴·동의와 계정 경계를 검증한다. 웹의 `dialogue.test.js`, `e2e/dialogue.spec.js`는 실제 입력·정보 버튼·생활 대응·명시적 저장·취소/계정 전환·공고 연결을 검증한다. 실행 결과는 worklog에 기록한다.
