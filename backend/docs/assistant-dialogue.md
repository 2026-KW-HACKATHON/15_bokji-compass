# 생활 상황 상담과 부족한 정보 보완

2026-10-07 구현, 2026-10-08 자유 입력 탐색 보완. 발표용 의사결정·검토 사항은 [복지 개인비서 최종 발표 기록](https://chatgpt.com/space/page_c4b4de06d7008191880f0037d2ae8ebe)에 정리한다. 이 문서는 실행 코드의 계약과 한계를 설명한다.

## 사용 흐름

웹 AI 비서 메뉴의 `AI 비서와 대화하기`는 `#assistant-chat` 전용 페이지를 연다. 추천 화면의 질문 버튼과 챗봇의 이어보기도 같은 페이지로 연결한다. 이 화면은 `mode:conversation`으로 메시지를 주고받으며 대상·지역 선택 설문을 표시하지 않는다. 인사에 대화로 답하고 지원 요청이 나오면 공고를 검색하며, 이전 지역·검색 상황·공고를 후속 질문에서 참조한다. [자유 대화 계약](free-conversation.md)을 참고한다.

아래 단계별 질문·명시적인 생활정보 저장 계약은 별도 생활 상담의 기본 `guided` 모드에 해당한다. `리모델링 지원금을 받을 수 있어?`는 주거 개선 탐색 주제를 선택하며, 문장 자체를 본인 소유·피해 사실로 저장하지 않는다. 본인/다른 사람/가정 상황을 구분한 후 필요한 사실을 한 가지씩 묻는다.

`1920년 건축` 같은 답변은 질문 중인 준공 연도에만 반영한다. 미래 연도·범위 밖 연도는 다시 묻고, `모름`·건너뛰기는 미확인 상태로 남긴다. 준공 연도만으로 지원 가능을 확정하지 않는다. 공개 공고의 알려진 조건을 다시 비교하고 남은 조건·접수 기간·원문 확인이 필요함을 표시한다. 선택한 공고가 불일치하면 이유를 보여 주며, 조회 장애와 후보 없음은 서로 다른 상태다.

`집에 누수가 생겼어`에는 점검 요청과 안전한 상황 기록 방법을 먼저 안내한 뒤 수리 지원 탐색 여부를 묻는다. 누수·침수 표현이 섞여도 즉시 대응 안내를 표시한다. 누수 질문을 재난 피해 사실로 자동 변환하지 않는다. 전기설비 주변 물·진행 중인 침수에는 접근을 피하고 안전한 곳으로 이동하도록 안내하며 공식 [국민안전24 침수 행동요령](https://www.safekorea.go.kr/safekorea-kor/acts/nacts/action-guide.do?actsHeaderTitle=%EC%B9%A8%EC%88%98&category=inundation&menuSn=4)을 연결한다.

## 사례에 제한하지 않는 탐색 (2026-10-08)

리모델링·누수·취업은 요구사항을 설명하기 위한 사례다. 해당 문장을 고정 진입 버튼이나 사용자 질문의 기본값으로 사용하지 않는다. 위 사례용 추가 질문 규칙에 들어맞지 않는 요청은 `general`로 받아 기존 공개공고 검색의 해석·순위 엔진을 사용한다. 분야를 네 가지 중에서 선택하도록 강제하지 않는다.

안내 대상을 먼저 확인하고, 공개된 최신 공고 전체를 검색·정렬한 뒤 알려진 조건의 불일치·접수 종료·비공개 전환 공고를 제외한다. 유효한 상위 후보 최대 12개에 공개 원문 근거와 아직 확인하지 못한 조건을 표시한다. `candidate_count`는 일반 탐색에서는 이 후보 묶음의 건수이며 전체 지원 제도의 수가 아니다. 검색 표현의 연령·가족·관심 단어는 관련도 신호로만 사용하며 사용자 사실로 저장하거나 자격 조건을 충족한 것으로 처리하지 않는다.

선택한 공고는 주제 분류와 관계없이 본인/타인 확인 뒤 조건을 비교한다. 일반 탐색의 결과가 없으면 네 사례 선택지 대신 `search_query` 텍스트 질문으로 원하는 도움을 구체화한다. 질문이 200자를 넘으면 앞부분만 잘라 검색하지 않고 200자 이내 핵심 내용을 요청한다. 한 차례의 검색어 보완 뒤에도 후보가 없으면 결과와 한계를 표시하며 새 질문을 시작할 수 있다. 조회 장애는 후보 없음으로 표현하지 않는다.

이 경로는 기존의 로컬 검색과 조건 비교를 재사용하며 외부 모델·웹 검색 호출을 추가하지 않는다. 원문 질문은 URL이나 영구 저장소로 전달하지 않는다. 후속 비교에 필요한 제한된 검색 의도(분야·기관·포함/제외 검색어 등)만 임시 상태에 보관하고 30분 만료·계정 삭제 규칙을 적용한다. 검색 의도도 생활정보 저장 대상으로 승격하지 않는다.

## HTTP 계약

웹 쿠키 또는 모바일 Bearer 회원 인증과 POST `X-Auth-Request: 1`이 필요하다. 응답은 오류를 포함해 `Cache-Control: no-store`다. 이 경로는 규칙과 기존 공고 비교를 사용하며 외부 AI 호출·동의를 요구하지 않는다. 기존 `/v1/assistant/questions`의 외부 AI 계약은 별개다.

| 경로 | 입력과 동작 |
| --- | --- |
| POST `/v1/assistant/dialogue` | 시작 `{question, revision_id?}`, 구조화 답변 `{continuation, answer:{slot,value}}`, 자유 후속 질문 `{continuation, question}`. question과 answer 혼합 및 후속 revision_id 금지. 횟수 제한 없음 |
| POST `/v1/assistant/dialogue/profile` | `{continuation, consent:true, confirmed:true}`. 서버가 보유한 본인의 명시적 확인 필드만 저장. 클라이언트 profile/account_id 금지. 횟수 제한 없음 |

공고 질문·챗봇·추천 조회·지속 안내의 정보 저장/확인·추천 제외/서류 준비에도 사용자별 횟수 제한을 적용하지 않는다. 외부 공고 AI 답변의 동시 실행 수 제한도 제거했다. 입력 길이·실행 시간·인증·동의·로그인 보안 제한은 유지한다.

자유 후속 질문은 같은 계정의 continuation을 사용한다. 현재 추가 질문에 대한 짧은 유효 답변이면 해당 항목만 확인하고, 새 지원 분야를 물으면 기존 본인 확인 정보를 유지하며 탐색한다. 타인·가정 상황은 본인 정보를 초기화한 별도 문맥으로 확인한다. 준비 서류·신청 방법·기간·지원 내용·대상 질문은 선택 공고 또는 이전 후보의 제목/순서로 대상을 정해 최신 공개 원문에서 답한다. 여러 후보 중 대상을 정할 수 없으면 제목이나 순서를 요청한다. 서류가 없다는 명시와 서류 정보 미기재를 구분하며 추정하지 않는다.

대화 응답은 `answer`, `topic`, `eligibility_decided:false`, `follow_up`, `missing_fields`, `continuation`, `profile_draft`, `confirmed_fields`, `can_save_profile`, `candidates`, `candidate_count`, `selected_policy`, `catalog_status`, `practical_steps`, `source_links`, `session_notice`, `answer_accepted`를 포함한다. `answer_accepted:false`는 형식 오류로 같은 질문을 유지한다. `catalog_status`는 `not_requested/ready/unavailable`이다. 후보는 최대 12개를 반환한다. 기존 분야 탐색의 `candidate_count`는 전체 비교 후보 수이며 일반 탐색은 상위 유효 후보 묶음의 수다.

저장 응답은 기존 지속 안내 snapshot과 `scan_status`다. 확인한 필드만 계정 잠금 아래 병합하여 다른 화면이 바꾼 무관한 필드를 보존한다. 기존 지속 안내 enabled를 유지하며 처음 저장은 꺼짐이다. 켜진 계정은 공고를 재비교하고, 공고 장애 시 저장 성공과 확인 불가를 함께 반환한다. 실패한 DB 저장은 대화의 저장 대상을 소비하지 않으며 성공 후 중복 저장은 409다. 타인·가정·대상 미확인의 정보는 본인 계정에 저장할 수 없다.

## 정보와 동시성

- 서버는 질문·답변 원문이나 전체 이력을 DB에 저장하지 않는다. 주제·답한 항목·확인한 최소 구조화 사실·일반 탐색용 검색 의도·이전 후보의 공개 개정 ID만 계정에 묶인 임시 메모리에 보관한다. 검색 의도에는 원문 질문·전체 대화·검색 결과를 넣지 않는다. 외부 모델로 전송하지 않는다.
- 대화는 마지막 입력부터 30분 후 만료한다. 입력 처리가 성공하면 만료 시간이 갱신되고 단순 조회는 연장하지 않는다. 만료 정보는 다음 접근 또는 30초 간격 정리에서 제거한다. 서버 종료, 회원 탈퇴, 지속 안내 정보 삭제도 해당 임시정보를 제거한다. 브라우저에서 새 상담을 시작하거나 창을 닫는 것만으로 서버의 임시정보가 즉시 삭제되는 것은 아니다.
- 예측 불가능한 연결 토큰은 사실 자체를 담지 않는다. 다른 계정의 토큰·만료·서버 재시작은 410이다. 동시 답변은 버전으로 검사하고 오래된 순서의 덮어쓰기를 409로 막는다. 명시적 저장과 답변 갱신도 직렬화한다.
- 소스 조회 중 탈퇴한 계정은 마지막 계정 검사에서 응답·임시정보를 제거한다. 실제 저장은 기존 탈퇴와 같은 계정 잠금을 사용한다. 공개가 철회된 선택 공고를 반환하지 않는다.

## 현재 한계와 다음 범위

공개공고 탐색은 주거 수리·누수·취업·재난에 제한하지 않는다. 다만 항목별로 답을 확인하고 생활정보로 저장하는 추가 질문은 현재 주거·구직·재난 관련 필드와 안내 대상·지역을 지원한다. 모든 공고의 조건을 동적으로 입력 가능한 질문으로 바꾸거나 모든 일상 문제의 대응 지식을 제공하는 기능은 아니다. 소득·자산·개별 사업 요건 등 지원하지 않는 조건은 계속 미확인으로 표시한다. 건축 연도는 탐색 정보이며 공고별 연한·건축물 적법성 등의 최종 판정 규칙을 대신하지 않는다.

저장된 값이 틀렸으면 `저장한 생활 정보 수정하기`로 이동해 수정한 뒤 새 상담을 시작한다. 건너뛴 값을 같은 대화에서 되돌려 수정하는 기능과 자유 문장에서 여러 사실을 자동 추출하는 기능은 후속 범위다. 과거 질문의 장기 관심사 메모리도 검토 단계이며 구현하지 않았다.

임시 대화 저장소는 서버 프로세스 단위다. 여러 worker·서버를 사용하는 배포에는 세션 라우팅 또는 만료·계정 삭제를 공유하는 저장소가 필요하다. 현재 브라우저 UI를 구현했고 모바일 네이티브 상담 UI는 후속 범위다. 정기 공고 확인 worker·외부 재난 피드·알림 채널의 운영 범위는 [지속 안내](proactive-guidance.md)를 따른다.

## 검증

`test_assistant_dialogue.py`, `test_assistant_dialogue_api.py`는 부족한 입력·연도 해석·건너뛰기·대상 구분·공개 공고·소스 장애·만료·경쟁 저장·탈퇴·동의와 계정 경계를 검증한다. 일반 탐색 검사는 사례 밖 분야·검색어 보완·긴 질문·본인/타인 경계·선택 공고 비교·종료/비공개 제외·응답 후보 한도를 포함한다. 웹의 `dialogue.test.js`, `e2e/dialogue.spec.js`는 실제 입력·정보 버튼·생활 대응·명시적 저장·취소/계정 전환·공고 연결을 검증한다. 실행 결과는 worklog에 기록한다.

`test_continuing_dialogue.py`는 자유 후속 질문·본인/타인 문맥·공고 지정·공식 신청/서류 안내·65회 연속 질문·조회 장애·활동 중 만료 갱신·회원/비회원 격리를 검증한다. `test_assistant_usage.py`와 공고 API 회귀는 기존 횟수/동시 실행 제한을 넘는 요청의 성공과 로그인 보안 제한의 보존을 확인한다. 웹 전용 페이지 회귀는 `e2e/assistant-conversation.spec.js`에 있다.
