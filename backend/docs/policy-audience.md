# 지원 대상·명확한 사업 장비 분류 표시 보완

2026-10-08. 공고 카드의 지원 대상이 연령 조건만 읽던 문제를 보완했습니다.

`storage.audience.audience_text(fields, overview, editorial=None) -> str`는 관리자 표시
수정이 있으면 확인된 대상 문구를 우선합니다. 그 외에는 원천 `eligibility`를 먼저
표시하고, 원문 대상이 없으면 확인된 연령 개요·대상 근거가 있는 다른 조건·확인된
`policy_requirements`의 원문을 사용합니다. 연령이 미기재라는 이유로 장애인·사업주 등
명확한 대상을 `지원 대상 확인 필요`로 바꾸지 않습니다. 나이·제외 조건 등 대상 문구의
전체 범위를 유지합니다.

`other_conditions(fields, overview) -> list[str]`는 기존 개요를 유지하고, 비어 있는
구형 개요에는 확인된 other 요건의 원문이나 원천 지원 대상·선정 기준을 표시합니다.
혜택·문의처·미확정 요건을 지원 대상으로 추정하지 않습니다. 이 함수는 DB·LLM·외부
API를 사용하지 않으며 저장된 원문·개요·정규화 조건과 자동 자격 판정을 변경하지 않습니다.

기존 기타/생활·금융 분류 중, 대상에 사업주·사업자·기업이 명시되고 지원 목적에
보조공학기기·업무/사업/생산 장비가 명시된 공고는 사업·창업으로 표시합니다.
근로자·직원 개인이 대상으로 명시되면 이 보완 규칙을 적용하지 않습니다. 관리자 분류와
주거·교육·건강 등 개인 지원 분야의 기존 우선 규칙은 유지합니다. SQL 필터·건수·페이지와
카드에서 같은 규칙을 적용하므로 재파싱·DB 업데이트 없이 기존 공개 공고에도 반영됩니다.
새 개요 생성 프롬프트에도 장애인기업 사업주 업무용 보조기기 예시를 추가했습니다.

검증: backend에서 `.venv/Scripts/python.exe -m pytest -p no:cacheprovider
tests/test_policy_audience.py tests/test_policy_categories.py tests/test_notice_presentation.py`
실행. 합성 공고와 격리 SQLite를 사용하여 원문 보존·대상 전체 문구·미확정 요건 배제·
관리자 수정·카드/SQL 분류와 페이지 일치를 확인합니다. 실제 DB 쓰기는 하지 않습니다.
