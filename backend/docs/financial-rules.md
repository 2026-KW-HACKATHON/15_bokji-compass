화면의 비율표는 32·40·48·50·60·80·100·120·150·180·200%를 단순 곱셈한 참고 표다. 생계급여와 차상위 비교의 8인 이상 한도는 이미 반올림된 6·7인 선정기준의 차이를 연장하므로 단순 비율표와 차이가 생길 수 있다. 예를 들어 12인 가구의 32%는 비율표 4,579,565원, 생계급여 선정 한도 4,579,563원이다.

소득인정액은 Decimal로 계산하며 화면에 원 단위로 표시할 때 HALF_UP을 사용한다. 이는 참고값의 표시 방식으로, 공식 소득인정액 원 미만 처리 규정을 확인한 것은 아니다. 생계급여 계산값이 한도를 1원 미만 초과하면 반올림·절사에 따라 비교가 바뀔 수 있으므로 `needs_review`로 반환한다. 기초생활 지침 238~239쪽의 지급액 10원 단위 올림 규정은 소득인정액 계산과 구분하며, 이 계산기는 지급액을 산출하지 않는다.

의료급여 40%, 주거급여 48%, 교육급여 50%는 공식 선정기준 비율이지만, 이 계산기에 해당 사업의 전체 심사 규칙이 구현되었다는 뜻은 아니다. 기초연금, 건강보험료 기준, 행복주택, 통합공공임대, 신혼희망타운 등의 판정도 현재 지원하지 않는다.

## 3. 생계급여 기본 산식

공식 세부 근거는 [2026 국민기초생활보장사업안내](https://www.easylaw.go.kr/CSP/FlDownload.laf?flSeq=1768437163027)의 99, 105~106, 134~166쪽이다. 요약 안내는 [보건복지부 소득·재산 조사](https://www.mohw.go.kr/menu.es?mid=a10708010400)를 함께 참고한다.

### 소득

가구원별 근로·사업소득에 적용 가능한 공제 중 가장 유리한 한 가지를 적용하고 기타 소득을 더한다. 현재 지원하는 기본 공제는 일반 30%, 34세 이하 60만 원 후 30%, 65세 이상 또는 등록장애인 20만 원 후 30%다. 고정 공제 후 금액은 0원 미만으로 내리지 않는다. 이는 모든 사업에 공통인 공제가 아니다. (105~106쪽)

나이·소득·공제 유형이 불명확하면 산입 요건을 추가 확인한다. 35세 이상 학생, 북한이탈주민 특례, 직업재활 참여자는 별도 검토 대상이다. 특히 직업재활의 20만 원 후 50% 공제는 해당 참여소득에 관한 규정이므로 전체 근로·사업소득에 일괄 적용하지 않는다.

**가족·지인 등의 생활비 지원 (118~119쪽)**: 가구 전체의 최근 12개월 월별 합계·횟수·지원자 관계·용도를 받는다. 6회 이상 지원은 각 월의 합계에서 가구 기준 중위소득 15% 초과분을 합산하여 12로 나눈다. 공제 기준은 안내의 예시처럼 원 단위로 반올림하는 참고 계산이며, 지원자·가구원별로 중복 공제하지 않는다. 공식 2인 가구 예시(30만 원 2회, 20만 원 1회, 65만 원 3회)는 월 반영액 5,027원이다. [보건복지부 2026 사업안내, 영광군 제공](https://www.yeonggwang.kr/bbs/?b_id=open_data&bf_idx=474626398&bs_content_type=1&bs_idx=1157400&mn=9007&per_page=20&site=headquarter_new&type=download&type2=write)

6회 미만은 월별 15% 초과분 합계가 가구 기준 중위소득 50% 이하인 일반 생활비 지원에 한해 미반영으로 계산한다. 50%를 넘는 비정기 지원, 학비·의료비·보증금 등의 지정 용도, 외국인 배우자 지원은 별도 확인으로 둔다. 빈 달은 사용자가 ‘미입력 달에는 받은 돈 없음’을 확인한 경우에만 0원으로 처리한다. 저장된 내역의 기준 월이 이번 달과 다르면 갱신이 필요하다.

내역이 부족해도 다른 소득·재산이 확인되면 **‘지원금 미반영 참고액’**을 표시하되 비교 상태는 `unknown`으로 둔다. 이를 완성된 소득인정액이나 ‘기준 이내’로 표시하지 않는다. 기존 월 지원금만 있는 저장 데이터도 이 방식으로 처리하고 지원 없음 선택과 현재 지원금이 충돌하면 확인을 요청한다. 과거 클라이언트의 내역 없는 명시적 월 지원금 0은 기존 계약과의 호환성을 유지한다.

세후 실수령액은 세전 금액으로 환산할 수 없어 기본 계산에서는 해당 소득 산식을 `unknown`으로 둔다. 입력 확인 단계에서 근사 계산을 명시적으로 선택한 경우에만 세후 금액을 세전으로 추정·환산하지 않고 입력액 그대로 산식에 넣으며, 그 결과는 `needs_review`/`unknown`과 가정 안내를 유지한다.

### 재산

금액 단위는 원이며 환산율은 **월** 기준이다.

| 지역 코드 | 지역 | 기본재산 공제 | 주거용재산 인정 한도 |
| --- | --- | ---: | ---: |
| `seoul` | 서울 | 99,000,000 | 172,000,000 |
| `gyeonggi` | 경기 | 80,000,000 | 151,000,000 |
| `metropolitan` | 광역시·세종·창원 | 77,000,000 | 146,000,000 |
| `other` | 그 외 지역 | 53,000,000 | 112,000,000 |

전남광주통합특별시(`jeonnam_gwangju`)의 별도 적용 기준은 아직 서버에 등록되지 않아 규칙 카탈로그에 금액을 제공하지 않는다. 사용자가 광주광역시 또는 그 외 지역 권역을 선택하면 각각 기존 `metropolitan` 또는 `other` 기준으로 참고 계산하며, 이는 통합지역의 공식 기준으로 검증된 값이 아니다. 권역을 선택하지 않은 입력은 기본 계산에서 지역 기준을 임의 추정하지 않고 `needs_review`로 처리한다. 입력 확인 화면에서 ‘근사 계산’을 명시적으로 선택한 경우에만 권역 미선택 상태에 ‘그 밖의 지역’ 기준(기본재산 공제 5,300만 원, 주거 한도 1억 1,200만 원)을 임시 적용한다. 근사 적용 사실을 결과에 표시하고 사업별 비교 상태는 `needs_review`/`unknown`으로 유지한다.

현재 계산 순서는 다음과 같다. (주거 분류 134쪽, 보증금 138쪽, 금융재산 148쪽, 부채 163쪽, 기본공제·환산 165~166쪽)

1. 실제 거주하는 1호의 주거용재산을 분류한다. 주거용 임차보증금은 계약 금액의 95%를 반영하고 지역별 주거 한도를 넘는 금액은 일반재산에 넣는다.
2. 월 4.17% 적용 차량은 일반재산에 합산한다. 월 100% 차량은 별도로 둔다.
3. 금융재산에서 가구당 생활준비금 500만 원을 공제한다.
4. 기본재산액을 주거용 → 일반 → 금융 순서로 한 번 공제한다.
5. 인정되는 부채도 주거용 → 일반 → 금융 순서로 공제한다. 기본재산과 부채 모두 월 100% 차량에는 공제하지 않는다.
6. 남은 주거용 1.04%, 일반 4.17%, 금융 6.26%, 별도 차량 100%를 적용해 월 소득환산액을 합산한다.

소유 주택은 시세를 그대로 입력하는 방식이 아니라 공적 평가액을 확인해야 한다. 소유 주택과 임차보증금을 동시에 입력하면 실제 거주 주택과 일반재산의 분류가 필요하므로 추가 확인 처리한다.

`bank`·`public` 입력은 사용자가 확인한 인정 부채라는 전제의 참고 계산이다. 금융기관 대출이라고 모두 인정되는 것은 아니다. 사업자 대출, 마이너스통장, 단기 카드론, 보증채무, 사적 차용증 등은 각각 제외·증빙 규정이 있으므로 대출 잔액을 무조건 합산하지 않는다. 임대보증금 반환채무도 2026년 1호 원칙과 기존 대상자 유예 등 확인 사항이 있다. 현재 `other` 부채가 있으면 자동 비교를 중단한다. (160~164쪽)

### 자동차

일반 용도의 차량 1대에 대해 다음 기본 조건만 자동 적용한다. 차량 가액은 구입가가 아닌 공적 평가액이다. (149, 154쪽)

| 차량 | 월 4.17%로 일반재산에 합산하는 기본 조건 |
| --- | --- |
| 승용차 | 2,000cc 미만이고, 차령 10년 이상 또는 가액 500만 원 미만 |
| 다인·다자녀 승용차 | 6인 이상 가구 또는 18세 미만 자녀 2명 이상, 2,500cc 미만, 7인승 이상, 차령 10년 이상 또는 가액 500만 원 미만 |
| 소형 이하 승합·화물차 | 법정 소형 이하 분류이며 차령 10년 이상 또는 가액 500만 원 미만 |

위 조건에 해당하지 않는 일반 차량에는 월 100%를 적용한다. 차령은 단순 구입 후 경과일이 아니라 최초등록일·제작연도 등 공식 규정을 확인해야 한다. 전기차는 배기량 0cc를 일반 승용차 기준에 대입하지 않고 법정 차급 등을 확인한다.

생업·장애인·보철용, 여러 대 보유, 차량 분류 불명, 압류·멸실·운행정지·처분예정 등은 추가 확인한다. 장애나 생업 용도를 선택했다는 사실만으로 차량을 제외하지 않는다. 생계급여 차량 가액에서 전기차 정부보조금을 임의 차감하지 않는다. (149, 151~156쪽)

## 4. 차상위계층 확인사업의 차이

### 소득·차량 입력 기준 보완

실제 공고와 지침의 쪽수·정의는 [2026년 입력 근거 조사](finance-input-evidence-2026.md)에 별도로 기록했다. 근로소득은 세전 기준, 사업소득은 필요경비를 뺀 소득세·개인지방소득세 차감 전 금액을 안내한다. 기초생활 지침의 비과세 예외·공적자료 우선순위 때문에 급여명세서 총지급액과 최종 심사 금액은 같지 않을 수 있다. 상시근로·일용근로·연금 등의 조회 기간도 서로 다르다.

입력한 소득이 양수인데 세후·매출액·기준 미확인이면 금액을 변환하지 않고 소득 합계와 관련 비교를 미확인으로 남긴다. 값이 0이면 해당 소득의 기준 확인은 요구하지 않는다. 연금·기타소득을 모두 하나의 세전·세후 기준으로 단정하지 않는다.

차량의 명의, 등록상 영업용/비영업용, 실제 사용 목적, 전체 가액의 공적 조회 여부, 저공해차 보조금을 분리한다. 국민임대의 등록상 영업용 차량도 총자산에 포함하며 별도 비영업용 승용차 한도에서만 제외한다. 생업·장애·보철용, 공동명의, 리스, 시세 추정, 보조금 차감은 증빙·산식이 완성되지 않아 자동 면제·지분 할인하지 않는다. 원입력 차량 합계는 단순 참고값이며 공고 심사 자산액과 구분한다.

기존 저장 JSON에 새 소득·차량 기준 필드가 없으면 `unknown`으로 읽고 재확인한다. 임의로 세전 소득·공적 차량가액·본인 단독 명의를 채우지 않는다.

## 6. 공고와 계산 규칙을 연결하는 요건

`evaluate_policy(profile, criteria)`는 내부 연결 함수이며, 사용자가 `reviewed`를 보내 심사를 통과시키는 공개 API가 아니다. 실제 공고 저장소·수집 파이프라인이 아래 내용을 검토해 제공해야 한다.

1. 공식 공고 원문, 적용 연도·모집일·공급유형을 확인하고 `source_url`, `evidence`에 근거 문구와 쪽수·표를 남긴다.
2. 함께 심사할 사람의 범위를 확인한다. 현재 자동 비교는 `household`만 지원하며 본인·부부·부모 등 별도 범위는 추가 검토한다.
3. `income_basis`, 소득 비율, `asset_basis`, 자산·차량 한도를 확인한다. 단순 월소득·소득인정액·도시근로자 기준을 구분하고 차량 및 부채 처리 방식까지 일치해야 한다.
   단순 합계 규칙은 `debt_treatment`로 부채 미차감 또는 금융·공공기관 부채 차감을 명시한다. 개별 차량 한도는 `vehicle_basis`로 전체 차량 최대가액인지 승용차 최대가액인지 지정한다. 미확정 값에는 자동 비교를 적용하지 않는다. 현재 비교 연산은 상한 이하(`<=`)만 지원하므로 미만·구간·별도 예외가 있는 공고에는 이 규칙을 연결하지 않는다.
4. 차상위 우대나 별도 자격이 있으면 `near_poor_treatment`에 표시한다. 현재 이 분기는 자동 처리하지 않는다.
5. 검토 후에만 `review_status="reviewed"`를 부여한다. HTTPS 주소 형식 검사는 출처가 공식 기관이라는 검증을 대신하지 않는다.

현재 생계급여 연결은 32% 소득인정액 기준만, 국민임대 연결은 구현된 일반 소득·자산·차량 한도가 모두 일치할 때만 사용한다. `gross-median-2026`도 공고의 소득·자산 정의가 입력 합계 산식과 정확히 일치하는 경우에 한한다. 차상위 확인사업은 공고 자동 비교 규칙으로 연결하지 않았다.

국민임대 연결은 부채 처리 `bank_public`과 차량 한도 범위 `non_commercial_passenger_max`도 명시적으로 일치해야 한다. `all_individual_max`·`passenger_max`·미확정 기준을 비영업용 승용차 한도로 대신 계산하지 않는다. `non_commercial_passenger_max`는 현재 국민임대 고정 규칙의 식별값이며 단순 중위소득 규칙에서는 별도 구현 없이 사용할 수 없다.

LLM은 검토된 결과와 부족한 정보를 설명할 수 있으나 산식이나 예외를 임의로 선택하지 않는다. `within`·`over`는 입력한 수치와 한도의 비교이며 자격 판정이 아니다. 누락·미지원 조건은 `unknown`과 `needs_review`로 반환하고 `eligibility_decision`은 항상 `null`이다. 규칙 연결 함수의 존재만으로 기존의 모든 공고가 재무 검토를 마쳤다는 뜻은 아니다.

## 7. 입력, 저장, 배포

모르는 금액은 `null`, 없는 금액은 `0`으로 구분한다. 금액은 0 이상의 원 단위 정수다. 가구원 수와 소득 입력 인원은 일치해야 한다. 가구 범위 미확인, 사용자가 선택한 추가 확인 사항, 미지원 연도 등은 자동 비교를 중단한다. 원자료를 보관하고 각 사업이 이를 독립적으로 계산하며, 한 사업의 소득인정액을 다른 사업의 입력으로 재사용하지 않는다.

| API | 이용·저장 방식 |
| --- | --- |
| `GET /v1/finance/rules` | 비회원 이용 가능. 지원 연도·버전·공식 출처 제공 |
| `POST /v1/finance/calculate` | 비회원 이용 가능. 요청값을 계산해 반환하며 이 경로에서는 DB에 저장하지 않음 |
| `GET /v1/finance/profile` | 로그인한 계정의 저장값만 조회하고 현재 규칙으로 다시 계산 |
| `POST /v1/finance/profile` | 로그인 세션, 기존 인증 요청 보호, 명시적인 `consent: true`가 있어야 저장 |
| `POST /v1/finance/profile/delete` | 로그인한 계정의 저장값 삭제 |

서버는 세션에서 계정 ID를 정하며 호출자가 다른 계정 ID를 지정하지 못한다. `account_financial_profiles`에는 계정별 최신 원자료 JSON 한 건과 저장 시각을 보관하고 계산 결과·과거 입력 이력은 저장하지 않는다. 다시 저장하면 같은 계정의 입력을 갱신하며, 로그인 만료·로그아웃으로 저장값을 삭제하지 않는다. 자동 보관기간 만료·계정 탈퇴는 미구현이다. 비회원 입력과 저장 전 초안은 프론트 메모리에서 관리하며 금융정보를 `localStorage`·`sessionStorage`에 보관하지 않는다. 회원의 저장·불러오기·삭제와 추천 정보 반영은 명시적인 동작으로 구분한다.

개발·테스트에서 `DB_ENABLED=false`이면 로그인된 회원의 첫 금융정보 요청에서 기존 인증 SQLite에 금융 테이블을 추가한다. 공개 계산은 인증 저장소를 만들지 않는다. MySQL은 `DB_ENABLED=true`로 설정하고 backend에서 `python -m app.modules.finance`를 명시적으로 실행해야 한다. 이 명령은 기존 인증 초기화와 금융 테이블 생성을 수행하며 HTTP 요청은 MySQL 테이블을 자동 생성하지 않는다. [초기화 명령·저장 계약](../app/modules/finance/readme.md), [API 관리대장](../../api-management.md).

현재 금융 스키마 초기화는 `create_all` 기반이며 기존 금융 테이블의 구조 변경·저장 원입력 버전 이관을 처리하는 마이그레이션 체계는 없다. 실제 MySQL 금융 저장 검증도 후속 작업이다. 공식 기준이 바뀌면 표뿐 아니라 입력 계약·예외·공고 연결을 검토하고 규칙 버전을 갱신한다. 조회할 때 현재 코드로 다시 계산하므로 이전에 표시한 결과가 그대로 보존되는 것은 아니다.

## 8. 남은 검토 범위

- 부양의무자, 별도 보장가구·가구 분리, 공적 소득의 제외 항목, 학생 재학 기간, 북한이탈주민 특례, 직업재활 참여소득 구분.
- 장기금융저축·자산형성지원금 등 추가 금융 공제, 처분·증여재산, 주택연금, 임대보증금 반환채무와 부채별 증빙·유예.
- 차량의 법정 차급·차령, 가구별 인정 대수, 생업·장애·보철·압류·멸실 등 특례. 차상위의 2,500cc 미만 차량 규정은 생계급여와 분리할 것.
- 차상위 추가 지출공제의 금액·기간·증빙, 각 사업의 차상위 우대·별도 자격.
- 공고별 가구 범위, 소득 조회 기간, 자산 평가 기준일, 공급 유형, 출생 자녀·맞벌이 가산, 공식 출처 및 검토 이력의 저장·갱신.

이 항목들은 사용자 선택이나 LLM 추론만으로 충족되었다고 간주하지 않는다. 현재 기본 계산의 참고값과 실제 담당 기관의 심사 결과는 다를 수 있다.
