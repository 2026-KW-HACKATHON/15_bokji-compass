# 광운대·월계동 검색과 필수 공개 데이터

2026-10-08. 실제 서비스 DB에 공개 개정 562건이 있었지만 광운대학교 원문의 개정은
0건이었다. `database/seeds/kwangwoon_notices.json`의 190건은 파일에만 있었고,
월계동 생활 서비스도 별도 지역 서비스 화면에서만 읽었다. 검색 기관 어휘를 공개
공고에서 얻으므로 광운대 게시기관 검색까지 실패했다.

## 수정한 동작

- `광운대에서 올린 장학금을 찾아줘`는 광운대학교 게시기관과 장학 분야를 함께 검색한다.
  공개 데이터가 없는 학교의 명시적 게시기관 요청도 기관명을 보존하고 수집 상태 경고를
  반환한다. 게시기관 이름이 사라진 요약이나 다른 기관의 일반 장학금으로 대체하지 않는다.
- `화도`의 `도`를 조사로 지워 검색 조건을 잃지 않는다. `받을 수 있는`, `월계!동`처럼
  입력한 문장에서는 요청 표현·단어 내부 구두점을 정리한다.
- `월계동 지원`은 실제 지역 범위 인용이 있는 노원구 전체 서비스도 찾는다. 공식 지역
  스냅샷의 상위 지역 이름을 사용하며 같은 이름의 다른 지역을 하나로 결정하지 않는다.
  특정 행정동의 서비스를 다른 법정동에 적용되는 것으로 간주하지 않는다.
- 지리적 확장은 지정 지역 개요의 실제 원문 인용이 있을 때만 적용한다. 연락처나 기관
  주소만으로 거주 조건·서비스 범위를 만들지 않는다. 단어 검색 모드는 그대로 유지한다.

## 데이터 보충과 검사

backend에서 실행한다. 스키마가 있어야 하며 DB 접속은 기존 `.env`를 사용한다.

```powershell
.\.venv\Scripts\python.exe -m app.modules.storage ensure-focus-data
.\.venv\Scripts\python.exe -m app.modules.storage ensure-focus-data --check
```

`ensure-focus-data`는 공식 광운대 원문 190건과 현재 검증된 지역 서비스 20건을 읽고
전체 계약 검증을 먼저 수행한다. 기존에 분석된 광운대 공고 2건은 기존 분석을 이용한다.
나머지는 원문 검색용 개정으로 저장하며 조건·자격 논리는 미확정, 자동 자격 판정은
비활성으로 유지한다. 지역 서비스는 제공 범위를 본문과 지역 개요의 인용에 보존한다.
신청 날짜는 기존 원문 날짜 해석만 사용하고 현재 접수 중이라는 상태를 만들어 내지 않는다.
지역 서비스의 원문 요약·확인일·출처는 `reference/local_services/services/*.json`에 있다.

동일한 정책 키가 어느 상태로든 이미 존재하면 건너뛴다. 광운대 공지는 공식 공지 경로의
DUID가 같은 경우 목록 페이지·검색 인자·모바일 호스트가 달라도 중복으로 처리한다.
기존 수정·분석 개정·수동 비공개를 덮어쓰거나 다시 공개하지 않는다. 전용 MySQL 잠금은
동시 보충 작업을 직렬화하고 각 공고의 저장·공개는 기존 저장소 트랜잭션을 사용한다.

`public.ensure_focus_data(repository)`는 `{added,skipped,coverage}`를 반환하며 명시적으로
공개를 허용한 `PolicyRepository(auto_publish=True)`가 필요하다. 외부 HTTP·LLM 호출은 없다.
`public.focus_coverage(repository)`는 읽기 전용 `{ready,checks:[{query,count}]}`를 반환한다.
여섯 필수 검색 중 하나라도 0건이면 CLI는 종료 코드 1로 누락을 보고한다. 검수자가 숨긴
필수 공고를 자동으로 되살리는 대신 점검 실패로 남긴다.

명시적 `storage init` CLI도 스키마 초기화 후 위 보충·검사를 실행한다. 서버 시작이나
공개 조회 요청에서는 데이터·스키마를 변경하지 않는다. 새 환경·DB 복원 후 동일 명령을
실행하여 시연에 필요한 데이터가 빠졌는지 확인할 수 있다. 이미 있는 데이터의 최신화는
기존 광운대 자동 수집과 지역 서비스 검증 절차를 사용한다.

## 실제 검증

실제 DB에 210개 공고를 추가했고 다시 실행했을 때 `added=0,skipped=210`이었다.
다음은 원문·종료 공고를 포함한 검색 건수이며 현재 신청 가능한 공고 수를 뜻하지 않는다.

| 검색 | 건수 |
| --- | ---: |
| 광운대에서 올린 장학금을 찾아줘 | 190 |
| 광운대학교 화도 장학금 | 26 |
| 광운대학교 동해 장학금 | 20 |
| 월계동 지원 | 8 |
| 월계1동 복지 상담 | 3 |
| 노원구 돌봄 | 3 |

격리된 SQLite의 실제 번들 검색, 공개 HTTP 응답·인용, 단어 검색 회귀,
달력·대화·저장소 검증은 422개 통과·1개 선택적 실제 DB 검사 생략이다.
검증 명령은 `tests/test_focus_data.py`, `tests/test_smart_search.py`,
`tests/test_policy_search.py`, `tests/test_policy_calendar.py`,
`tests/test_assistant_dialogue.py`, `app/modules/storage/tests`를 pytest로 실행한다.
Windows 임시 폴더 권한 충돌을 피하려면 프로젝트 `tmp` 안의 새 `--basetemp`를 지정한다.

관리 스크립트로 백엔드만 재시작한 뒤 내부 웹 프록시와 실제 공개 도메인
`https://bokji.commitnaru.com`에서 각각 8개 검색을 확인했다. 위 여섯 검색 외에
`광운대에 있는 화도 동해 장학금`은 18건, `월계!동에서 받을 수 있는 지원을 찾아줘`는
8건이다. 16개 응답 모두 기존 웹 `parsePolicyPage`로 검색 설명과 원문 인용을 읽었다.
웹 정적 파일·모바일 빌드·DB 설정·공개 터널은 변경하지 않았다.
