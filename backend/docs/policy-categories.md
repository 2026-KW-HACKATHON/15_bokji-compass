# 공고 분야와 기존 공고 재분류

2026-10-07: 농림축산·어업과 사업·창업을 추가했습니다. 공개 목록·상세·캘린더·관심 분야
추천·관리자 편집·공개 검수에 같은 분야를 사용합니다. 카테고리·태그 필터, 총 개수와
페이지 이동은 카드에 표시되는 재분류 결과를 기준으로 처리합니다.

## 공유 계약

`app.contracts.categories.PolicyCategory`와 `POLICY_CATEGORIES`는 8개 분야를 정의합니다.

| 분야 | 주된 지원 내용 |
| --- | --- |
| 생활·금융 | 개인·가구의 생활 안정, 생계비, 일반 금융 지원 |
| 주거 | 개인·가구의 주택, 전세·월세, 주거 지원 |
| 일자리 | 취업·구직·고용·근로 지원 |
| 교육 | 장학금, 학자금, 학비·교육 지원 |
| 건강·돌봄 | 의료·건강·돌봄·양육·복지 지원 |
| 문화 | 문화·여가 지원 |
| 농림축산·어업 | 농업·임업·축산·어업 생산, 경영, 정착, 시설·장비 지원 |
| 사업·창업 | 소상공인·기업의 창업, 경영, 판로, 사업 자금 지원 |

`PolicyDisplayCategory`와 `POLICY_DISPLAY_CATEGORIES`는 화면·관리자·추천 관심 분야에
미분류 표시 `기타`까지 포함한 9개 값을 제공합니다. 파싱 출력은 미분류일 때 기존처럼
`category=null`과 `unresolved` 사유를 사용합니다. `PolicyOverview` JSON Schema는
공유 Literal에서 생성하므로 단건·묶음 파싱 모두 새로운 분야를 허용합니다.

대출·보증·보조금이라는 지급 방식만으로 산업 지원을 생활·금융으로 묶지 않습니다.
농업인 자녀 장학금·중소기업 취업연계 장학금은 교육, 중소기업 장기근속자의 주택
우선공급은 주거처럼 주된 지원 목적을 우선합니다.

## 저장된 공고의 즉시 반영

`app.modules.storage.categories.effective_category(record) -> str`은 `category`,
`source_json`, `draft_json`을 가진 저장 개정에서 화면 분야를 반환합니다.
`effective_category_expression(catalog) -> SQLAlchemy expression`은 `category`, `title`,
`source_json`, `draft_json` 열이 있는 SQL 하위 질의에 동일한 규칙을 적용합니다.
SQL 식은 라벨 없는 식이며 필터·총 개수·페이지 이동 전에 적용합니다.

1. `_editor_category` 또는 관리자 분류 사유가 있으면 수동 선택을 유지합니다.
   새 2개 분야로 이미 분류한 모델 결과도 유지합니다.
2. 농업 창업과 주택 구입을 함께 지원하는 귀농·귀산촌 정착 사업은 농림축산·어업입니다.
3. 장학·학자금·주택·돌봄·취업·고용·근로·생활 안정 등 개인 지원 목적이 제목에 명시되면
   기존 분야를 유지합니다. 소비자 페이백, 소년소녀가정, 주민 지원, 대지급금도 보호합니다.
4. 제목의 명확한 농업·축산·어업·산림 사업·작물·기업·창업 지표로 과거 분야를 보완합니다.
   농산물 GAP 시설, 스마트축산단지, 과실 생산단지는 과거 건강·주거·일자리 분야에서도
   농림축산·어업으로 표시합니다.
5. 과거 생활·금융·기타에서 제목만으로 판단되지 않으면 사업 목적과 실제 지원 내용의
   산업 지표를 확인합니다. 일반 지원 대상의 직업 목록은 분류 근거로 사용하지 않습니다.
   명확한 `농림축산식품 업종/분야` 제한만 일반적인 기술 창업 제목의 농업 분류를 보완합니다.

제목과 사업 설명의 공백을 유지해 `대한 우선심사`가 `한우`로, `우수 산업기업`이 수산업으로
오인되는 것을 방지합니다. 원문 전체·기관 이름·공급자 분류도 자동 재분류 근거로 사용하지
않습니다. 다른 사업 안내나 기관 이름 때문에 무관한 분야로 바뀌는 것을 방지합니다.

조회 시 분류만 보완하며 DB 원문·인용·기존 분석 JSON·개정 이력을 수정하지 않습니다.
스키마 마이그레이션·LLM 재호출·재수집 없이 기존 공개 공고에 적용됩니다. 규칙으로
판단하기 어려운 공고는 기존 분야를 유지하며 관리자에서 수동 수정할 수 있습니다.

## 관리자와 파싱

`storage.editor.PolicyEditInput`은 공유 화면 분야를 검증합니다. `read_policy_edit`의
`categories`는 9개 값을 반환하며 관리자 화면은 이 값으로 선택 항목을 만듭니다.
관리자가 저장하면 선택한 분야를 근거와 함께 새 개정에 남기고 이후 읽기 규칙이 보존합니다.

단건 개요 프롬프트는 `welfare-overview-v5`, 묶음은 `welfare-batch-v2`입니다.
8개 분야와 지급 방식보다 주된 지원 목적을 우선하는 지시를 사용합니다. 새로운 처리
signature로 파싱하며 기존 인용·자격 판정 검증을 유지합니다.
