# 메인 공고 추천의 대상 확인

2026-10-07. 담당: 백엔드 matching. 구현 파일은
`app/modules/matching/public.py`, 검증은 `tests/test_matching.py`입니다.

## 해결한 문제

이전 추천은 나이·소득 등의 일부 개별 조건이 일치하거나 조건이 미상인 공고를 함께 반환했습니다.
그 결과 자립준비청년·장애·한부모 등 핵심 대상 여부가 확인되지 않아도 메인에 추천될 수 있었습니다.
지금은 공개 최신 개정의 완전하고 활성화된 자격 논리가 실제 입력 정보로 성공한 경우에만 개인
후보로 사용합니다. 기준 시점·심사 가구 범위·소득 산정 정의가 확인되지 않으면 통과로 추정하지 않습니다.

조건 all/any/not의 기존 3값 평가를 유지합니다. 필요한 입력은 공고마다 다릅니다. 나이 조건만 있는
공고는 나이로 비교할 수 있으며, OR의 성공 분기와 관련 없는 정보를 모두 요구하지 않습니다.
개별 제한 없음(state 0)은 사용자 정보에 따른 일치 근거가 아닙니다.

## 정보 부족 시 동작

빈 정보로도 자격 논리가 성공하고 전체 대상의 명시적 원문 근거가 있는 신청 중 공고만 일반
안내로 사용합니다. 문화비·교통비라는 분야나 제목은 조건 없음의 근거가 아닙니다. 원문에 수급·소득·
지역·특수 대상 조건이 있으면 정규화 필수 자격에서 확인해야 합니다. 확인 가능한 후보가 없으면
빈 `items`와 정보 입력·전체 공고 확인 안내를 반환하며 합성 공고를 추가하지 않습니다.

원문 대상 누락 검사는 제목, 공급자의 eligibility/selection, 공지의 명시적인 지원 대상/신청 자격
줄을 확인합니다. 우선/우대/가점 줄은 필수 대상으로 바꾸지 않습니다. 이 검사는 보수적 누락 방지
장치이며 모든 원문의 의미를 완전히 판정하는 NLP 기능은 아닙니다. 공개·정규화 검토의 책임을
대신하지 않으며 지원되지 않는 특수 대상 정보는 추정하지 않습니다.

상시/연중이나 현재 신청 날짜가 확인된 공고만 메인에 올라갑니다. 신청 종료·시작 전·기간 미확인,
날짜의 제외 경계, 미비교 신청 조건, 예산 소진률 100%, 검증 실패, 비활성·부분 정규화는 제외합니다.
전체 탐색의 공개 공고 조회 기능은 유지합니다.

## 프론트 응답과 인기도·예산

`mode`는 personalized/popular/general/profile_required이며, `profile_sufficient`는 실제 정보로
공고의 자격 논리를 충분히 비교할 수 있었음을 나타냅니다. 충분한 입력으로 불일치를 확인했지만
일치하는 후보가 없으면 personalized/true/빈 items와 현재 조건에 맞는 공고가 없다는 안내를
반환합니다. 이를 정보 부족으로 안내하지 않습니다. `guidance`는 항상 설명을 제공하고 일반 후보에는
정보가 부족해 보여준 공고임을 알립니다. `missing_fields`는 미확인 공고 조건의 정규화 필드 키입니다.
기존 summary/items/matching/eligibility_decided=false/profile_source/truncated도 유지됩니다.

실제 공급자의 누적 조회수만 안전한 후보 내 정렬에 사용합니다. 최근 추세·사이트 이용자 수·신청
인원으로 표현하지 않습니다. 예산 사용률은 출처에 정확한 값이 있을 때만 선택적으로 붙입니다.
해당 수치의 공급자·근거·갱신 시각은 별도 presentation/ingestion 계약을 따릅니다.

## 검증

격리 SQLite와 합성 원문으로 특수 대상 누락, 정보 부족 일반 안내, 개별 제한 없음 오인 방지,
공고별 입력 충분성, OR/NOT, 소득/지역이 있는 문화·교통 지원, 비활성·미상 조건, 과거/미래/미상
신청 기간과 제외 경계, 공식 조회수 정렬, 예산 소진 제외를 검사합니다. 실제 사용자나 운영
공고의 자격 판정을 확정하지 않으며 정책 공개/자동매칭 상태를 변경하지 않습니다.
추천 회귀 25개와 matching/test_matching.py Ruff 검사를 통과했습니다. 실제 ingestion의
collection_records와 Gov24 변환 원문을 격리 DB에 넣은 통합 검사로 누적 조회수 정렬 및 원문
예산 비율 연결도 확인했습니다. 외부 API·운영 DB·LLM은 호출하지 않았습니다.

```powershell
# backend 폴더
.\.venv\Scripts\python.exe -m pytest -p no:cacheprovider tests/test_matching.py -q
.\.venv\Scripts\python.exe -m ruff check --no-cache app/modules/matching tests/test_matching.py
```
