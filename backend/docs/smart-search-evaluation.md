# 의도 검색 수용 평가

`tests/test_smart_search.py`는 격리된 SQLite에 공고를 직접 구성해 공개 목록·달력·HTTP API를
검증합니다. 운영 데이터베이스 쓰기나 외부 모델 호출 없이 실행합니다. 단순히 해석 함수의
출력을 복사한 테스트 대신, 비슷한 공고를 함께 놓고 포함·제외되어야 하는 결과를 비교합니다.

| 입력의 의미 | 반드시 확인하는 결과 |
| --- | --- |
| 광운대에서 올린 장학 공고 | 광운대가 게시한 타 학교 장학 공고도 포함하고, 외부 기관이 게시한 광운대 대상 공고와 구분 |
| 광운대생 받을 돈 / 학비 보태주는 지원 | 학교가 명시된 대상 공고, 해당 학교의 본교·KLAS 문맥, 학교 제한 없는 대학생 지원을 함께 탐색 |
| 광은대 / kwangwoon / 광운 대 | 확인된 기관 이름을 사용해 별칭·띄어쓰기·보수적인 오타 보정을 처리하고 보정 사실을 표시 |
| 서울시가 올린 광운대 학생 장학금 | 서울시 게시기관 조건과 광운대 학생 관련 조건을 모두 충족; 전국 대학생 공고도 후보가 될 수 있음 |
| 광운대나 서강대 / 광운대 말고 서강대 | 같은 역할의 대안은 합치되, 제외한 학교를 긍정 조건으로 되살리지 않음 |
| 우리학교 등록금 너무비싸 | 확인되지 않은 학교 소속을 만들지 않고 일반 대학생 지원도 탐색 |
| 알바·근로 말고 / 갚기 싫어 | 근로 필수 공고와 상환해야 하는 대출을 제외하고 무상 지원을 유지 |
| 청년 월세 / 백수인데 월세낼 돈이 없어 / 회사 다니는데 월세 | 주거 목적과 대상 문맥을 함께 읽고, 취업 공고를 월세 지원으로 혼동하지 않음 |
| 병원비 지원, 근로·대출 말고 | 의료비 목적을 유지하며 근로와 상환 각각의 의무·부정 표현을 구분 |

재게시물의 `우리대학`을 게시기관의 학생 대상으로 무조건 연결하지 않습니다. 다른 대학의
명시적인 대상 조건과 함께 등장하면 그 문맥을 확인해야 합니다. 문의처·신청 URL은 대상
근거가 될 수 없으며, 추출된 조건의 인용 근거가 해당 메타데이터를 가리켜도 검색 근거로
승격하지 않습니다. 카드의 이유와 인용은 허용된 원문 필드에 실제로 존재해야 합니다.
긴 본문에서 띄어쓰기를 정규화해 찾은 대상도 그 대상이 등장하는 원문 구간을 인용해야
하며, 본문 첫 부분의 무관한 문구를 근거로 보여 주지 않습니다.

기관 어휘는 최신 공개 공고를 기준으로 유지합니다. 카테고리·지역 필터로 해당 학교의 공고가
후보에서 사라져도 사용자가 입력한 학교 이름의 해석이 달라지면 안 됩니다. 학교 이름이
직접 없는 전국 대학생 지원도 후보로 남을 수 있어야 합니다.
공개 공고에 학교 이름 자체가 없더라도 `광운대생`·`광운대 다니는데`처럼 학교 소속을
명시한 입력은 전국 대학생 지원을 찾을 수 있어야 합니다. 입력한 학교 이름을 공개 원문에서
확인하지 못했다는 안내를 표시하며, 확인되지 않은 이름을 다른 학교로 임의 보정하지 않습니다.

결과의 관계는 신청 자격의 확정이 아닙니다. `student_general`은 전국 대학생 대상 근거가
있다는 뜻이며, 소득·학적·성적·주소 등 개인 조건을 확인했다는 뜻이 아닙니다. 알 수 없는
학교, 프로필 또는 신청 날짜를 검색이 만들어 내지 않는지도 검증합니다.

조회 수가 매우 높은 무관한 공고와 오래된 관련 공고를 함께 넣어 전체 후보를 검색한 후
정렬·개수·페이지를 계산하는지 확인합니다. 최신 공개 버전만 검색하고 더 최신인 비공개
초안은 제외합니다. 목록과 달력의 검색 결과, 날짜가 없는 공고의 분리, 인기·최신·이름
정렬의 명시적 선택, 정확한 단어 검색 범위의 우선 적용도 검증합니다.

기관 이름만 입력하거나 기관 관련 지원을 입력한 뒤, 게시기관·관련 공고 선택지를 다시
요청해도 의미 검색을 유지해야 합니다. `search_relation=publisher|related` 결과 개수는
처음 표시한 선택지 개수와 일치해야 하며, 관련 공고에는 학교 이름이 직접 없는 본교 문맥의
공고도 포함됩니다. 정확한 단어 검색인 `search_scope`로 바뀌어 이 공고를 놓치면 안 됩니다.
달력 선택지의 개수는 요청한 달에 겹치는 날짜 있는 공고만 세며, 날짜가 없는 공고는
기존 `undatedTotal`에 별도로 남습니다.
학교를 확인할 수 없다는 안내는 API와 사용자 화면에서 사용하는 `search.warnings`로
전달합니다.

현재 해석은 공고에서 얻은 기관 어휘와 정의된 지원 분야·한국어 표현을 사용하는 로컬
방식입니다. 이 수용 사례를 통과해도 임의의 구어 표현을 모두 이해한다는 증거가 되지는
않습니다. 새로운 분야나 말투를 지원할 때에는 기존 사전에 없는 표현과 유사하지만 무관한
공고를 함께 평가하고, 결과의 정확도와 누락을 각각 확인해야 합니다. 운영 공고 전체의
정확도·재현율이나 대규모 데이터에서의 지연 시간을 이 테스트만으로 주장하지 않습니다.

추가 평가에서는 분야별로 게시기관·명시 대상·문맥 대상·일반 학생 지원·단순 언급의 정답을
나누고, 상위 결과의 정확도와 관련 공고의 재현율을 별도로 기록합니다. 근로·상환 제외,
다중 기관, 알려지지 않은 학교는 별도 오류 묶음으로 확인합니다. 같은 문장을 규칙에 추가한
뒤 그 문장만 재검증하는 대신, 보류한 표현과 실제 공고에서 일반화 여부를 확인합니다.

2026-10-07 최종 검증에서 수용 사례 49개가 통과했고, 해당 테스트 파일의 Ruff 검사도
통과했습니다. FastAPI 테스트 클라이언트의 기존 폐기 예정 API 경고 2건이 출력되었습니다.
