# 코드·Codex CLI 복지 분류 실증 결과

실행일: 2026-09-21. 실제 공개 API 표본 6개, Codex CLI 실제 호출 1회. 정책별 수많은 분기를 작성하기보다 공통 코드 처리 후 의미 해석을 LLM에 위임하는 방향 검증.

이 문서는 당시 실증 기록입니다. 2026-09-22 추가된 범용 파서·Luna/Terra 설정·현재 저장 범위는 [파싱 사용법](raw-parsing.md)과 [구현 상태](implementation-status.md) 참조.

표본은 앞선 조사에서 실제 조회한 첫 페이지 5건과 복지로 상세 1건 재사용. 추가 외부 복지 API 호출 없음. 전체 정책을 대표하는 무작위 표본이나 별도 검증 데이터셋은 아님. 2/17은 이번 보수적 규칙의 자동 처리 범위이며 코드의 이론적 한계나 정확도 수치와 구분.

## 코드로 가능한 부분

- 공급자 필드 매핑·ID 보존·원문 위치·스냅샷 해시 생성.
- 명확한 전체 문자열 규칙: `상시신청`, 완전한 ISO 날짜 구간, 주체가 명시된 단독 나이 조건.
- 누락은 `not_stated`로 기록. 신청기간·자격 제한 없음으로 추정하지 않음.
- 작은 패턴 사전으로 나이·소득·재산·가구 등 **다중 태그 힌트** 추출.
- 출력 스키마·원문 인용·참조·자료형·경계 검사.

실증 코드에 정책 ID·제목별 분기 없음. 조건을 처리할 공통 규칙이 확실하지 않으면 기본 경로를 LLM으로 설정. 임의 점수 임계값이나 `if` 개수 기준 대신 주체·논리·기준일을 코드가 충분히 해석했는지로 판단.

나이 단독 규칙도 기준일을 모르면 `reference_date=null` 후보만 반환. 코드 처리 완료는 정책 전체 자격 확정을 의미하지 않음.

## 코드 힌트의 한계와 LLM의 보완

| 실제 정책 | 코드만으로 부족한 점 | 실제 Codex 결과 |
| --- | --- | --- |
| 유아학비 지원 | 보호자·아동·저소득 추가지원·외국인 예외 혼재 | 3~5세를 `child`에 연결, 일반·추가·제외·신청 절차 그룹 구분 |
| 근로·자녀장려금 | 가구유형별 소득상한·가구 재산·국적 예외 혼재 | 가구 재산 `lt 240000000`, 기준일 `전년도 6월 1일` 후보 추출 |
| 월세자금보증 | 신청자·부모·부부 소득과 우대형 여러 경로 혼재 | 부모 소득 `parents/lte/60000000`, 부부 연소득은 `couple`로 분리 |
| 친환경 에너지절감장비 | 장비별 우선순위와 자격·예외가 한 문서에 존재 | `priority` 그룹·역할 분리, 단종 시 상위마력 허용 예외 구분 |
| 해양사고 국선 심판변론인 | 여러 사유 중 하나 + 변론인 부재의 공통 요건 | 공통 `all`, 대안 `any` 구분. 쉼표로 연결된 빈곤 조건은 미해결 유지 |
| 장애인자립자금대여 | 가구 소득인정액·신청자 나이·금융 심사·다른 상품 안내 혼재 | `household/gt/50`, `household/lte/100`, `applicant/gte/19` 구분. 다른 상품을 본 사업의 예외 자격으로 합치지 않음 |

특히 월세 계약의 보증금을 단순 키워드 코드는 `assets`로 감지하지만, LLM은 계약 보증금과 가구 총자산이 다르다는 점을 미해결/검토 메모에 기록. 키워드 검출은 후보 검색에 활용하고 비교할 실제 필드는 의미 분석 후 확정하는 편이 적절.

## 사전 선정한 8개 비교 항목

1. 유아 3~5세의 주체는 신청 보호자가 아닌 아동.
2. 가구원 전체 재산 2억4천만원 **미만**.
3. 부모 소득 6천만원 **이하**, 신청자 소득과 분리.
4. 복지로 표본의 신청자 나이 19세 **이상**.
5. 가구 소득인정액의 중위소득 비율 50% **초과**.
6. 같은 비율 100% **이하**.
7. 장비 지원 우선순위는 일반 자격조건과 구분.
8. 해양사고 선정기준의 ‘어느 하나’는 대안 관계.

8개 일치 확인. `review.py`는 해당 부분의 필드·주체·연산자·값 또는 그룹 유형을 검사하는 표본 점검기. 전체 후보 60개 정확도, 모든 제외조건 보존, 단위·논리식 완전성을 증명하는 점수로 사용하지 않음.

## LLM 결과에도 남은 문제

- 이번 실험은 정책당 조건 10개·그룹 6개로 출력을 제한. 일부 조건이 그룹 설명·미해결 메모에만 존재하고 구조화 후보에서 누락. 정책 6개 모두 부분 분석으로 반환.
- `value`·`unit`·`reference_date`에 자유 텍스트가 존재. 운영 판정에는 타입이 확정된 필드 레지스트리와 값·단위·기준일 계약 필요.
- 그룹 간 연결이 설명 문장에 남아 있어 실행 가능한 완전한 AND/OR/NOT 트리 아님.
- 실제 예: 유아 지원의 나이 기준일 자리에 적용기간 범위가 들어감. 원문 인용은 맞아도 나이 계산 기준이 확정된 것은 아님.
- 실제 예: 무소득을 숫자 0으로 정규화했으나 소득의 산정 범위·기간은 미상. 해당 값만으로 자동 비교 금지.
- 복지로 2025년 금액 예시는 본 정책의 현재 금액 기준으로 일반화하지 않고 참조로 분리했으나, 현재 기준 자료 검토는 별도 필요.
- 근거 일치 검사는 인용 문자열의 존재만 확인. 값의 올바른 해석·제외조건 누락·전체 논리 완전성은 별도 검증 대상.

## 채택할 처리 방식

```text
원본 보존·공통 필드 매핑 (코드)
    ↓
명확한 값·단순 문장 규칙 처리 (코드)
    ↓ 미해결 문맥 + 필요한 주변 원문
조건 주체·복합 논리·예외·참조 해석 (Codex CLI)
    ↓
스키마·근거·숫자·단위·논리·누락 검사 (코드)
    ↓
검토 필요한 초안 저장 → 검증된 규칙만 검색·판정에 사용
```

이번 호출은 모든 정책에 미해결 항목이 있어 6개를 한 번에 전달. 코드가 해결한 필드도 문맥으로 포함했으며 정책 내 빈 필드 참조를 해석할 때 원문 다른 필드를 함께 사용.

다음 구현은 정책별 예외 if문 추가보다 **Codex 후보 추출 → 공통 검증** 연결 우선. 긴 정책은 문단별 후보 추출 후 전체 정책 수준에서 AND/OR·예외·누락을 다시 결합. 임의 개수 제한에 의한 누락을 완료로 처리하지 않음.
