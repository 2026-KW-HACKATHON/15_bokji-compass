# 회원가입 이메일과 SMTP 설정

일반·카카오 신규 가입은 이메일을 직접 입력해야 합니다. 일반 가입은 이메일로 받은 6자리 인증번호를 확인해야 계정을 만들 수 있습니다. 카카오 가입에는 이메일 입력만 요구하며, 카카오 API에서 이메일·실명·생년월일·성별을 가져오지 않습니다. 기존 회원은 이메일이 없어도 로그인할 수 있습니다.

## 실제 메일 발송 설정

메일 제공업체에서 SMTP 발송이 가능한 계정과 발신 주소를 준비한 뒤 `backend/.env`에 설정하고 서버를 재시작합니다. 기존 `.env`에는 `.env.example`의 새 항목이 자동 복사되지 않으므로 아래 값을 직접 추가하세요.

```dotenv
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_SECURITY=starttls
SMTP_USERNAME=sender@example.com
SMTP_PASSWORD=메일_제공업체가_발급한_SMTP_비밀번호
SMTP_FROM_EMAIL=sender@example.com
```

위 주소는 형식 예시입니다. 실제 호스트·포트·로그인 정보는 선택한 제공업체의 안내를 사용하세요. SSL 연결을 요구하는 제공업체는 보통 `SMTP_PORT=465`, `SMTP_SECURITY=ssl`을 사용합니다. TLS 인증서를 검증하며 평문 SMTP 설정은 지원하지 않습니다. 비밀번호 대신 앱 비밀번호나 SMTP 전용 자격증명을 요구하는 제공업체는 해당 값을 사용합니다. 발신 주소는 제공업체에서 허용한 주소여야 하며 표시 이름 없이 이메일 주소만 입력합니다. 자격증명은 Git이나 프론트 환경변수에 넣지 않습니다.

설정이 없거나 발송에 실패하면 가입 화면에 오류를 표시합니다. 개발 환경에서도 인증번호를 API·콘솔·화면에 대신 노출하지 않습니다. SMTP 설정 전에는 일반 신규 가입을 완료할 수 없으며 기존 로그인과 카카오 가입은 사용할 수 있습니다.

MySQL을 사용한다면 배포 전 `backend`에서 `.venv/Scripts/python.exe -m app.modules.auth init`을 실행합니다. SQLite는 첫 회원 API 요청 시 자동 갱신합니다. 기존 계정에 nullable `email`, `email_verified_at` 열을 추가하고 인증 대기 테이블을 생성하며 계정·비밀번호·세션은 보존합니다.

## 인증 흐름과 제한

1. `POST /v1/auth/email/request`에 `{ "email": "member@example.com" }`을 보내면 메일을 발송하고 HttpOnly `bokji_signup_email` 쿠키를 설정합니다.
2. 같은 브라우저에서 `POST /v1/auth/email/verify`에 이메일과 문자열 인증번호 `code`를 보내 확인합니다.
3. 같은 이메일을 일반 가입의 `email` 필드에 넣습니다. 서버가 인증 증명을 한 번 소비하는 작업과 계정 생성을 같은 트랜잭션에서 처리합니다. 아이디 중복으로 가입에 실패하면 증명을 보존하므로 아이디를 수정해 재시도할 수 있습니다.

인증번호는 발송 후 10분, 인증 완료 증명은 확인 후 10분 동안 유효합니다. 같은 브라우저에서 재발송하면 이전 번호와 증명은 폐기합니다. 번호를 5회 틀리면 새 번호를 받아야 합니다. 발송 제한은 이메일당 60초에 1회·시간당 6회, IP당 시간당 20회이고 번호 확인은 IP당 15분에 60회입니다. 화면에서 이메일을 수정하면 인증 상태가 초기화됩니다. 브라우저 쿠키 없이 번호만 복사하거나 인증한 이메일을 바꿔 가입할 수 없습니다.

이메일은 앞뒤 공백을 제거하고 소문자로 저장합니다. 일반적인 ASCII 이메일 주소를 지원합니다. 로그인은 기존 아이디 또는 카카오 계정으로 합니다. 이메일은 연락처이며 UNIQUE 로그인 식별자로 사용하지 않습니다. 특히 카카오 가입의 이메일은 소유 인증을 거치지 않으므로 이메일이 같다는 이유로 계정을 연결하거나 비밀번호 재설정을 허용하지 않습니다. `email_verified`는 일반 인증 가입에서만 true입니다. 프로필 수정 API에서는 이메일 변경을 허용하지 않습니다.

## 검증

`tests/test_email_auth.py`는 인증 우회·다른 이메일/브라우저·만료·오입력·재발송·일회성·동시 가입·발송 제한과 SMTP TLS/실패 처리를 확인합니다. SMTP 전송 함수만 대체하는 단위 테스트와 `tests/e2e_server.py`의 테스트 전용 수신함을 사용하는 브라우저 테스트는 실제 계정 생성과 인증 API를 실행합니다. 테스트 수신함은 일반 `app.main:app`에 등록하지 않습니다. 실제 제공업체의 전달·스팸 분류 여부는 SMTP 설정 후 별도로 확인해야 합니다.
